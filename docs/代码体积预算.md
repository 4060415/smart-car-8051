## 一、限额到底卡什么

Keil 官方对 C51 评估版的原文（[keil.com/limits](https://www2.keil.com/limits)）：

> The 8051 compiler, assembler, linker, and debugger are limited to 2 Kbytes of object code.
> Source code may be of any size.
> Programs that generate more than 2 Kbytes of object code will not compile, assemble, or link.

三条推论，直接决定预算怎么排：

1. **卡的是"目标码"，不是源码**；源码写多少都行。
2. **只算 code，不算 data。** 报告里那个 240 B 动作缓冲放 RAM，**一字节都不占这 2048 的额度**。
   所以"240 B 缓冲会不会把 2 KB 吃掉"这个担心是多余的 —— 它吃的是 RAM，不是 code。
3. 卡点在 **BL51 链接器**（编译/汇编阶段不拦），所以是"写到最后一刻链接才报错"，
   这正是它危险的地方 —— 所以下面第五节要求"写一块、量一块"。

## 二、量法（可复现）

Keil 只报一个总数（`code=1147`），不报"红外解码占多少、串口打印占多少"。
我们自己从 A51 生成的 `.LST` 清单里逐行拆标号：

```powershell
cd D:\工程实践_迁移
python tools\lst_sizes.py   firmware\remote\remote.LST --top 45   # 各标号区间体积
python tools\_remote_budget.py firmware\remote\remote.LST          # 按功能分组求和
```

两个脚本是本文件结论的**唯一依据**，`tools\` 下已有：

| 脚本 | 作用 |
|---|---|
| `tools\lst_sizes.py` | 通用：解析 A51 `.LST`，按标号切区间算体积，分出"指令字节 / DB 数据字节" |
| `tools\_remote_budget.py` | 专用：把 `remote.LST` 的标号按功能分组（调试/解码/电机/时基/按键/主循环）求和 |

`.LST` 的行格式（踩过的坑，记下来免得下次重踩）：

```
00CB F540            233                 MOV     LASTCMD, A
^LOC ^目标码(hex对)   ^行号  ^源文本
0318 3D204952                <- 源文本太长的行，目标码会溢出到这种"没有行号"的续行

## 五、真正会吃掉预算的几件事

| 风险 | 后果 | 对策 |
|---|---|---|
| **正式固件改用 C 写** | Keil C51 / SDCC 生成的 8051 代码通常是手写汇编的 **2~3 倍**；同样功能可能 2000 B 以上，直接撞墙 | **正式固件继续用 A51 汇编**。报告里"正式 C 固件"这个说法改成"汇编实现"，或只在非关键模块用 C |
| 保留全量串口调试 | +368 B | `DEBUG_UART 0` 一键关闭；调试期开着，验收版关掉 |
| 浮点、长整型乘除、格式化打印 | 每个都是几百字节量级 | 全部用整数/定点；本来也不需要 |
| 写着写着忘了量 | 撞到 2048 才发现，回头删功能很痛 | **每写完一块就跑一次 `build.ps1`，看 `code=` 增加多少**（第六节） |

## 六、RAM 也不缺，但注意一条

STC 官网 STC89C52RC 的 features（[stcmicro.com/STC/STC89C52RC.html](https://www.stcmicro.com/STC/STC89C52RC.html)）：

> On-chip 8K FLASH program memory　/　**On-chip 512 byte RAM**　/　Be capable of addressing up to 64K byte of external RAM

即 **512 字节**：256 内部（128 直接 `DATA` + 128 间接 `IDATA`）+ 256 **内部扩展 EXTRAM**（用 `MOVX` 访问，
Keil C 里就是 `xdata`）。报告要求的 240 B 缓冲 + 运行变量 + 中断栈，512 B 装得下。

⚠️ **放置建议：240 B 缓冲走 `MOVX @DPTR`。**
不要用 `MOVX @Ri` —— 那条路拿 **P2** 当高 8 位地址，而 **P2 整口被数码管段选占了**
（a=P2.7 … g=P2.1），一访问就把显示打花。用 `DPTR` 不碰 P2。

## 七、还没闭环的前置项（不解决会白干）

**录制 / 回放 / 清空这三个键的键值现在还不知道。**
`config.h` 第八节只钉死了 5 个：前进 `46`、后退 `15`、左转 `44`、右转 `43`、暂停 `40`。
报告的表 2/表 3 需要"录制开始键、录制结束键、回放键、清空键"四个新键。两条路：

1. **测出来（推荐）**：烧 `remote.hex`（它会把收到的**任何**键的 cmd 字节打到串口），
   拿遥控器把其余键逐个按一遍，记下串口输出 → 补进 `config.h` 第八节。
   `remote.asm` 与 `config.h` 两处键值要一起改。
2. **先用板载键**：`S3`(P3.4) / `S4`(P3.2) 当"录制开始/停止"和"回放"，
   遥控器只管四个方向 —— 少测一轮，但操作不如遥控器顺手。

这个缺口和代码体积无关，但**是开工前必须先钉死的**（否则边写边猜键值，返工）。

## 八、这份预算怎么用

- 报告里的"资源占用分析"一节可以直接引本文件第三/四节的表。
- 报告里"硬件资源受限"那部分可以补一句：**动作单元编码（3 B/单元）使 240 B 缓冲可存 80 条，
  而代码体积本身仍留有一倍以上余量** —— 这是有实测支撑的结论，不是估算。
- 每写完一块就量：`powershell -NoProfile -ExecutionPolicy Bypass -File firmware\<模块>\build.ps1`
  → 看 `code=` 数字，与第四节预算对照。真要是某一块超了预算，先砍调试打印，再考虑换工具链
  （备选方案见 `docs\开发环境与工具链.md` 末尾：ASEM-51 / SDCC，均为免费且无体积限制）。

| **正式固件改用 C 写** | Keil C51 / SDCC 生成的 8051 代码通常是手写汇编的 **2~3 倍**；同样功能可能 2000 B 以上，直接撞墙 | **正式固件继续用 A51 汇编**。报告里"正式 C 固件"这个说法改成"汇编实现"，或只在非关键模块用 C |
| 保留全量串口调试 | +368 B | `DEBUG_UART 0` 一键关闭；调试期开着，验收版关掉 |
| 浮点、长整型乘除、格式化打印 | 每个都是几百字节量级 | 全部用整数/定点；本来也不需要 |
| 写着写着忘了量 | 撞到 2048 才发现，回头删功能很痛 | **每写完一块就跑一次 `build.ps1`，看 `code=` 增加多少**（第六节） |

## 六、RAM 也不缺，但注意一条

STC 官网 STC89C52RC 的 features（[stcmicro.com/STC/STC89C52RC.html](https://www.stcmicro.com/STC/STC89C52RC.html)）：

> On-chip 8K FLASH program memory　/　**On-chip 512 byte RAM**　/　Be capable of addressing up to 64K byte of external RAM

即 **512 字节**：256 内部（128 直接 `DATA` + 128 间接 `IDATA`）+ 256 **内部扩展 EXTRAM**（用 `MOVX` 访问，
Keil C 里就是 `xdata`）。报告要求的 240 B 缓冲 + 运行变量 + 中断栈，512 B 装得下。

⚠️ **放置建议：240 B 缓冲走 `MOVX @DPTR`。**
不要用 `MOVX @Ri` —— 那条路拿 **P2** 当高 8 位地址，而 **P2 整口被数码管段选占了**
（a=P2.7 … g=P2.1），一访问就把显示打花。用 `DPTR` 不碰 P2。

## 七、还没闭环的前置项（不解决会白干）

**录制 / 回放 / 清空这三个键的键值现在还不知道。**
`config.h` 第八节只钉死了 5 个：前进 `46`、后退 `15`、左转 `44`、右转 `43`、暂停 `40`。
报告的表 2/表 3 需要"录制开始键、录制结束键、回放键、清空键"四个新键。两条路：

1. **测出来（推荐）**：烧 `remote.hex`（它会把收到的**任何**键的 cmd 字节打到串口），
   拿遥控器把其余键逐个按一遍，记下串口输出 → 补进 `config.h` 第八节。
   `remote.asm` 与 `config.h` 两处键值要一起改。
2. **先用板载键**：`S3`(P3.4) / `S4`(P3.2) 当"录制开始/停止"和"回放"，
   遥控器只管四个方向 —— 少测一轮，但操作不如遥控器顺手。

这个缺口和代码体积无关，但**是开工前必须先钉死的**（否则边写边猜键值，返工）。

## 八、这份预算怎么用

- 报告里的"资源占用分析"一节可以直接引本文件第三/四节的表。
- 报告里"硬件资源受限"那部分可以补一句：**动作单元编码（3 B/单元）使 240 B 缓冲可存 80 条，
  而代码体积本身仍留有一倍以上余量** —— 这是有实测支撑的结论，不是估算。
