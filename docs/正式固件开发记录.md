## 二、块① 做了什么（`firmware\car\car_asm.asm`）

### 2.1 三条定死的架构约定（后面所有块都遵守）

1. **主循环永远不直接写 `P0`。** `P0` 由 Timer0 中断每 99.8 µs 组装一次：
   方向位来自 `DIRBITS`，`ENA`/`ENB` 来自 PWM 比较，蜂鸣器位来自 `BUZB`。
   → 这样"主循环改方向"和"中断打 PWM"不会互相踩（这是软件 PWM 最容易踩的坑）。
2. **动作码 → 电机的映射只有一处**（`MOTOR_SET_ACT` + `DIRTAB`/`DUTYTAB`），
   也就是报告里的 `Motor_Set(action, speed)` 统一出口。手动、模式、回放全都调它。
3. **时基**：Timer0 方式 2（重装 164）≈ **99.8 µs/tick**；**20 tick = 2 ms = 500 Hz PWM**，
   占空比 5% 一档（0~100%）。Timer1 方式 2 做 9600 波特率（调试）。
   红外解码将来复用**同一个 tick**，不再另开定时器。

### 2.2 已经能跑的功能

| 功能 | 怎么验证 |
|---|---|
| 档位 0 = 停 | 数码管 `0`、D3 灭、两轮断电（`ENA`/`ENB` 拉低） |
| 档位 1~5 = 前进 20/40/60/80/100% | 数码管显示档位、**D3 亮 = 电机在动** |
| **按键调速** | `S3`(`P3.4`) 按一下加一档；`S4`(`P3.2`) 按一下减一档；顶到 0/5 就不再变 |
| **蜂鸣器提示** | 每次变档短响（≈20 ms，1 kHz）；由中断产生方波，**不阻塞主循环** |
| 按键去抖 | 20 ms 去抖 + "松手才认下一次"（所以是"按一下变一档"，不是长按连发） |
| 串口调试 | 每次变档打一行 `gear N  duty=XX%` |

### 2.3 上机验证步骤（不需要遥控器）

```
1. ~~拔电池、只插 USB~~ -> 烧 firmware\car\car_asm.hex -> 冷启动（⚠️ 2026-09-20：**不用拔电池**，USB+电池同接也能冷启动下载，见 `待办与风险.md` B1 更正）
2. 把车轮架空
3. 按 S3：数码管 0->1->2->3->4->5，轮子越来越快，每按一次"嘀"一声，D3 亮
4. 按 S4：一路退回 5->...->1->0，0 档轮子停、D3 灭
5. 顶到 5 再按 S3 不动；到 0 再按 S4 不动   （边界正确）
（想要串口日志：关掉 STC-ISP，跑 tools\read_com.ps1 -Port COM7 -Seconds 15）
```

**块② 自查出的问题（当场修掉）**

| 问题 | 症状 | 处理 |
|---|---|---|
| **NEC 重复帧被当成"帧被拒"**（`remote.asm` 起就有这个 bug，我搬过来一起继承了） | 重复帧的引导码是 **9 ms 低 + 2.25 ms 高**，而门限要求 ≥2.5 ms 才算完整帧 → 重复帧走了"拒绝"分支。后果：**按住键时"松键停车"的 300 ms 计时永远刷不到**，表现为"按一下动一下就停"；而且**主循环里这种错误只打串口不出声**，所以现场看起来像"完全没反应" | 门限改成两段：`1.2 ms ≤ 高 < 2.5 ms` → **判为重复帧**（`IRSTAT=3`，用于刷新"还按着"的时刻）；`< 1.2 ms` → 才当噪声拒绝 |
| **★ 短引导码的"完整帧"被整帧丢掉**（上一条修过头了） | 实测这只遥控器发的**每一串**都是 9 ms 低 + 1.2~2.5 ms 高（`irdecode` 每次都报"很短一嗒"）。上一条修法在这里**直接当重复帧返回**，于是**首帧的 32 位数据从没被解过** → `car_asm.hex` 收到重复帧只刷新计时、不做动作 → **用户看到"完全没反应"** | 改成：**短引导码不急着下结论，继续解 32 位** —— 解出来 = 完整帧（正常动作）；解不出来 = 重复帧（刷新"还按着"）。用一个 `SHORTL` 标记区分这两种出口。这样"短引导码完整帧"和"真重复帧"都能正确处理 |
| 松键超时停车后**没刷新显示** | 车停了，数码管还亮着 D3（"在动"） | 停车后补 `SHOW_STATE` |
| `JC IR_REJECT` 跳过了 128 字节射程 | 汇编报 `TARGET OUT OF RANGE` | 照 `remote.asm` 的老办法：把失败出口**就近**放在引导码检查旁边 |
| **`.asm` 存成"UTF-8 带 BOM"会编不过** | A51 在第 1 行报 `SYNTAX ERROR / ILLEGAL CHARACTER` | 存**无 BOM 的 UTF-8**（PowerShell 用 `Set-Content -Encoding UTF8` 会加 BOM，要改用 `UTF8Encoding($false)`） |
| **★ 串口调试打印把红外接收"噎住"**（**本次最重要的一条**） | 现象链：`car_asm.hex` 按遥控器**完全没反应**；`irdecode` **按不同键显示同一个值 `2C`**。真因：**9600 baud 下每个字符约 1 ms**，打一行 40 字符的调试信息要 **42 ms**，而一整帧 NEC 只有 **67 ms** → 打印期间**错过下一帧的开头** → 从帧中间截到数据 → 引导码不符 → 被拒 → 又打印 → 又错过……（死循环）。打印耗时固定 → **总在同一偏移截断** → 解出同一个值 ✓ 完整解释了 `2C` | **`DEBUG_UART = 0`**（正式用必须是 0）。实测顺带省下 434 B：`code` 1508 → **1074 B** |
| **测量方法本身误导过结论** | 我一度根据"半截时序"判定"这颗遥控器是 NEC 短引导码变体" —— **错的**。原因是**漏看了折行的续行**：`irtrace` 打印的时序一行放不下会折行（续行以空格开头），我只解析了第一行 | **解析日志必须按字节/按记录拼回折行**；`irtrace` 的完整时序证明信号是**标准 NEC**（引导码 8.9ms + 4.4ms，地址 `0x00` + `~地址 0xFF` 完美互补） |
| `irdecode.asm` 的**分派漏了"静默"分支** | 空闲时（`IRSTAT=1`）也落到"数据段错"分支 → **上电就一直嘀嘀嘀** | 显式判 `IRSTAT==5` 才响 4 声；`1` 什么都不做 |

## 六、2026-09-18 上机排查：找到"按遥控没反应"的真正根因（★ 最重要）

### 6.1 现象
块② 上机后：上电正常（响 3 声 + 数码管 `8`），但按遥控器**完全没反应**。
先前归因"串口打印噎住红外"（已把 `DEBUG_UART=0`）后仍没反应 → 不是打印问题。

### 6.2 决定性证据（串口抓取 `tools\read_com_stream.ps1`）
把拒绝帧诊断扩成打印 32 位原始字节后（`DEBUG_UART=1`），抓到：

```
! IR rej lo=59 hi=2B a=FF b=00 c=00 d=00   （连按 5 次完全一致）
```

- `lo=59`（89 tick）、`hi=2B/2C`（43~44 tick）→ **引导码完全正常**（标准 NEC 8.9ms+4.4ms）。
- `a=FF b=00 c=00 d=00` → addr 校验过（FF/00 互补）、**cmd 校验必挂（00/00）**。

### 6.3 根因（★ 从 `remote.asm` 一路继承的 bug）
`IR_SETBIT` 里位掩码推进用的是 **`RL A`**：

```asm
MOV  A, MASKB
RL   A          ; ← 80H→01H 循环，永远不会变成 0
MOV  MASKB, A
JNZ  ISB_DONE   ; ← 永远为真 -> PTRIDX 永远不前进
```

于是 **32 个数据位全被 OR 进 `IB0`**（`IB1/IB2/IB3` 永远 0），校验必挂。
**再加上掩码只在"1"位才推进**（`IR_SETBIT` 只在 1 位被调用，0 位不推进）→ 位序也是错的。
结论：`remote.asm` "之前测过能用" 其实只验证了**时序**（irtrace），**解码一直是坏的**。

### 6.4 修复（`car_asm.asm`）
1. 掩码推进从 `IR_SETBIT` 挪到 `IR_NEXTBIT`（**每个位都推进**，含 0 位）。
2. `RL A` → `CLR C` + `RLC A`，用进位检测"8 位满"→ `INC PTRIDX`。

```asm
IR_NEXTBIT:
    MOV  A, MASKB
    CLR  C
    RLC  A
    MOV  MASKB, A
    JNC  IR_NB_CONT
    MOV  MASKB, #01H
    INC  PTRIDX
IR_NB_CONT:
    DEC  BITS
    ...
```

## 七、块③④：模式状态机 + 寻光（2026-09-19 已写、已编译、**已上机验证**）

### 7.1 做了什么

| 项 | 实现 |
|---|---|
| 模式变量 | `MODE`（`50H`）：`MODE_MANUAL=0`、`MODE_LIGHT=1`，`NMODES=2` |
| **★ 开机必清零** | 初始化里加了 `MOV MODE, #MODE_MANUAL` —— **内部 RAM 上电是随机值**，不清有可能一开机就在别的模式（这是"凡是会被读的变量都要显式初始化"那条教训） |
| 模式切换 | **长按 S3 ≈1 s**（`LP_TMO_H=39`，39×256 ≈ 9984 tick） |
| 短按/长按怎么分 | `KEY_SCAN` 的 `KS_S3`：按下（20 ms 去抖）后**计时等松手** —— 松手 <1 s = 短按（加档）；按住 ≥1 s = 长按（切模式）。**不是"按下就加档"**，否则长按切模式会顺带多加一档 |
| 模式显示 | `SHOW_MODE`：手动 → 档位（走 `SHOW_STATE`）；其它 → `MODETAB[MODE]` 代号（寻光 = `L`）。**D3 在任何模式都表示"在动"** |
| 模式分派 | `MAIN_LOOP` 顶部按 `MODE` 分：手动走原来的"收红外 + 遥控"；非手动**不收回外**，跑模式动作后直接 `LJMP IR_KEYSCAN`（长按 S3 仍能切回） |
| 非手动模式的档位键 | `ML_APPLY` 加了 `MODE` 判断：非手动时**只改档位、不动电机**（否则本地 S3/S4 会把车按"前进"驱动，与模式动作打架） |
| 块④ 寻光 | `LIGHT_STEP`：每趟主循环读两路光敏（见光=低）。两边都亮→直走；只有左亮→左转；只有右亮→右转；都遮住→停。速度用当前档位；进模式时若档位为 0 自动给 `GEAR_DEFAULT`(3) |

### 7.2 写的时候自查出的两个坑（已修）

1. **寻光下档位减到 0 时电机不停**：原来 `GEAR==0` 直接 `RET`，电机保持上一次动作 → 车会一直跑。
   改成显式 `ACT_STOP`（`MOTOR_SET_ACT` 收到 `ACT_STOP` 无论档位多少都断两路）。
2. **寻光下 D3 不亮**：`LIGHT_STEP` 现在把选中的动作写进 `CURACT` 并每趟 `SHOW_MODE`，D3 才能反映"在动"。

### 7.3 上机怎么验（交给用户）

```
1. 烧 firmware\car\car_asm.hex -> 冷启动（车轮架空）
2. 手动模式（默认）：数码管显示档位
   - 短按 S3 = 加档，短按 S4 = 减档
   - ⚠️ 现在是"松手才动作"（短按加档），手感与之前"按下就加档"略有不同
   - 遥控方向键 / 加减档（键 6 / 4）照旧
```

### 7.5 块⑤ 循迹（2026-09-20 追加；⚠️ **转向方向在 2026-09-20 联调时又改了一次 —— 见下**）

**硬件事实（2026-09-18 实测，不得改）**：`P3.5` = 左探头 V2，`P3.6` = 右探头 V3；
**白纸/有反射 = 低(0)，压黑线 = 高(1)**；这两个探头是**数字反射式、直接进 MCU，不经过 LM393 比较器**
（所以调 `W1`/`W2` 不影响循迹）。

**`TRACK_STEP` 判据**（每趟主循环调一次）：

| 左`P3.5` | 右`P3.6` | 判断 | 动作 |
|---|---|---|---|
| 0 | 0 | 两个都白 = 脱线 | 先直走找线；离开线超过 `TRK_TMO`（≈0.5 s）→ **停车** |
| 0 | 1 | 只有右探头压线（线在车右下） | **右转** |
| 1 | 0 | 只有左探头压线（线在车左下） | **左转** |
| 1 | 1 | 两个都压线 = 车骑在线上 | **直走** |

> ★★ **转向规则（几何推出来的，与手感无关，可独立复核）**：
> **哪一侧的探头压线，线就在车的那一侧下方** → 说明车偏到了线的**另一边** → 要**朝压线的那一侧转**回来。
> 即 **左探头压线 → 左转；右探头压线 → 右转**。
> 这条规则**与"探头骑在线上"还是"分列线两侧"无关**（两种装法推出来一致），所以可以放心用。

> ★ 蜂鸣器：**手动**刹停那刻响一声，之后**每 ≈0.7 s 续响**（`AVBEEP_H = 27`，27×256 tick ≈ 0.7 s）；
> **停响** = 按遥控接管 **或** 障碍移开（⚠️ 障碍移开只**停响**，车**仍停着**等遥控）。
> **寻光**退回手动时只响**一声**（切模式提示音的量级），不续响。
> 详见 `docs\联调记录.md` 第 0.3 / 0.4 / 0.7 节。

**只用了超声波**（HC-SR04：`Trig`=`P1.3`、`Echo`=`P1.2`，已验证功能正常）。
红外反射探头 `P3.5`/`P3.6` 本车是**朝下装来循迹的**，避障装法（朝前）与它**互斥**（报告也这么写）。

**关键约束**：`usfollow.asm` 用的是 **Timer0 方式1** 计时测距，但本固件 Timer0 方式2 在打

只做门限比较、不做 cm 换算，省掉乘法/除法。

**★ 设计要点（含 2026-09-20 修的两个自己造的 bug）**：
- ❌ **第一版 bug**：拦停时主循环直接 `LJMP IR_KEYSCAN` 跳过了**整条遥控处理路径** →
  **前方有障碍物时遥控完全不响应**（用户实测报的）。
- ✅ **改法**：`AV_GATE` 只更新状态字节 `AVST`（`5CH`），**不跳过任何输入处理**；
  遥控照常收、照常响铃/更新显示/记动作。**"能不能动"由 `MOTOR_SET_ACT` 一个出口统一决定**
  （它在开头按 `AVST` 四态分派：改写成 `ACT_RIGHT` / 强制刹停 / 放行）→ **有障碍时按键不聋**。
- ❌ **第二版 bug（转向版引入的）**：一直右转会把 `DIRBITS` 改成右转并**留在那里** →
  障碍拿开后车**一直右转不恢复**。→ `AG_FREE` 里补了"把 `CURACT` 重新套上"。
- `MOTOR_SET_ACT` 的改写是**在 `R7 != 0` 之后**做的：档位 0（本来就没让动）仍然停车，
  避障不会把停着的车拐走。
- 开关状态 `AVOIDON`（`5BH`）**上电必须显式置 1**、`AVST`（`5CH`）显式置 `AV_FREE`（内部 RAM 是随机值）。
- `S4` 短按仍是**减档**、长按 ≥1s 是**避障开关**（和 S3 的长按逻辑同一套 `LP_TMO_H`）。
  开关提示音：**开 = 响两声，关 = 响一声长的**。
- `SHOW_STATE`/`SHOW_MODE` 显示 —— 判据是 `CURACT`：
  **避让（`AV_TURN`）时车确实在动，D3 该亮**；
  **刹停锁存（`AV_HOLD`）时 `MOTOR_SET_ACT` 会把 `CURACT` 清 0，所以 D3 是灭的**（不会"停着还显示在动"）。
  ⚠️ 后面这条是 R3 特意补的：寻光/循迹每趟都会把 `CURACT` 设回动作码，
  不在出口清掉的话 D3 就会误亮（和 P4 是同一类问题）。
- 实测代价：开着避障时每趟主循环多花 ≤2 ms 测距（没回波时的等待上限）。

**实现**：
- **前进/后退锁定**：`IR_HOLDCHK` 里的 300 ms 松手超时**对 `ACT_FORWARD` / `ACT_BACK` 豁免**
  （`CJNE A,#ACT_FORWARD` / `#ACT_BACK` 直接 `LJMP IR_KEYSCAN`），其余动作照旧走超时。
  **只加 12 B**，没有新增状态变量（"锁定"就是"`CURACT` 是前进/后退"这个事实本身）。
- **遥控加减档改成全局**（2026-09-20）：原来非手动模式下只认「停止」键，现在
  `ML_NOMODE` 里除了 `KEY_STOP` 还认 `KEY_SPD_UP` / `KEY_SPD_DN`，
  并且**复用板载按键那条变档路径 `LJMP ML_APPLY`**（它会做提示音 + 非手动模式下刷新模式代号），
  比再写一套省约 20 B。`code` 1557 → **1586 B**。

⚠️ 副作用（要知道）：**前进/后退锁定时，如果遥控器没电/超出范围，车不会自己停**
（原来的 300 ms 保护被豁免掉了）—— 靠「停止」键、板载长按 S3 切模式、或全局避障来停。
如果觉得危险，可以把这两个 CJNE 去掉恢复成"按住才走"。

### 9.4 ⚠️ 设计差异：PWM 从 500 Hz 降到 100 Hz（有意为之）

- **100 µs tick 照旧每次都加**（红外脉宽测量、各种超时靠它，精度不变）
- **PWM 每 `PWM_DIV`(=5) 个 tick 才刷一次** → 500 µs/步 × 20 步 = 10 ms = **100 Hz**

正好对上报告评审里"**PWM 频率取 100~200 Hz**"的建议 ✓（这个值是个宏，随时可调）

### 9.5 ⚠️ 待修 bug（恢复 C 移植时**第一件事**）

`main.c` 的 `delay_ms()` 是**嵌套空循环猜时间**：
```c
for (i = 0; i < 250; i++) for (j = 0; j < 4; j++) ;   /* ← 错的 */
```
Keil C51 每层循环要 **5~8 个机器周期**，我按 1~2 个估 → `delay_ms(20)` 实际约 **140 ms**（慢 7 倍），
按键"**不跟手**"。

**改法**：用现成的 100 µs 时基计时，与优化级别无关：
```c
static void delay_ms(unsigned char ms) {
    unsigned int start = get_tick();
    unsigned int span  = (unsigned int)ms * 10;      /* 1ms = 10 个 tick */
    while ((unsigned int)(get_tick() - start) < span) ;
}
```

#### ★★★ C5 专题：为什么"超声波绕行"在 C 版里会失效（汇编版却没事）

**根因：C 版用"主循环轮询 + 读 100µs 的 tick"量回波宽度，而主循环被中断拖慢了好几倍。**

| | 汇编版（验证过，能用） | C 版（失效） |
|---|---|---|
| 中断服务程序占空 | ~60µs / 99.83µs | C 的中断更长，留给主循环的时间更少 |
| 轮询一圈 | ~22µs（≈0.2 tick） | **200~400µs（≈2~4 tick）** |
| 15cm 的回波宽度 | 8.75 tick | 8.75 tick（一样） |
| 结果 | 逐点采到"回波变低" → d≈8 → **进近区 → 原地右转避让** ✅ | 还没轮到看"回波变低"，`d` 就先撞上 `>= US_NEAR(12)` 的判据 → **判成"够远"** → **车照直撞** ❌ |

**为什么这个 bug 特别隐蔽**：单看代码，`us_read()` 的逻辑与汇编版"逐条等价"；
只有**把中断占空算进去**才会发现"轮询太慢 → 一步跨过整个判据窗"。
而且它**只影响 C 版** —— 汇编版分辨率约 0.2 tick，根本踩不到。

**修法**：让**中断**（精确 99.83µs）去数回波持续时间，主循环只开关闸门：

```c
/* timer0_isr 里（放在 P0 写入之后，PWM 时序零影响）*/
if (echo_on) echo_ticks++;

/* us_read 里 */
ET0 = 0; echo_ticks = 0; echo_on = 1; ET0 = 1;
while (US_ECHO && echo_ticks < US_NEAR) ;    /* 只需等到"变低"或"数够=够远" */
ET0 = 0; echo_on = 0; n = echo_ticks; ET0 = 1;
```

⇒ **分辨率恒定 = 1 tick（1.72cm），与主循环快慢完全无关**；轮询再慢也只是边沿晚识别 ±1 tick。
顺带把触发脉冲从 ~150µs 收到 **~13µs**（与汇编版/usprobe 一致，规格是 ≥10µs）。

> ⚠️ **教训**：C 版的时序分析**不能只看"逻辑等价"** ——
> 凡是"用软件轮询去测宽度"的地方，都要把**中断占空**算进去。
> 同类隐患还有一处，见 §9.7 的红外解码（`meas_level`，那里已经写明了"时基读取必须内联"）。

#### ★★★ C5 终章（2026-09-21）：**真正的根因 = 我把汇编版的 `US_UPTO` 读错了（窗口差 256 倍）**

**用户实测**：新自测版（已去掉串口代码、触发脉冲也对齐了）**仍然恒显示 `E`**。
`E` = "等回波上升沿超时" ⇒ **`US_ECHO` 在窗口内一次都没变高**。

**于是回去逐行核对汇编版，发现了这个：**

```asm
US_W1:  JB      US_ECHO, US_UP        ; 回波为高 -> 去测量
        ACALL   TICK_GET
        MOV     A,      R5
        CLR     C
        SUBB    A,      R7            ; 低字节差（只为算借位）
        MOV     A,      R4
        SUBB    A,      R6            ; A = 【高字节差】
        CLR     C
        SUBB    A,      #US_UPTO      ; ★ 拿【高字节】和 20 比！
        JC      US_W1
```

| 等回波上升沿的窗口 | 实际值 |
|---|---|
| `car_asm.asm`（汇编版，上机验证过） | **US_UPTO 比的是高字节 ⇒ 20×256 = 5120 tick ≈ 511 ms** |
| `usprobe.asm`（实测能用） | Timer0 溢出 = **71 ms** |
| **C 版（原）** | **20 tick ≈ 2 ms** ❌ ← **短了 256 倍** |

**机理**：`US_UPTO EQU 20` 从名字和数值看都像"20 个 tick"，我照着字面搬成了 2ms。
但汇编里它是**和 16 位差值的"高字节"**相比 —— 门限其实是 **5120 tick**。
⇒ 回波只要来得比 2ms 晚一点，C 版就永远等不到 ⇒ 判成"够远" ⇒ **不绕行、不刹停、也不响**，
同时自测版恒显示 `E`。而 `usprobe` 用 71ms 窗口，所以它一直是正常的。

**修法**：按汇编版语义改回**高字节**比较（`>= (US_UPTO << 8)`），并核对生成代码：

```
JB US_ECHO → 否则 低字节差 → 高字节差 → CLR C / SUBB A,#014H(20) → JC 继续等
```
与汇编版逐条一致 ✅

> ### ✅ 上机结果（2026-09-21）：**修完就通了**
>
> 用户实测确认 **"可以工作了"** —— 超声波测距 / 避障在 C 版上**首次跑通**。
> 这是 **C 版的第一次上机成功**（此前 `main.hex` 只做到"能烧、产物自洽"）。
>
> **代价与教训**：这个根因的排查花了**两轮上机**，中间还走了两条岔路
> （先怀疑硬件 —— 而且当时依据的 `uscheck.hex` 判据本身是坏的；再怀疑中断占空）。
> 那两条岔路上顺手改的东西**不是白改**（触发脉冲确实和能用的实现差一个数量级、
> `uscheck` 的 D3 判据确实缺失上升沿），但它们都不是根因。
>
> **真正的教训一句话**：
> > **把汇编里的门限常数搬进 C 时，要连"它是和哪个字节比"一起搬，而不是只看常量的数值。**
> > `US_UPTO EQU 20` 是"高字节单位"，不是"20 个 tick"。

> ⚠️ **`US_UPTO` 的注释现在明确写着"单位是高字节，不是 tick，别再改小"** —— 防止将来重蹈。

#### ★★ C2 / C3：避障新模型与实现要点

| | 红外（P3.7，1~2cm） | 超声波（5~21cm） |
|---|---|---|
| 触发动作 | **直接刹车**（`AV_HOLD` 强制刹停） | 5~21cm 右转避让 / <5cm 刹停 |
| 手动 | ✅ | ✅ 受开关控制 |
| 寻光 | ✅ | ✅ 受开关控制 |
| **循迹** | ✅ **也有** | ❌ 不参与 |
| 能不能关掉 | ❌ **关不掉** | ✅ 长按 S4 / 遥控 5 |

**C2 的一处必要修正**：`avoid_toggle()` 关闭时**显式 `avst = AV_FREE`** ——
否则开关关了、`AV_HOLD` 却还卡着，车永远不动，"救急：关掉避障就能恢复"会失效。
★ 若此刻车头红外还贴着东西，下一趟 `av_gate` 会**立刻重新刹停** ——
这正是"红外关不掉"该有的表现。

**C3 是本次最容易写错的一处**（和既有避让机制直接冲突）：

| 状态 | `motor_set()` 的行为 | 循迹下能用吗 |
|---|---|---|
| `AV_TURN` | 把**任何**动作码都改写成"**原地右转**" | ❌ **绝对不行** —— 会把车推离黑线，循迹直接废掉 |
| `AV_HOLD` | 强制刹停，**与动作码无关** | ✅ 可以 |

⇒ 给红外单开一条刹车路径 `ir_brake()`：设 `AV_HOLD`（**不是** `AV_TURN`）、
`cur_act = ACT_STOP`、`motor_set(ACT_STOP, 0)`、用 **`show_mode()`**（不是 `show_state()`，
循迹下要保住 `t` 显示）。

**两处顺序上的坑**（看生成代码才敢确认）：

1. **`AV_HOLD` 分支必须放在"红外判断"之前** ——
   否则红外每趟都检测到 -> 每趟都调 `ir_brake` -> **连续鸣叫**，
   而不是设计要的"每 ≈0.7 s 一声"。
2. **红外判断必须放在"循迹早退"之前**（早退保留，它管的是**超声波**不参与）——
   否则循迹下红外根本不生效。

**对照验证**（在 `main_abs.asm` 的生成代码里查，确认没写反）：

```
ir_brake:
  XRL A,#03H / JZ      -> if (avst == AV_HUMAN) return;
  MOV avst,#02H        -> AV_HOLD（02H），不是 AV_TURN（01H）✓
  LCALL L?0356         -> CLR A; cur_act = 0; motor_set(ACT_STOP, 0) ✓
  LCALL show_mode      ✓
  av_beep_t = now; beep(24 = BEEP_KEY) ✓
```

#### ★★★ C6 / C7 专题：从"带节流的阻塞式"到"完全非阻塞"

C5 终章（上机通了）之后，实机又连着暴露两个问题，**两轮各修一次**，方向一次比一次接近根因：

| 轮次 | 实机症状 | 根因 | 修法 |
|---|---|---|---|
| **C6** | 遥控抽风、车马达彻底不动 | 窗口改成"高字节比较"(511ms) 后，**每趟主循环都测一次**（≈26ms）⇒ 触发太密 ⇒ 模块不响应 ⇒ **每趟白等满 511ms** ⇒ 主循环被拖到 ~0.5s | 加 **≥60ms 节流**（HC-SR04 规格要求）+ 窗口收到 40ms |
| **C7** | 遥控不抽风了，但**超声避障还是失效** | C6 仍然是**阻塞**的：模块没回波就白等一整个窗口，而 NEC 一帧 67ms，主循环一被拖就丢方向键 | ★ **三态状态机，主循环永不等待** |

**C7 的状态机（全部由中断推进，主循环只挂档/取件）**：

```
IDLE --us_trigger()--> WAIT --回波上升沿--> HIGH --下降沿--> IDLE（结果就绪）
                        |                              |
                        +-- 250 tick 超时 --------------+
```

主循环只做两件事，都是微秒级：

1. 下一次 `us_read()` 把**中断量好的结果**取走（`us_got` → `us_last_d`）；
2. 距上次触发 ≥60ms 且当前空闲，就发一个 ~13µs 触发脉冲，然后**立刻返回**。

⇒ 模块哪怕完全不响应，也只是 WAIT 在 25ms 后由中断自己超时收场，**主循环全程没有等待**。
这正是 C5/C6 两版都没解决的那一点。

**★ 一个必须记住的实现坑：`US_TOUT_TICKS` 必须 ≤ 255。**
`us_wait` 是 `unsigned char`；门限若写成 400，C51 会把它提升成 **16 位比较**，
而 8 位计数器**永远到不了 400 ⇒ 状态机永久卡在 WAIT、再也不测距**（比不改还糟）。
现在生成的代码是 `MOV A,us_wait / CLR C / SUBB A,#0FAH(250) / JNC` —— **8 位比较**，安全。
（已用 `main_abs.LST` 逐条核对：`JNB US_ECHO` 是直接**位测试 P1.3**，2 个周期。）

#### ★★ 中断预算实测（这轮新加的一道核对）

C 编译出来的中断比手写汇编长得多，**超了会丢时基**；而且犯病时**车照样能跑、灯照样亮**，
只是"所有时间都变长"——非常难查。所以补了工具 `tools\c51_isr_time.py`：
它读 `main_abs.LST`，先建**控制流图**（无条件跳 / 条件跳 / 落空 / 返回），
再求**最坏路径**与**典型路径**的机器周期。

```
python tools\c51_isr_time.py firmware\c51\main_abs.LST timer0_isr
```

**★ 判据（别再用"必须 < 92 周期"当硬线，那个判据是错的）**：

| 界线 | 值 | 含义 |
|---|---:|---|
| 一个 tick | **92 周期 / 99.83µs** | T0 方式2 自动重装 ⇒ **溢出周期固定**，与中断长短无关 |
| **硬线** | **184 周期（2 个 tick）** | 方式2 只有**一个**溢出标志 TF0：一个中断里挤进 **≥2 次**溢出，标志被合并 ⇒ **真的丢计数**。★ 进入中断时 TF0 由**硬件清零**，所以"1 次溢出"不会丢 |
| 软线 | 92 周期（1 个 tick） | 超过它，那一 tick 主循环**一点 CPU 都拿不到**（突发卡顿，**不是丢时间**） |

**C7 实测**：

| | 机器周期 | 时间 | 占一个 tick |
|---|---:|---:|---:|
| 最坏路径（PWM 步进 + 10ms 分频 + 测距三者撞在同一 tick，约 500 趟一次） | **114** | 123.7µs | 124% |
| 典型一趟 | **36** | 39.1µs | **39%** |

⇒ **114 < 184：不丢时基**；典型 39% ⇒ 主循环拿得到约 61% 的 CPU（汇编版中断约占 24%）。
C6 的最坏路径约 91 周期，C7 的状态机把它抬到 114 —— **仍在硬线以内**，所以没有去精简中断
（在那里做微优化反而会把"能跑"的 PWM/数码管路径改坏）。

> ⚠️ **教训**：判断"C 版中断会不会拖垮系统"，要按**方式2 的溢出合并**判（**2 个 tick**），
> 而不是"中断必须短于 1 个 tick"。用错判据会得出"必然丢时基、距离读数偏大 24%"的**错误**结论
> —— 这轮就差点据此去改一个本来没坏的 PWM 内核。

### ★★ C9：**超声近距提示音（"倒车雷达"）**（2026-09-21 用户需求，只改 C 版）

**用户原话**：*"关闭避障时，通过超声测距，离障碍越近蜂鸣器叫得越密集"*。

**动机**：避障一关，车就**不会自己刹**了 —— 这时用声音把距离交还给人，
等于给车加一个"倒车雷达"。**最实用的组合就是 C8 + C9：关掉避障 + 按住后退 = 倒车雷达**。

**门限复用避障那一套常数**（不引入新的距离阈值，避免两处口径打架）：

| 距离（`us_read()` 返回的 tick） | 行为 |
|---|---|
| `d >= US_NEAR`（**12 ≈ 21 cm**）或读不到（`US_FAR = FF`） | **不响** |
| `US_STOP(3) <= d < US_NEAR` | **间歇响**：`wait = 1000 + (d−3) × 512` tick<br>⇒ d=3（≈5 cm）**≈100 ms** 一声；d=11（≈19 cm）**≈510 ms** 一声 |
| `d < US_STOP`（**3 ≈ 5 cm**） | **连续响**（最急 = "贴上了"） |

**四条刻意约定**（为了"不吵、不干扰别的功能"）：

| 约定 | 理由 |
|---|---|
| **只在车真的在动时响**（`cur_act != ACT_STOP`） | 否则停在障碍前会**一直叫**，没法用 |
| **循迹不参与**（`mode == MODE_TRACK` 返回） | 与 C3"超声波不参与循迹"一致 |
| **回放不参与**（`mode == MODE_PLAY` 返回） | 回放的安全是 T7"遇障立即停车终止"，不掺提示音 |
| ★ **与避障互斥**：避障**开着**时它不响 | 那时由避障自己的"刹停 + 每 0.7 s 间歇响"负责，两边都响会打架 |

**★ 一个踩到的坑（值得记）**：第一版我写成 `wait = PROX_INT_MIN + (d-US_STOP) * PROX_INT_STEP`，
**编译直接失败** —— `c51_link.py` 报 `EXTRN CODE (?C?IMUL)`：
**C51 的 `*` 会引出库乘法**，而本工程的自制链接器**硬拒库函数**（没有 BL51 可链库）。
改成**移位** `<< 9`（= ×512）后通过。⇒ 这与 `prt_gear` 里"用加法代替 ×5"是**同一个原因**，
**以后在 `main.c` 里写算术一律避开 `*` / `/` / `%`**。

**★ 两次行为修订（2026-09-21 当天，用户反馈）**：
初版有一条"**只在车真的在动时响**"的闸门（怕停在墙前一直叫）
→ 用户反馈"车停下之后完全不叫"，**删掉闸门**改成"停着也一直响"

### ★★ C10：**D3 改成"避障开关状态"指示灯**（2026-09-21 用户需求，只改 C 版）

| D3 | 含义 |
|---|---|
| **亮** | `us_avoid_on == 1`（超声波避障**开着**，也是**上电默认**） |
| **灭** | `us_avoid_on == 0`（**关着**） |

```c
static unsigned char d3_mix(unsigned char seg)
{
    if (us_avoid_on) return (unsigned char)(seg & 0xFE);   /* D3 位清 0 = 亮 */
    return (unsigned char)(seg | 0x01);                    /* D3 位写 1 = 灭 */
}
```

| `show_mode()` | 模式代号 `L` / `t` |
| `rec_err()` / `rec_fullstop()` | 显示 `E` / `F` 时 |
| `init_all()` ×2 | 上电 `0` / 诊断版 `8` |
| `diag_update()` | `DIAG_IR` 版的键值显示 |

**★ 必须补的一处**：`avoid_toggle()` 末尾**立刻 `show_mode()`** ——
否则车静止时没有别的地方写 `P2`，**按 5 关了避障 D3 也不变**。

**代价（已与用户确认接受）**：**"电机在动"这个指示没有了**。

### ★★ C12：**倒车时超声提示音不响**（2026-09-21 用户需求，只改 C 版）

### ★★ C13：**锁存提醒音只响 3 声就安静**（2026-09-21 用户需求，只改 C 版）

**用户原话**：*"车停着的时候前面有障碍物自己怎么会时不时响一下"*
→ 追问确认：**障碍物真的在 5 cm 以内**（所以是**正常的刹停锁存**，不是误触发），
只是"**每 0.7 s 一声一直响**"嫌吵 → 选定：**只响几声就停**。

**先判明是谁在响**（现场很有用）：

| 车停着时可能响的 | 何时响 | 是不是这次的现象 |
|---|---|---|
| ★ **超声波刹停锁存的间歇响** | 前方 **<5 cm** 触发锁存后**每 ≈0.7 s 一声**，直到按遥控接管 | ✅ **就是它** |
| C9 近距提示音 | 只在**避障关闭**时响，且**停稳 2 s 后静音** | ❌ 排除 |

**R3/R4 原本的语义**：锁存期间**反复响**是提醒"**车是我刹住的，按遥控就还给你**"
（按任意遥控键 → `avst = AV_HUMAN` → 立刻不再响）。

**C13 的改法**：加一个"**本次锁存已响几声**"的计数器，到 `AVBEEP_N` 就 `return` 静音 ——
**锁存本身完全不变**（车照样停着等遥控），只是**不再一直叫**。

| | |
|---|---|
| 入口那一声（`av_gate_hold` 的 `beep`） | 算**第 1 声**（所以 `av_beep_n = 1`） |
| 之后每 0.7 s | 第 2、3 声（`AVBEEP_N = 3`）⇒ **总共约 1.4 s 内响 3 声**，然后安静 |
| 红外那一路（C11 已静音） | 入口不响 ⇒ `av_beep_n = 0` 起算 |
| 恢复"一直响到接管" | 把 `AVBEEP_N` 改大（如 255）即可，一行 |

**★★ C13 修订（同一天，用户反馈"超声波 <5cm 刹停锁存还是会响"）—— 修的是两个洞**

| 洞 | 为什么会"还是会响" | 修法 |
|---|---|---|
| ① **入口那一声没被计数挡住** | `av_gate_hold()` 末尾**无条件** `beep()`，而且每次进来都把 `av_beep_n` 重置成 1 | 只有 **`av_beep_n == 0`（新一次遭遇）** 才出声 |
| ② ★ **锁存被反复重立** | 超声读数**贴得极近时会抖**（有时读到 <3 tick、有时读不到回波 `FF`）；而一读到 `>= US_STOP`，`av_gate()` 就把 `avst` 清成 `AV_FREE` ⇒ 下一拍又锁存 ⇒ **又响 3 声** | 加**滞回**：障碍要**持续**退到 `US_CLEAR`(≈21 cm) 之外 **`AV_CLEAR_TICKS`(≈0.5 s)** 才把 `av_beep_n` 清零（新增 `av_clear_on` / `av_clear_t`）|

⇒ 现在的语义：**"一次遭遇"最多 3 声**；障碍**真的**走远（持续 0.5 s）之后才重新武装。

**★ 附带修掉一个更危险的问题：`-Debug` 变体曾经编不过**

`-Debug` 报 A51 **`ERROR #A29 SEGMENT LIMIT EXCEEDED`** ——
**直接寻址变量区只有 `30H~7FH` 共 80 字节**，而调试版（多 8 字节 `av_dbg_*`）**早已用满**，
C8~C13 一路加的变量（`back_t0` / `prox_stop_t` / `av_clear_t` / `av_beep_n` …）把它顶了出去
（最后一个变量被排到 `0080H`）。
**修法：删掉两个"只写不读"的死变量腾 3 字节** ——
`buz_div`（蜂鸣器早就改成"每个 PWM 步翻一次"，没人读它）、
`ml_start`（写法是"存进去又立刻读出来"，直接赋 `t0` 完全等价）。现在离上限还有 **2 字节**余量。

> ⚠️ **教训（很重要）**：以后往 `main.c` 加全局变量**前先算 DATA 账**，

**★★★ C13 修订2（2026-09-21 晚）—— 靠串口实测才找到的**真凶**：`tick_get()` 绕回**

用户反馈"**也还是会响**"之后没有再猜，而是给 `-Debug` 版加了"**谁在叫**"的打印
（`beepwhy()`：H/L/P/Q/B/T/G 各对应一个触发点）并抓串口，结果**直接把上一轮的判断推翻了**：

| 统计（`firmware\_serial_beep.log`） | 值 |
|---|---|
| `! BEEP` 总数 | 75 —— **`Q` ×70**、`P` ×4、`T` ×1 |
| ★ **`L`（锁存间歇）/ `H`（刹停入口）** | ★ **一次都没有** |
| 状态行 | `IR=1 AV=2 D=08 OF=0 M=0` |

⇒ **根本不是"锁存提醒"（C13 改的那条），而是 C9 的近距提示音** ——
`OF=0`（避障被关掉了）⇒ `prox_beep()` 在工作；`D=08`（≈14 cm）在近距区内。

**时间线（每遇到一条状态行算一窗 ≈0.5 s）**：

| 窗口 | 现象 |
|---|---|
| 1~57（≈28 s） | `OF=1`（避障开）⇒ **一声都没有** ✅（C9 与避障的互斥是好的） |
| **58** | 用户按了避障开关（`T`）⇒ `OF=0` |
| 60 起 | **`Q` 开始响**，而且**每隔约 10~25 窗（≈5~12 s）来一串 `Q=4`（≈2 s）** |

**根因：`tick_get()` 是 16 位，`65536 × 99.83 µs ≈ 6.55 s` 就绕回一次**

```c
if ((unsigned int)(tick_get() - prox_stop_t) >= PROX_HOLD_TICKS) return;   /* 旧写法 */
```

绕回之后 `(now - prox_stop_t)` **又变成小值** ⇒ 判断重新认为"刚停下、还在 2 s 宽限内"
⇒ ★ **停着的车每 6.5 s 左右白白响 2 秒，永远如此** —— 正是用户报的"停着时不时响一下"。

**修法**：改用**一次性标志** `prox_hold` —— 宽限到点就**永久置 0**，只有车"再次动起来"才撤销。
这样绕回最多让宽限**提前结束**（无害），**绝不会**让它重新开始。

> ⚠️ **顺带核对：同类的 `(tick_get() - t0) >= 门限` 在 `ir_holdchk` / `ir_recv` 里也有，
> 为什么它们没事？** 因为那两处是"**超时了就停车/放弃**"—— 绕回只会让超时**晚一点**（最多一个门限），
> **不会误触发**。**只有 `prox_beep` 是拿这个比较当"该不该响"的闸门**，
> "晚"就等于"在不该响的时候响"。⇒ 以后写这种比较，先问一句"**绕回会不会让它以为条件又成立了？**"

> ⚠️ **教训（方法论）**：C13 那一轮我按"锁存提醒"去改了两处逻辑，**方向就是错的**；
> 是 `beepwhy()` 的串口日志一句话把它纠正过来。**逻辑推不出来的时候，先上打印。**

### ★★ C14：**录制时超声波避障"不参与"**（2026-09-21 用户需求，只改 C 版）

**用户原话**：*"现在来修录制环节 录制时默认关闭避障"*。

**为什么要关**：**录制 = 人在教**。超声波那一路在近区会做两件事，**都跟"教"冲突**：

| 它的动作 | 对录制的破坏 |
|---|---|
| `AV_TURN`：把任何动作**改写成"原地右转"** | 人按"前进"，车却右转 ⇒ 教出来的轨迹不是人开的 |
| `AV_HOLD`：太近则**刹停 + 锁存**，并且 **`cur_act` 被清成 `ACT_STOP`** | ★ **直接污染记录**（往记录里写一条 STOP），回放自然也不对 |

**实现：一个唯一出口 `avoid_off()`**（与 C3"循迹时超声波不参与"同一套做法）

```c
static bit avoid_off(void)
{
    if (recon) return 1;        /* ★ 录制中 -> 超声波这一路不参与 */
    if (us_avoid_on) return 0;
    return 1;                   /* 用户把开关关了 */
}
```

改写过的读取点（**全部**改走它，不留第二处判断）：

| 位置 | 原来 | 现在 |
|---|---|---|
| `av_gate()` 的"超声波"分支 | `if (!us_avoid_on)` | `if (avoid_off())` |
| `av_gate()` 的锁存分支 | `if (!us_avoid_on \|\| mode == MODE_TRACK)` | `if (avoid_off() \|\| mode == MODE_TRACK)` |
| `prox_beep()`（C9 近距提示音） | `if (us_avoid_on) return;` | `if (avoid_off() == 0) return;` |
| `d3_mix()`（D3 灯） | 按 `us_avoid_on` | 按 `avoid_off()` ⇒ **录制中 D3 也是灭的** |
| `-Debug` 的 `OF=` 打印 | 按 `us_avoid_on` | 按 `avoid_off()` ⇒ 日志与车的真实行为一致 |

**★ 两个容易漏、但必须做的点**

1. ★ **进录制必须把旧锁存解开**：若 `avst` 还停在 `AV_HOLD`，`motor_set()` 会
   **一直把车按住** ⇒ 表现是"**一进录制车就走不动**"。
   所以在 `av_gate()` 最前面加：`if (avoid_off() && avst == AV_HOLD) avst = AV_FREE;`
   （⚠️ 车头红外不受影响 —— 紧接着的 `ir_det()` 会重新刹停，C2/C3 冻结语义不变。）
2. ★ **用了"实时等效屏蔽"，不是"进出录制时存/取开关值"**：
   退出录制的路径**不止一条**（`rec_exit` / `rec_fullstop` / `clr_key` / 进回放…），
   存/取值很容易漏一处；**实时判定不可能漏**。
   ⇒ 副作用（其实是好事）：录制中按开关（数字键 5 / 长按 S4）只改
   **"离开录制之后"**的状态，两边不打架。

**几处刻意的取舍**

| 项 | 决定 | 理由 |
|---|---|---|
| **车头红外** | **不受影响**，录制中照样刹停 | C2/C3 冻结："最后 1~2 cm"那道关不掉；⚠️ 但它刹停会**往记录里写一条 STOP**（贴着东西时录进去的轨迹就带这个停） |
| **C9 近距提示音** | 录制中**会响**（因为避障此刻"不参与"） | 录制时避障不刹车了，**用声音补回距离感**，算安全补偿；不想要的话在 `prox_beep()` 开头加一句 `if (recon) return;` |
| **录制中按 5 开关避障** | 允许按，但**不影响录制期间**的表现 | 见上：实时屏蔽，退出录制后才生效 |

### ★★ C16：**弧线转弯改急（半径更小、速度不变）**（2026-09-21 用户需求，只改 C 版）

**用户原话**：*"前进时曲线转弯太慢了 能不能转的快一点"* → 选定 **A：弯更急，行进速度不变**。

**实现：只改一个表**（弧线的"内轮"占空比；外轮仍然按用户的档位跑）

```c
/* 改之前 */ static const unsigned char code arc_tab[5] = { 2, 3, 5, 6, 8 };  /* 内轮≈外轮 40% */
/* 现在   */ static const unsigned char code arc_tab[5] = { 1, 2, 2, 3, 4 };  /* 内轮≈外轮 20~25% */
```

**为什么这样就"转得更快"**：差速驱动的转弯半径只取决于"内轮/外轮"的比 r
（L = 轮距）：`R = (L/2) × (1+r)/(1−r)`

| r | 转弯半径 | 说明 |
|---:|---|---|

★ **外轮速度一点没动**，所以**直行与弧线的行进速度都不变**，只是转向变利落 ——

**调参口诀（以后自己微调就改这一个表）**：

- ⚠️ 低档时外轮只有 20%（duty 4），内轮给 **1（5%）电机可能"堵着不转"** ——
  那等于绕内轮原地转，功能上能用，但如果听到"嗡嗡不转"就说明在堵转，改成 2。

#### 改了什么（只两处逻辑 + 一个编译开关）

| | 改之前（**C16（弧线转弯改急）**） | 改之后（**C17（避障分级）**） |
|---|---|---|
| ≥ 21 cm | 放行 | 放行（不变） |
| **12 ~ 21 cm** | **原地右转**（丢掉前进分量） | ★ **弧线右绕**（`ACT_ARC_R`，车不停） |
| 5 ~ 12 cm | 原地右转 | 原地右转（不变，作为"急让"档） |
| < 5 cm 或车头红外 | 刹停 + 锁存 | 刹停 + 锁存（**不变**，且**不受保持窗口影响，立即生效**） |
| 重判频率 | 每趟主循环（约 5 ms）用同一份旧读数重判 | ★ **做出决定后保持约 280 ms 再重判**（进避让仍是立即的） |

**实现要点**（`firmware\c51\main.c`）：

1. `avst` 增加一个取值 **`AV_ARC = 4`**（`motor_set()` 里多一个分支 → 改写成 `ACT_ARC_R`，复用现成的弧线表 `arc_tab`）；
2. `av_gate()` 尾巴重写为"**决策保持 → 重新分档**"两段，用 `tick_get()` 16 位差值判 280 ms（`AV_DEC_TICKS = 2800`）；
3. 新门限 **`AV_SPIN = 7` tick ≈ 12 cm**（与 `US_CLEAR` 同值但语义不同，所以另起名字）；
4. ★ **RAM 增量为 0**：计时复用已有的 2 字节 `av_clear_t`（锁存期间它记"障碍开始退远"，避让期间记"上次分档"—— 两者在 `av_gate()` 里由 `AV_HOLD` 分支提前 `return` 天然互斥，变量声明处已写明）；
5. **编译开关 `AV_L1`**（风格同 `HOLD_MODE`）：`1` = 新行为（默认），`0` = 退回 C16 行为。

**仿真顺带确认的 4 条行为细节**（都是 C16 就有的既有语义，C17 没改）：

1. **`AV_HUMAN`（遥控接管态）可能只维持一趟主循环** —— 只要下一份读数 ≥ `US_STOP`(≈5cm) 就被重新分档丢掉。这正是 **R11（"接管只用一次"）** 要的语义；也意味着 **R6（危险区接管后按住才走）** 的例外窗口很短。
2. **<5 cm 的锁存延迟由采样周期决定**（≤60 ms），但**一旦读到了就立即锁存、不等保持窗口**（安全优先，与"决策保持"不冲突）。
3. **分档门限是量化的**（1 tick ≈ 1.72 cm，且判据是 `<`）：`d≤6`(≲10.3cm) → 原地转；`d=7~11`(≈12.0~18.9cm) → 弧线；`d≥12`(≥20.6cm) → 放行。所以文档写"5~12cm / 12~21cm"是近似值。
4. **锁存那一刻驱动一次停车，之后主循环不再重复驱动**（手动模式下没有别的地方写电机）—— 所以判据要看"最后一次非空驱动"，不是"每趟都有驱动"。
