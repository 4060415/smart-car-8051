## 1. 本轮要回答的两个问题（**这就是全部重点**）

C7 是冲着下面两条报障改的，**所以先测它们，别从别处开始**：

| # | 你之前报的现象 | C7 的判断（假设根因同源） |
|---|---|---|
| **Q1** | 「上电时需要按一下 S3，遥控才有反应」 | C6 之前 `us_read()` 阻塞 → 主循环被拖到 ~0.5 s → **NEC 一帧才 67 ms**，帧头全错过。C7 改成**三态状态机、主循环永不等待** ⇒ **上电后应该立刻能遥控** |
| **Q2** | 「超声避障还是失效」 | 同一个阻塞也饿死了避障判据的刷新。C7 之后 ⇒ **14~20 cm 应弧线右绕**（C17 起；C7~C16 是原地右转），**8~10 cm 应原地右转** |

⇒ **A 段 + B 段就是这两条的判据**。这两段过了，再谈别的（CDEF 段）。

## 2. 上电前提（**每次都查，10 秒**）

| 项 | 要求 |
|---|---|
| ★ **车头 1~2 cm 内不能有任何东西** | 车头红外对管的极性是**上电时自动校准**的（以那一刻 `P3.7` 电平当"无反射"参考）；而红外**关不掉** ⇒ 上电时贴着东西会让极性反，表现是"面前没东西却一直刹停"。**中招了就挪开重上电** |
| 车轮 | **架空**（垫到轮子能自由转）——A/B 段尤其必须 |
| 超声波 | `Trig=P1.3` / `Echo=P1.2` 接好；⚠️ 板上插座 `CSB1` 是 `1:GND 2:Echo 3:Trig 4:VCC`，与 HC-SR04 丝印**正好反**，按原样直插 = **电源接反** |
| 遥控器 | NEC 那只（键值见下表），装上电池 |
| 超声波开关 | **每次上电都复位成"开"**。怀疑被误关 ⇒ 断电重上电最快 |

### 按键速查（唯一真相源：`firmware\c51\main.c` / `config.h`）

| 键 | 码值 | 作用 |
|---|---|---|
| 前进 / 后退 | `46` / `15` | 前进=按一下持续走；后退=**按住才走、松手停** |
| 左转 / 右转 | `44` / `43` | 车停着按=**原地转**；前进中按=**弧线转弯**（R9） |
| 停止 | `40` | 急停 |
| 加档 / 减档 | `5A`（数字键6）/ `08`（数字键4） | 档位 0~5 |
| **超声波避障开关** | `1C`（数字键5） | ★ C 版新增，与**长按 S4** 等效；**两声短响=开 / 一声长响=关** |
| 直选模式 | `0C` / `18` / `5E`（数字键1/2/3） | 手动 / 寻光`L` / 循迹`t` |
| 录制 / 回放 / 清空 | `42` / `52` / `4A`（数字键7/8/9） | ⑦⑧ 创新功能 |

板载：**S3 短按=加档**、**S3 长按≈1 s=切下一个模式**；**S4 短按=减档**、**S4 长按≈1 s=超声波开关**。

### 判据常数（用来算距离）

- 时基 tick = **99.83 µs**；超声波 **1 tick ≈ 1.72 cm**
- **12 tick ≈ 21 cm** → 以上算"够远"；**7 tick ≈ 12 cm**（`AV_SPIN`）；**3 tick ≈ 5 cm** → 以下**刹停 + 锁存**
- ★ **C17 起（C 版）超声波分两档**：**12~21 cm → 弧线右绕**（车不停、保留前进分量）；**5~12 cm → 原地右转避让**；**<5 cm 刹停锁存**
- ★ **C17 起决策保持约 280 ms**：进避让是立即的，但**做出决定后 280 ms 内不重判**（不再每 5 ms 用同一份旧读数改动作）
- 车头红外：**1~2 cm 直接刹车**（不转向、关不掉、**循迹下也生效**）

## ★ C8 新增：**倒车安全化**（2026-09-21 用户需求，6 条新判据）

> **背景**：超声波与车头红外**都装在车头、只朝前** ⇒ 倒车时看不到车后，
> **软件无法做"后向避障"**（要真做得加后向传感器）。所以倒车改成**三条硬约束**：
> ① **限速**（出力最高 2 档）② **连续倒车 3.0 s 自动停车** ③ **前向超声波不参与倒车**。
>
> ★ **改之前**：倒车时若前方 5~21 cm 有东西，`av_gate()` 会把倒车**改写成"原地右转"**
> （表现：倒着倒着突然原地打转）—— 用户报的"后退时避让不生效"就是这个。

| # | 操作 | 预期 | 不对意味着 |
|---|---|---|---|
| **C8-1** | 档位加到 **5**，按遥控**「后退」** | 车**倒得明显比前进慢**（≈2 档出力）；★ **数码管仍显示 `5`**（限的是出力，不是档位） | `motor_set` 的限速没生效 |
| **C8-2** | ★ **按住「后退」不放** | **约 3 秒**后**自动停车 + 两声短响**；**继续按着也不会再动**；★ **松开再按 → 又能倒** | `back_guard()` 没跑，或计时没用系统时基 |
| **C8-3** | ★ 车头前方 **5~21 cm** 放障碍，按「后退」 | ★ **车正常倒车**（**不再原地打转**）—— **这是本次修的主症状** | 倒车放行分支没生效 |
| **C8-4** | ★ 车头前方 **< 5 cm** 放障碍，按「后退」 | ★ **也能倒车离开**（不再被刹停锁存拦下） | 同上 |
| **C8-5** | 把手贴到**车头对管**前 1~2 cm，再按「后退」 | ★ **仍然刹停 + 锁存**（**车头红外仍是全局、关不掉的**，C2/C3 语义未变） | 改过头了，把红外的全局性也去掉 |
| **C8-6** | **回放**一段含倒车的记录 | ① **不被 3 s 限时截断**（回放要忠实复现）；② 倒车段的**出力被限到 2 档** | 回放被 `back_guard` 截断（它应只在手动/录制里生效） |

> ⚠️ **C8-3 / C8-4 是这次真正要证的**：这两条不过，说明倒车仍然"倒不动"。
> ⚠️ **C8-5 是防改过头的**：红外那道"最后 1~2 cm"必须还在。
> ⚠️ 倒车**看不到车后**这件事软件解决不了 ⇒ 演示时**倒车必须人看着**（C8 只是兜底）。

## ★ C9 新增：**超声近距提示音（"倒车雷达"）**（2026-09-21 用户需求，5 条新判据）

> **动机**：避障一关，车就**不会自己刹**了 —— 这时用声音把距离交还给人。
> **门限复用避障那一套**（`US_NEAR=12`≈21cm / `US_STOP=3`≈5cm），不引入新阈值：
>
> | 距离 | 行为 |
> |---|---|
> | ≥ 21 cm 或读不到 | **不响** |
> | 5 ~ 21 cm | **间歇响**：越近越密（≈5 cm 时 **100 ms** 一声，≈19 cm 时 **510 ms** 一声） |
> | < 5 cm | ★ **连续响**（最急 = "贴上了"） |

| # | 操作 | 预期 | 不对意味着 |
|---|---|---|---|
| **C9-1** | ★ 先**关掉避障**（按遥控 **5** 或长按 **S4**，听到"一声长响"= 关），然后手动**前进**靠近墙壁/挡板 | **≈21 cm 内开始叫**，**越近越密** | 门限/映射错，或 `prox_beep()` 没跑 |
| **C9-2** | ★ **松开遥控让车停下**（车停在障碍前 21 cm 内） | ★ **停下后继续响约 2 秒，然后自动静音**；<5 cm 时那 2 秒是**最急的间歇**（≈100 ms），**不是长鸣** | `PROX_HOLD_TICKS` / `prox_hold` 那段没生效 |
| **C9-2b** | ★★ **就让车停着别动，观察 1 分钟**（避障**关闭**、障碍在 21 cm 内） | ★ **一直安静**，**不会每隔几秒又响一下** | ★ 这是 **C13 修订2** 修的 `tick_get()` 绕回 bug（`6.55 s` 绕回 ⇒ 又以为"刚停下"）—— 症状就是"停着时不时响一下" |
| **C9-3** | 停稳 2 秒后**再按前进**（仍在障碍前） | ★ **立刻又开始按距离响**（一"动"就重新武装） | `prox_moving` 的重新武装没做对 |
| **C9-4** | **打开**避障（按 5，两声 = 开），再靠近 | **不响**（改由避障自己"刹停 + 每 0.7 s 间歇响"负责） | 两边都在响 = 互斥没做对 |
| **C9-5** | 进**循迹 `t`** 靠近障碍；以及**回放**中靠近障碍 | 都**不响** | 该排除的模式没排除 |
| **C9-6** | ★ **C8 + C9 组合**（最实用）：关掉避障 → **按住「后退」** | 车倒退时**按距离越近叫得越急**，且**约 3 s 自停**（C8） | 正好等于一个"倒车雷达"，两条功能应能叠加 |

> ## ⚠️ 现场最容易搞错的一点：车上有**两个**会响的东西，按**节奏**区分
>
> | 谁在响 | 触发条件 | 节奏 | 能关吗 |
> |---|---|---|---|
> | **车头红外对管**（`ir_brake`） | 贴到 **1~2 cm** | **一声**，之后**每 ≈0.7 s 一声**（锁存间歇响） | ❌ **关不掉**（C2/C3 冻结语义） |
> | **超声提示音**（C9） | 避障**关闭** + **21 cm** 内 | **越近越密**（100~510 ms），<5 cm 连续响 | ✅ 打开避障即不响 |
>
> ⇒ **"每 0.7 s 慢响" = 红外锁存（说明车已经贴上东西了）；"越来越密" = 超声提示音。**
> 若听到的是前者，那和 C9 无关 —— 是红外那道"关不掉的最后 1~2 cm"在响，属正常。

## ★ C13 新增：**锁存提醒音只响 3 声**（2026-09-21 用户需求，3 条）

> **起因**：车停在障碍前 **5 cm 内**（真的触发锁存）时，**每 0.7 s 一声一直响**，嫌吵。
> **改法**：加"本次锁存已响几声"的计数器，到 `AVBEEP_N`（=3）就安静。
> ★ **锁存本身完全不变**：车照样停着等遥控接管。
> 计数含**刹停那一声**在内 ⇒ 总共约 1.4 s 内响 3 声。

|---|---|---|---|
| **C13-1** | 手动前进，让车逼近障碍到 **<5 cm** | **刹停 + 响**，然后**再响两声就安静**（总共 3 声，约 1.4 s） | `av_beep_n` 的检查/自加没生效，或 `AVBEEP_N` 没改 |
| **C13-2** | ★ **就让它停在 5 cm 内别动**，观察 **1 分钟** | ★ **一直安静**（不会"过一会儿又响几声"）—— 这是 **C13 修订**专门修的洞 | 少了滞回：读数一抖就把 `avst` 清成 `AV_FREE`、再锁存 ⇒ 又响 3 声 |
| **C13-3** | ★ 响完之后**别按任何键**，看车 | ★ **车仍然停着**（锁存没解除）；把障碍挪开也**只是不再响、车还是不走** | 改过头了：把锁存也一起解了（应该只静音） |

## G 段：哪条不过，怎么办（**先读这段，再动手**）

> ★★ **第一原则**：C 版第一次上机，**任何"看起来像老问题"的现象都要先怀疑是移植/新改动引入的**，
> 不要默认"汇编版这样、C 版也这样"。**只回报"第几步 / 看到什么"**，别自己解释原因。

### G-1 先看"响不响"（0 秒，站着看）

| 车的表现 | 它在哪条路 |
|---|---|
| 停住 + **响一声** + 之后每 ≈0.7 s 再响 | 被**刹停锁存**了（红外 或 超声波 <5 cm） |
| **不转、不停、完全不响** | ⚠️ **静默放行** —— 只有三种可能：**超声波开关关了** / **循迹模式（超声波不参与）** / **超声波读到"够远"** |

### G-2 再确认开关和模式（5 秒，不用重烧）

1. 数码管：`0`~`5` = 手动；`L` = 寻光；**`t` = 循迹 → 超声波故意不参与**。
2. 按 **5**（或长按 S4）听：**两声短响 = 刚才是关的**（现在开了，再试避障）；**一声长响 = 刚才是开的**。
3. ★ 最快复位：**断电重上电**（开关每次上电都复位成"开"）。

### G-3 要数据就烧诊断版（**只在需要时烧，别拿它测手感**）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File firmware\c51\build_c_abs.ps1 -Debug
# 烧 firmware\c51\main_dbg.hex
# 然后先关掉 STC-ISP（否则串口被占），再读：
powershell -NoProfile -ExecutionPolicy Bypass -File tools\read_com.ps1 -Port COM7 -Seconds 60
# 日志落点：firmware\_serial_read.log
```

每 0.5 秒（或状态一变）打一行：`! IR=0 AV=1 D=08 OF=1 M=0`

| 字段 | 含义 |
|---|---|
| `IR=` | 车头红外是否检测到（0/1） |
| `AV=` | 闸门：`0`FREE / `1`TURN（原地右转避让）/ `2`HOLD（刹停锁存）/ `3`HUMAN（已接管）/ ★ **`4`ARC（弧线右绕，C17 新增）** |
| `D=` | 超声波距离，单位 tick ≈ 1.72 cm；**`FF` = 读不到/够远** |
| `OF=` | 超声波开关（0/1） |
| `M=` | 模式：`0`手动 / `1`寻光 / `2`循迹 |

| 看到什么 | 说明 |
|---|---|
| `D=FF`（手就在 15 cm） | 超声波**根本没量到** → 回到 G-4 查硬件 |
| `D` 在 `0C`~`13`、`AV=4` | ✅ 正常（C17）：此时车应**边前进边向右拐**（弧线绕） |
| `D` 在 `03`~`0B`、`AV=1` | ✅ 正常，此时车应**原地右转** |
| `AV=` 在 `1`/`4` 之间**秒级以下**反复跳 | ⚠️ 决策保持没生效（应至少保持 ≈280 ms 才切换） |
| `IR=1`（手离得还有 10 cm 就 1） | ⚠️ **车头红外误报** —— 它关不掉，会抢在超声波前刹车（`AV=2`） |
| `OF=0` | 超声波开关被关 → 按 `5`（两声 = 开） |
| `M=2` | 循迹模式：超声波故意不参与，只有红外刹车 |
| `AV=0`（一直） | 闸门没介入 ⇒ 不是避障问题，查电机/驱动 |
| 串口**完全没字符** 且数码管全灭 | ⚠️ **先怀疑诊断版本身**：`prt_boot()` 在第一次写数码管前就要打印，而 `put_char()` 里是 `while(!TI);` ⇒ **串口一出问题整机卡死**。别去怀疑避障 |

> ⚠️ 诊断版**开着打印，红外本来就会漏帧**（9600 baud 打一行 40 字符要 42 ms，而一帧 NEC 只有 67 ms）
> ⇒ **它只回答"解码逻辑对不对"，不能用来测手感**。抓完记得**烧回 `main.hex`**。

### G-4 判定"是硬件还是我的代码"（两条一起跑，结论唯一）

手放车前 **10~15 cm** 不动，分别烧：

| 烧哪个 | 谁在测距 | 数码管含义 |
|---|---|---|
| `firmware\diag\usprobe.hex` | 它**自己**的汇编代码 | `-` = 没回波；`0`~`9` = 距离 = **数字×5 cm** |
| `firmware\diag\us_scope.hex` | ★ **`main.c` 里那一份 `us_read()`**（C7 起非阻塞） | `E` = 等不到回波上升沿；`H` = 够远；`0`~`9` = **固件实际用的 tick 数** |

| `usprobe` | `us_scope` | 结论 |
|---|---|---|
| 有数字 | 有数字（`6`~`9`） | ✅ 硬件和 `us_read()` **都能测** ⇒ 问题在**避障逻辑 / 开关**，不在测距 |
| **`-`** | **`-`** | 硬件这层就没回波 ⇒ 查模块 / `Trig` 线 / 供电（⚠️ 先确认 `CSB1` 插法没反） |
| 有数字 | **`-`** | ★ **硬件是好的、是 `main.c` 的 `us_read()` 有问题** ⇒ **直接报我，我改代码** |

> ⚠️ **别再用 `uscheck.hex` 判硬件**：它的 Trig 那段原来漏了 `CLR`（没有上升沿 ⇒ Echo 永远不变高 ⇒ D3 永远灭），
> 当时的"硬件坏了"是**假警报**（已修，但结论别沿用）。它的**接线判定**（`1`/`2`/`0`/`9`）仍有效。

### G-5 一句话现象 → 先查哪

| 现象 | 最可能的原因 |
|---|---|
| 数码管不亮 / 乱码 / 反复复位 | ★ **栈**（`SP=7FH`）或启动代码 ⇒ **立即停手**，把现象告诉我 |
| 显示 `0` 正常，但按键完全没反应 | 中断没起来（`ET0/EA/TR0`） |
| 按键能加档、电机能转，**遥控完全没反应** | 红外：走 G-3 抓 `K=`（解码正常会打出 `K=46`） |
| `! IR rej lo=.. hi=..` | 见到边沿没解成 NEC；NEC 应为 `lo≈90`、`hi≈45`（单位 100 µs）。`lo` 偏大 = **轮询偏慢** ⇒ 报我 |
| **电机声音比汇编版"闷"、转速略不同** | ✅ **正常，不是 bug**：C 版 PWM 是 **100 Hz**（汇编版 500 Hz），评审本来就要求 100~200 Hz |
| 电机顿挫 / 蜂鸣器沙哑 / 红外时好时坏 | ★ ISR 超时（见 C 段），把现象告诉我 |
