# 避障 L1 优化实施方案（分级避让 + 决策保持）

> ## ✅ 已实施（2026-09-21）—— 结果摘要
>
> **编号**：本方案在讨论稿里的代号是 **L1（分级避让 + 决策保持）**；落地后按本工程编号记为
> **C17（避障分级：12~21 cm 弧线右绕 + 5~12 cm 原地右转 + 决策保持约 280 ms）**。
> 编号含义对照表见 `docs\正式固件开发记录.md` 的 §C17（避障分级）一节开头。
>
> | 项 | 方案预计 | **实际** |
> |---|---|---|
> | code | +60~90 B（→约 3550） | **+65 B：3482 → 3547 B**（`main.hex` HEX 10019 B） |
> | RAM（DATA） | +2 B | ★ **+0 B** —— 计时**复用** `av_clear_t`（原因见下"一处修正"） |
> | 中断开销 | 不变 | ✅ **不变**（最坏 114 / 典型 36 机器周期，实测复核） |
> | 其他模式 | 不受影响 | ✅ 循迹/录制/回放/倒车各有早退分支，`AV_ARC` 只由分档段赋值 |
>
> **指纹**：`main.hex` `25FCFA5C3F2AAE1F…` / `main_dbg.hex` `76D81038500CF302…` / `main_irdiag.hex` `BD973174228402A9…`
> **★ 自证**：`AV_L1=0` 重编，**三个变体的 hex 与 C16 逐字节相同**（`885724F3…` / `718ECDD1…` / `D0F196D1…`）。
> 详见 `docs\正式固件开发记录.md` §C17；验收判据见 `docs\C7上机测试清单.md`「C17 新增」一节。
>
> ### ⚠️ 一处修正：§3.1 那张 RAM 表算错了（**方案里说 +2 B，实际必须 +0 B**）
>
> 方案按**普通变体**算（74/80 → 加 2 B 后仍剩 4 B），**漏了诊断变体**。实测：
> **`DIAG_IR=1` 变体已经用到 79/80 B，只剩 1 个字节** —— `README` 里"DATA 只剩 2 字节"说的正是它。
> 一开始照方案加了 2 字节的 `av_dec_t`，`-Ir` 变体当场编译失败（**A51 `SEGMENT LIMIT EXCEEDED`**）。
> ⇒ 按 Step 2 的要求（"优先使用现有状态变量"）改为**复用已有 2 字节的 `av_clear_t`**：
> 它在锁存期间记"障碍开始退远"、在避让期间记"上次分档"，两者由 `AV_HOLD` 分支的提前 `return` 天然互斥。
> **教训：在这个工程里判断"还能不能加变量"，必须按 `-Ir` 变体算。**

> **状态：✅ 已实施（本节以下为当时提交的方案原文，保留作溯源）。**
> **基准**：C16 定版 `firmware\c51\main.c`（2711 行）+ `main.hex` `code=3482 B`、SHA256 `885724F38568424B0FAC8808F6733A63BF4099ED21A67BFAA0821CDBFAFE6FD5`。
> **本工程编号**：这一轮如果实施，记为 **C17**（沿用 `C1`~`C16` 的编号习惯）。
> 文中所有行号都指向 C16 定版；所有 RAM 数字都是从 `firmware\c51\main_abs.asm` 的 `DSEG`/`BSEG` 段**逐条解析出来的实测值**，不是估算。

## 0. 结论摘要

| 项 | 结论 |
|---|---|
| 能不能做 | ✅ 能做，且**不碰超声波底层状态机、不新增阻塞、不动任何其他模式** |

### 1.2 主循环顺序（决定了闸门与各模式的先后关系）

```

    ① if (mode == MODE_PLAY) { play_step(); continue; }   ← 回放独立分支，不碰闸门
    ② av_gate();                                          ← 闸门先跑，写 avst / 改动作
    ③ if (recon) rec_sample();                            ← 录制采样（采的是 cur_act，不是驱动图案）
    ④ 模式分派：manual_step() / light_step() / track_step() + auto_step()
```

**要点**：闸门跑在模式步**之前**，所以同一趟里"闸门先定动作 → 模式步再写一遍 → 到 `motor_set` 时被闸门改写"。今天的行为就是这样，本次不改变这个结构。

### 2.1 新增的状态与常量（Step 3）

```c
/* ---- 避障闸门状态：新增一个取值 ---- */
#define AV_FREE   0
#define AV_TURN   1     /* 5~12cm：原地右转 */
#define AV_HOLD   2
#define AV_HUMAN  3
#define AV_ARC    4     /* ★ 新增：12~21cm 弧线右绕（保住前进分量） */

#define AV_SPIN       7      /* 7 tick ≈ 12cm：比这更近 -> 从弧线降级为原地右转 */
#define AV_DEC_TICKS  2800   /* 决策保持 2800 × 99.83us ≈ 280ms（一步决定至少管这么久） */
```

```c
static unsigned int av_dec_t;   /* 上次"重新分档"的时刻（只在避让中用） */
```

**为什么不建新状态机**：现有 `avst` 已经是一个"闸门状态"的单字节，两个新档位就是多一个取值；保持只需要**一个时间戳**。若另建 `av_mode/av_band/av_ticks` 三个变量，RAM 与回归面都变大，收益为零。

**为什么不在 `av_gate()` 里加局部变量**：`?DT?av_gate?MAIN` 是一个**覆盖段**（当前 1 B 给 `d`）。而这个自写链接器**不做覆盖分析**，任何新局部都**实打实占 DATA**。所以方案里 `tick_get()` 调两次（比较一次、赋值一次），**刻意不引入局部 `now`**。

### 2.2 E4 的完整新代码（替换 L1407–1428）

> ⚠️ **实施时的两处修正**（见文首）：① 下文的 `av_dec_t` **实际改成了共用的 `av_clear_t`**（RAM +0）；
> ② `AV_L1` 开关用 `#ifndef` 包起来，可用编译命令行 `DEFINE(AV_L1=0)` 关掉、不必改源码。
> 其余逻辑与下文一致。

```c
    d = us_read();
#if DEBUG_UART
    av_dbg_d = d;
#endif
    if (d < US_STOP) {                      /* 太近（<5cm）：立即锁存，不受"保持"限制 */
        av_gate_hold();
        return;
    }

    /* ---- ④ 决策保持：刚做过的决定要认账，别拿同一份旧读数每 5ms 改一次动作 ----
     *   只有"正在避让"（弧线 / 原地转）才需要保持；
     *   AV_FREE 时一发现障碍就立刻进入避让，反应不延迟。
     *   用同一份 16 位时基做差，溢出自动正确（本工程所有超时都这么写）。 */
    if ((avst == AV_ARC || avst == AV_TURN) &&
        (unsigned int)(tick_get() - av_dec_t) < AV_DEC_TICKS) {
        if (cur_act == 0) return;           /* 本来停着 -> 不许自己窜出去 */
        motor_set(cur_act, gear);           /* 由驱动出口按 avst 改成弧线 / 原地转 */
        return;
    }

    /* ---- ⑤ 重新分档（进避让是立即的，之后每 AV_DEC_TICKS 才重判一次）---- */
    av_dec_t = tick_get();
    if (d < AV_SPIN)
        avst = AV_TURN;                     /* 5~12cm：原地右转（急转让开） */
    else if (d < US_NEAR)
        avst = AV_ARC;                      /* 12~21cm：弧线右绕（车不停，保留前进分量） */
    else
        avst = AV_FREE;                     /* ≥21cm：放行 */

    if (cur_act == 0) return;
    motor_set(cur_act, gear);
```

> ★ 注意两处**必须保留**的细节：
> ① `if (cur_act == 0) return;` —— 这是"车停着不许自己窜出去"的守卫（L1421/L1427 原文就有）；**保持分支里也必须再写一遍**，否则用户按了"停止"之后（`cur_act=0` 但 `gear` 不为 0），保持窗口会把车**重新开起来**。
> ② `AV_HUMAN`（遥控接管）在这段里被 `AV_FREE`/分档覆盖，与**现在**的语义完全一致（现在也是 L1417 无条件清 `AV_HUMAN`）——即"接管只在 <5 cm 期间有效，一旦退到 5 cm 以外就重新武装避障"。

### 2.3 E3 的 `motor_set()` 新闸门

## 3. RAM / Flash 增量（Step 2 的账）

### 3.1 DATA（直接寻址区 30H~7FH）——**实测账**

从 `main_abs.asm` 的 `DSEG AT 0030H` 段逐条解析（61 个 `DS`，含 7 个覆盖段）：

| | 普通变体（当时算的） | ★ **诊断变体 `DIAG_IR=1`（当时漏了）** |
|---|---|---|
| 用户区总量 | **80 B**（`30H~7FH`） | 80 B |
| 当前已用 | **74 B**（`30H~79H`） | ★ **79 B（`30H~7EH`）** |
| 当前空闲 | 6 B（`7AH~7FH`） | ★ **1 B（`7FH`）** |
| 方案里的新增 | ~~`av_dec_t`（`unsigned int`）**+2 B**~~ | ❌ 就是它把 `-Ir` 撞停的 |
| **实际做法** | **复用 `av_clear_t`（2 B）：`+0 B`** | **`+0 B` ⇒ 仍是 79 B，编译通过** |

> ⚠️ **顺带更正一条文档口径**：`README.md` 写的是"DATA 段只剩 **2 字节**"，按定版 `main_abs.asm` 实算是 **6 字节**（那条大概是早期 C6 的口径，后来 C8~C16 改掉过变量）。本次改完会顺手把 README 这条订正成实测值。
> 栈不受影响：本工程 `STACK_TOP = 0x7F`，栈从 `80H` 往 `FFH` 长（IDATA 128 B），`30H~7FH` 与栈**不重叠**。

### 3.2 位段 / XRAM

| 区 | 现状 | 本次 |
|---|---|---|
| BSEG（`20H~2FH`，128 位） | 用了 **15 位** | **0** |
| XRAM（`0x0000~0x00FF`） | 记录区 `0x0000~0x00EF`（240 B），保留 `0x00F0~0x00FF`（16 B） | **0**（不加 XRAM 变量，避免 `XBYTE` 的额外代码与慢访问） |

### 3.3 Flash（估算，±30 B）

| 改动 | 估计 |
|---|---|
| `av_gate()` 保持 + 两档分档（含 1 次 16 位比较） | +40 ~ 55 B |
| `motor_set()` 多一个分支 | +10 ~ 15 B |
| `init_all()` 清变量 | +4 ~ 8 B |
| **合计** | **+60 ~ 90 B** ⇒ `3482` → **约 3550 B**，占 8 KB 的 **43.3%** |

> code 根本不是约束（已用自写链接器绕开 Keil Eval 的 2 KB 上限）；三变体（`main` / `main_dbg` / `main_irdiag`）都要重编。

### 3.4 中断与主循环开销

- **中断（`timer0_isr`）一行不改** ⇒ 已实测的最坏路径 114 / 硬线 184 机器周期**不变**。
- 主循环：新增的是"每趟一次 16 位减法比较"（约 20 个机器周期）+ 至多两次 `tick_get()`（各关/开 `ET0` 几个周期）。**在主循环路径上没有任何等待、没有 `delay`、没有 `d_20ms()`**。

## 4. 手动模式 / 寻光模式分别怎么处理

**结论：闸门代码完全共用，一行都不分模式。** 两个模式的差别**不在闸门里**，而在于"谁在写 `cur_act`"：

| | 手动模式 | 寻光模式 |
|---|---|---|
| `cur_act` 来源 | 遥控键（`do_key()`）/ 板载档位（`apply_gear()`） | `light_step()` 每趟自己算（`ACT_LEFT/RIGHT/FORWARD/STOP`） |
| 闸门看到的 `cur_act` | 用户意图 | **上一趟**寻光算出的动作（闸门先跑） |
| 12~21 cm | `AV_ARC` → 弧线右绕（`cur_act` 被改写成 `ACT_ARC_R`） | **同上**（寻光的动作在驱动出口被改写成弧线） |
| 5~12 cm | `AV_TURN` → 原地右转 | **同上** |
| <5 cm | `AV_HOLD`：刹停 + **锁存**，等人按键 | `av_gate_hold()` 走寻光支路：**退回手动模式** + `AV_HUMAN`（响一声、不锁存）——**本次不动** |
| 车停着（`cur_act==0`） | 不自己窜出去（守卫） | 同（寻光两路都遮住 → `ACT_STOP`） |
| 档位 0 | `motor_set` 在闸门**之前**就早退 ⇒ 不动 | `mode_goto()` 进自主模式时已补 `GEAR_DEFAULT` |

> 唯一需要提醒的**观感变化**：寻光模式下 12~21 cm 时，车从"原地右转"变成"边走边绕"（弧线），**前进分量变大了**。这是本次改动的目的（更早、更连续地绕开），但它确实让"自主模式下的避让"更主动一点；如果台上觉得寻光变得更"冲"，可以单独给寻光禁用弧线档（加一个模式判断，+8 B）——**建议 v1 不这么做**，先看实测。

## 5. Step 4：250~300 ms 非阻塞保持机制

### 5.1 机制

```
每趟主循环（约 5ms）都进 av_gate()：
  ├─ <5cm ? ──────────────── 是 -> av_gate_hold()（立即，安全优先，不管保持窗口）
  ├─ 在避让中 且 距上次决定 < 280ms ? ── 是 -> 沿用 avst 驱动当前动作，直接 return
  └─ 否则 -> 重新分档（按当前 d 选 AV_TURN / AV_ARC / AV_FREE），并 av_dec_t = now
```

- **进避让立即生效**（`avst` 原本是 `AV_FREE`，不满足保持条件）⇒ 反应不延迟。
- **进避让之后每 280 ms 才重判一次** ⇒ 解决"同 5 ms 内用同一份旧读数反复改动作"。
- **280 ms 与超声波的关系**：传感器 16 Hz（60 ms 一个新样本）⇒ 280 ms ≈ **4.7 个新样本**，既吸收了量化抖动，又不至于反应太钝。
- 时间基准：`tick_get()`（16 位、1 tick = 99.83 µs），差值比较 `(unsigned int)(now - av_dec_t) < AV_DEC_TICKS`，**溢出（6.55 s 回绕）自动正确** —— 与工程里 `AVBEEP_TICKS` / `TRK_TMO_TICKS` / `PROX_HOLD_TICKS` 的写法一致。
- **不阻塞**：只读时基、只赋值，没有循环等待、没有 `d_20ms()`、没有 `while`。超声波仍是原状态机（中断推进 + 主循环每趟 `us_read()` 取件/触发）。

### 5.2 为什么用"保持时间"而不是"每个新样本重判"
"每个新样本重判"（60 ms 一次）需要一个"样本序号"快照（1 B），且 60 ms 对这台车**仍然偏短**（车只走几厘米就改主意，观感还是抖）。你定的 250~300 ms 是对的量级；`AV_DEC_TICKS` 是一个常量，台上觉得"转太久"就改小（例如 2500 = 250 ms）。

## 6. 为什么不会影响循迹 / 录制 / 回放 / 倒车

| 场景 | 兜住它的机制（**已存在，不需要新代码**） | 本次是否可能让它失效 |
|---|---|---|
| **循迹** | `av_gate()` 在 `ir_det()` 之后、超声波判据之前**早退**：`if (mode == MODE_TRACK) { avst = AV_FREE; return; }`（L1384–1387）。**早退发生在④⑤之前**，所以永远不会把 `avst` 置成 `AV_ARC`。车头红外刹车在早退**之前**，仍然生效 | ❌ 不会（`AV_FREE` 是无条件赋值，`AV_ARC` 一起被清） |
| **录制** | `avoid_off()` 在 `recon` 时返回 1 ⇒ 早退分支 `avst = AV_FREE; if (cur_act) motor_set(cur_act, gear);`（L1401–1405），在④⑤之前；且 `av_gate()` 开头还有一道 `avoid_off() && avst==AV_HOLD → AV_FREE`（L1330） | ❌ 不会。**而且录制数据本来就不含避障动作**：`rec_sample()` 采的是 `cur_act`（人的意图），避障只改**驱动图案**（`dirbits/duty`），从不写 `cur_act`（唯一例外是 `AV_HOLD` 把 `cur_act` 置 `ACT_STOP`，而录制中根本进不了 `AV_HOLD`） |
| **回放** | `play_step()` 走主循环最前面的独立分支，**根本不调 `av_gate()`**；进/出回放都显式 `avst = AV_FREE`（L2209 / L2180）⇒ `motor_set` 的闸门不会改写回放动作；遇障由 `play_safety()` 停车终止（不绕行） | ❌ 不会（那两个赋值是无条件的，`AV_ARC` 一并清掉） |
| **倒车** | `if (cur_act == ACT_BACK) { avst = AV_FREE; motor_set(ACT_BACK, gear); return; }`（L1393–1397），同样在④⑤之前 | ❌ 不会 |
| **避障开关关掉** | `avoid_off()` 早退（L1401）；`avoid_toggle()` 关时也置 `AV_FREE`（L1449） | ❌ 不会 |
| **回放/自主模式切回手动** | `mode_goto()` 只清 `cur_act`；`avst` 由下一趟 `av_gate()` 决定（手动模式重新分档） | ❌ 不会 |
| **`ir_holdchk()`（前进锁定式）** | 它只认 `avst == AV_HUMAN`（L1824）；本次不动 `AV_HUMAN` 的语义 | ❌ 不会 |
| **`prox_beep()`（近距提示音）** | 它只在 `avoid_off()` 时工作；闸门参与时它整段早退 | ❌ 不会 |
| **`apply_gear()` 锁存保护** | 只看 `avst == AV_HOLD`（L872），不改 | ❌ 不会 |

> **残留风险的控制点**：`AV_ARC` 只有两个赋值点（E4 的④⑤），而所有"清状态"点都是**无条件赋 `AV_FREE`**。所以"新状态残留到别的模式"这条路在结构上被堵死了 —— 台上仍要按 §8 的 F 段验一遍。
