2. `docs\待办与风险.md` 的 C 项写的本来就是"**把原工程整理迁入**"，方向早已选定；
3. 复制不改动原件，是唯一"错了也不丢数据"的方案。

## 三、校验方法与结果（可复现）

不信 robocopy 的退出码，改成**逐文件哈希对账**：

```powershell
$src='D:\工程实践'; $dst='D:\工程实践_迁移\原始资料'
$s = Get-ChildItem -Recurse -Force -File $src | Where-Object { $_.Name -ne 'desktop.ini' }
$d = Get-ChildItem -Recurse -Force -File $dst
$sh=@{}; foreach($f in $s){ $sh[$f.FullName.Substring($src.Length+1)]=(Get-FileHash $f.FullName -Algorithm SHA256).Hash }
$dh=@{}; foreach($f in $d){ $dh[$f.FullName.Substring($dst.Length+1)]=(Get-FileHash $f.FullName -Algorithm SHA256).Hash }
# 缺失 / 多出 / 哈希不符 三个集合都应为空
```

| 检查项 | 结果 |
|---|---|
| robocopy 自身报告 | `Files: 113 total, 112 copied, 1 skipped, 0 FAILED`；`Dirs: 16 total, 14 copied, 2 skipped` |
| 逐文件 SHA256 对账（排除 `Desktop.ini`） | **114 源 / 114 合并后，缺失 0、多出 0、哈希不符 0** |
| 字节总量 | 源 221.4 MB / 合并后 221.5 MB（差值为目录项占用，非内容差异） |

> robocopy 的 `113` 与对账的 `114` 差 1：robocopy 用 `/XD .pytmp` 整目录排除了 `.pytmp`，而对账时把 `.pytmp\gdi_test.png` 单独补拷了回来。补拷后重新对账，两边同为 114。
