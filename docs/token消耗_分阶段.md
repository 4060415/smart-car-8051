## 一句话读法

- **最烧 token 的阶段是「③ 主程序编写与设计评审」**，占 **31.7%**（628,262,193 tokens）。
- 前 3 个阶段合计占 **68.0%**：③ 主程序编写与设计评审、④ C 版移植（汇编 → C51 等价移植）、⑤ 基础功能联调与优化（①~⑥ 调参/上机）
- **前期准备只占 3.2%**（63,070,609 tokens）。它跨 09-07 与 09-17 两段，共 8 个会话，
  但**这段上下文最短、会话最短**，所以单价最低——「准备得久」和「烧得多」不是一回事。
- 贵的不是「哪件事难」，而是**这件事在多少个长会话里被反复继续**：
  ③④⑤ 这几个阶段都是由 500~860 步的超长会话撑起来的。
- ⚠️ **去掉重复重跑后，全项目真实量级是 15.2 亿**（现在是 19.8 亿）；
  而 **④ C 版移植去重后只有约 2.2 亿**（现在 4.2 亿）。详见下节「重复消费审计」。

## 重复消费审计（重要）

对 26 个会话做**两两逐步指纹比对**（指纹 = 轮号 + 步号 + 输出长度），
凡步步相同即视为同一条对话被重跑。结果（脚本 `tools/dup_check.py`）：

| 会话 A | 会话 B | A 的步数 | 公共前缀步数 | A 的输入合计 | **被重复消费的输入** |
|---|---|---|---|---|---|
| `7fc2ee62` | `39c402ce` | 607 | **565** | 245,964,944 | **230,434,633** |
| `546c3655` | `23018133` | 515 | **482** | 203,467,642 | **198,040,625** |
| `546c3655` | `6eb77bba` | 515 | 89 | 203,467,642 | 15,918,826 |
| `6eb77bba` | `23018133` | 97 | 89 | 18,169,697 | 15,918,826 |

**结论：重复消费合计 460,312,910 tokens ≈ 全项目的 23.2%。**

具体是两条对话各自被跑了多遍：

- **主开发对话**：`7fc2ee62`（79 轮）与 `39c402ce`（111 轮）**前 65 轮逐字相同**、
  前 565 步完全一致 → `7fc2ee62` 的 94% 是 `39c402ce` 的子集。保留长的那条可省 **2.46 亿**。
- **C 版移植对话**：`546c3655`（35 轮）与 `23018133`（27 轮）**前 27 轮逐字相同**、
  482 步完全一致 → `546c3655` 的 97% 是 `23018133` 的子集。保留长的那条可省 **2.03 亿**。

  拆开看这条 C 对话（逐段实测）：

  | 部分 | 步数 | 输入合计 | 未命中 | 输出 |
  |---|---|---|---|---|
  | 两条共有的 482 步（重跑） | 482 | 198,040,625 | 323,121 | 608,413 |
  | `546c3655` 真正新增的尾部 | 33 | 5,427,017 | 336,329 | 34,188 |
  | `23018133` 真正新增 | 0 | 0 | 0 | 0 |

  即：**4.2 亿的「C 版移植」里，真正的新增工作只有约 2.1 亿**，其余是同一段对话重跑。
- `6eb77bba` 是这条 C 对话在第 89 步分出的短分支，与两者共享 89 步，
  但保留了「怎么绕过 2 KB 限额」的口头解释，**有独立价值，不建议删**。

⚠️ 机制说明：这不是模型在重复劳动，而是**同一条对话被先后完整重跑**——
推测与 09-17 的工作区合并（会话 `6a719abf`）以及中途切换模型版本有关
（同一序列里出现过 `deepseek-flash`、`deepseek-v4-flash`、`deepseek-v4-pro` 三种模型）。
下次换模型 / 换工作区时，走**「继续同一会话」或 fork**，不要从头再喂一遍整段对话。
