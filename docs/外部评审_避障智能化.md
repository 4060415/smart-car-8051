# 外部评审材料：这台小车"避障能不能更智能"（前提：不加硬件）

> ## ★ 结论（2026-09-21 已定）
>
> **编号**：本材料里把候选方案叫 **L0~L5（智能化的几个档位：自动解锁存 / 分级避让 / 试左交替 / 脱困 / 扫描选边 / 加硬件）**；
> 实际落地的那一档 **L1（分级避让 + 决策保持）** 按工程编号记为 **C17（避障分级）**
> —— 编号对照见 `docs\正式固件开发记录.md` §C17（避障分级）一节开头。
>
> 讨论与外部评审后**不加任何硬件**，只做了**低风险的一档 L1（分级避让 + 决策保持 = C17）**：
> **12~21 cm 弧线右绕（车不停）+ 5~12 cm 原地右转 + 决策保持 280 ms**，
> **<5 cm 刹停锁存与车头红外优先级不变**；**RAM 增量 0、code +65 B**，`AV_L1` 开关可一键退回。

## 0. 一句话问题

现在的避障只有三档：**远 → 放行；中距 → 一律原地右转；太近 → 刹停并锁存（要人按键才走）**。
在**不增加任何硬件**的前提下，它能做得更"智能"吗？有哪些方案、各自代价与风险？哪些说法站不住？

## 1. 硬件平台（全部为实测事实）

| 项 | 内容 |
|---|---|
| MCU | STC89C52RC（8051 内核），**8 KB Flash**，**512 B RAM** = 128 B `DATA`（用户区 `30H~7FH` 共 80 B）+ 128 B `IDATA` + **256 B 片内扩展 RAM**（只能 `MOVX @DPTR`，不能用 `MOVX @Ri`，后者拿 `P2` 当高 8 位地址会把数码管显示打花） |
| 时基 | 晶振 11.0592 MHz；Timer0 方式 2 自动重装（重装值 164 = 92 机器周期）→ **1 tick ≈ 99.83 µs**；软件再分频出 **10 ms 节拍** |
| 电机驱动 | L293D；方向 `P0.0~P0.3`（IN1~IN4）、使能 `P0.4/P0.5`（ENA/ENB）；**软件 PWM**：100 Hz、20 步、5% 一档 |
| 档位 | 1~5 档 = 占空比 20/40/60/80/100%（另有一档 0 = 停） |
| 转向方式 | 差速。`DIR_RIGHT` = 左轮正转 + 右轮反转 = **原地右转**（左右镜像）；`DIR_FWD` = 两轮同向正转；**弧线转弯** = 两轮都正转、内轮占空比降到外轮的 **20~25%**（表 `arc_tab={1,2,2,3,4}`），转弯半径 ≈ **0.75 L**（L = 轮距） |
| 显示/提示 | 共阳数码管（`P2` 整口段选）+ 板载指示灯 D3（现在表示"超声波避障是否参与"）；蜂鸣器 `P0.6`（软件方波） |
| 遥控 | NEC 红外接收头 0038 → `P3.3`，**主循环轮询解码**（不用外部中断）；键值：前进 `46`、后退 `15`、左 `44`、右 `43`、停 `40`、加档 `5A`、减档 `08`、数字键 5 `1C` = 超声波避障开关、数字键 7/8/9 = 录制/回放/清空 |
| 板载按键 | S3 = `P3.4`（短按加档 / 长按切模式）、S4 = `P3.2`（短按减档 / 长按避障开关） |

## 2. 资源预算（定版实测）

| 资源 | 现状 | 结论 |
|---|---|---|
| Flash | **3482 / 8192 B = 42.5%**（且已用自写链接器 + 清单回退工具绕开 Keil Eval 版 2048 B 上限） | **代码体积不是瓶颈**，+100~300 B 无所谓 |
| `DATA`（直接寻址区） | 用户区 `30H~7FH` 共 80 B，**只剩约 2 B** | 新增全局变量要先算账，否则得进 XRAM |
| 片内扩展 RAM | 记录区占 `0x0000~0x00EF`（**240 B = 80 条 × 3 B**），保留区 `0x00F0~0x00FF` | **只剩 16 B** 可利用（访问只用 `MOVX @DPTR`） |
| 中断开销 | 最坏路径 **114 机器周期**（软线 92 / 硬线 184 —— 方式 2 下 ≥2 次溢出才会丢时基）；典型 39% | 还有余量，但**别往中断里加活** |
| 主循环 | **完全非阻塞**（一趟几毫秒）；超声波是"中断推进的三态状态机"，主循环只发触发、取结果 | ★ **历史教训**：早期版本在超声波上**阻塞等待回波**，结果主循环被拖到 0.5 s ⇒ **丢红外帧、避障反而失效**。所以任何新逻辑**不得阻塞主循环** |
| 超声波节流 | 两次测距间隔 **≥ 60 ms**（HC-SR04 模块规格），主循环每趟只是"取上次结果" | 有效采样率 ≈ **16 次/秒**；且读到的可能是**最多 60 ms 前的旧值** |

## 3. 现在的避障逻辑（精确到行为）

### 3.1 定位
避障是**闸门（gate）**，不是模式：

| 场景 | 超声波是否参与 | 车头红外是否参与 |
|---|---|---|
| 手动模式 | ✅ | ✅ |
| 寻光模式 | ✅ | ✅ |
| 循迹模式 | ❌ 不参与（被推开就跑偏） | ✅ 仍然刹车 |
| 录制中 | ❌ 不参与（否则会把"绕行/刹停"当成人的操作录进去） | ✅ 仍然刹车 |
| 回放中 | ❌ 走"自己的安全逻辑"：遇障**直接停车并终止回放，绝不绕行** | ✅ |
| 倒车时 | ❌ 不参与（超声波朝前，倒车时读数无意义） | ✅ |

### 3.2 门限与动作（`av_gate()`，每趟主循环执行一次）

```c
#define US_NEAR   12   /* 12 tick ≈ 21 cm：更近 -> 转向避让 */
#define US_STOP    3   /*  3 tick ≈  5 cm：更近 -> 刹停锁存 */
#define US_CLEAR   7   /*  7 tick ≈ 12 cm：退到这儿才停响（滞回，防抖） */

if (ir_det())          { ir_brake(); return; }        /* 车头红外 1~2cm：刹停锁存 */
if (mode == TRACK)     { avst = AV_FREE; return; }    /* 循迹不参与超声波 */
if (cur_act == BACK)   { avst = AV_FREE; ... return; }/* 倒车不参与 */
if (avoid_off())       { avst = AV_FREE; ... return; }/* 录制中 / 开关关掉 */
d = us_read();
if (d < US_STOP)       { av_gate_hold(); return; }    /* < 5cm：刹停 + 锁存 */
avst = AV_FREE;
if (d < US_NEAR) {                                    /* 5~21cm：*/
    avst = AV_TURN;                                   /*   状态=转向避让 */
    if (cur_act == 0) return;                         /*   车本来就停着 -> 不自己窜出去 */
    motor_set(ACT_RIGHT, gear);                       /*   立刻原地右转 */
    return;
}
if (cur_act == 0) return;
motor_set(cur_act, gear);                             /* ≥21cm：按用户动作走 */
```

驱动出口还有第二道改写（`motor_set()`）：

```c
if (avst == AV_TURN) {
    act = ACT_RIGHT;          /* 近区：任何动作都被改写成"原地右转" */
} else if (avst == AV_HOLD) {
    cur_act = ACT_STOP;       /* 太近：强制刹停 */
    dirbits = DIR_STOP; duty_a = 0; duty_b = 0; return;
}
```

### 3.3 由此得到的实际行为

| 前方距离 | 实际发生的事 |
|---|---|
| ≥ 21 cm | 按用户动作走（直行/倒车/转弯/弧线） |
| 5 ~ 21 cm | 车**原地右转**（不是绕行、不前进）；**只要还在近区，每趟主循环（约 5 ms）就重写一次这个动作**；因为超声波读数最多滞后 60 ms 且带 1.72 cm 量化误差，实际表现常是"转—直行—又转"的**抖动式折线**，甚至原地反复打转 |
| < 5 cm，或车头红外贴上（1~2 cm） | **刹停 + 锁存**：蜂鸣器**共响 3 声**后安静，车一直停着；**障碍自己移开也不走**，必须按任意遥控键"接管"（接管后进入 `AV_HUMAN` = 放行；接管那一次，前进会临时变成"按住才走、松手约 0.3 s 停"，松手后即恢复正常） |
| 寻光模式且 < 5 cm | **退回手动模式** + 响一声（不锁存、不间歇响） |

### 3.4 现有的"智能"其实是什么
现在的近区行为等价于一个**单侧（永远向右）的"转到前方清空为止"反射式策略**：原地旋转会让朝前的超声波波束扫过不同方向，转到读数 ≥ 21 cm 就恢复直行。**它没有记忆、没有比较、没有承诺**（每一次判断都是"当下这一帧"）。

## 4. 已经识别出的"显得笨"的点

1. **原地转，丢了前进分量**：近区一进去就变成原地右转，车不再平移，动作突兀；窄通道里更是原地磨。
2. **永远右转**：右边也不通（墙角、椅子腿）时，只会一直往右试。
3. **每 5 ms 重判**：没有"决策保持"，读数一抖就改变主意 ⇒ 折线/抖动。
4. **锁存要人救**：< 5 cm 停了就停死，障碍走了也要按键（这是**故意的安全设计**：刹停后把决定权交回人）。

## 5. 硬约束（这些决定了"智能"的天花板）

| 约束 | 后果 |
|---|---|
| **只有一个朝前的超声波，且没有舵机** | **不转动车身，就不知道左右哪边空**。任何"选边"都必须"转过去量一下" |
| **没有编码器，也没有测速** | 转角只能**时间开环**：所谓"转 45°"其实是"转 x ms"，电池电压下降、地面摩擦变化都会让角度不准 |
| 车头红外量程 1~2 cm | 只能兜"已经贴上了"，做不了预警；与循迹接插件的 `ZC` 同网（接线要现场核） |
| 采样率 16 Hz、读数滞后 ≤60 ms、量化 1.72 cm | 快速接近时可能"一帧就贴上了"；精细的"比例控制"受量化限制 |
| 主循环不得阻塞 | 任何"扫描/多步决策"必须写成**非阻塞状态机**（否则重犯"丢红外帧"的旧病） |
| `DATA` 只剩约 2 B、XRAM 只剩 16 B | 新状态变量要么挤位域、要么塞进 XRAM 的 16 B |
| 工程约束（非技术） | 无版本控制；每改一次都要**重跑一遍既有回归清单**并**重烧一架车**；固件有三个变体（正常版 / 串口调试版 / 键值诊断版）要一起编 |

## 6. 已讨论过的候选方案（供评审排序）

成本栏中：`+B` = 估计增加的代码字节；"状态"指新增的**持久变量**。

| # | 方案 | 做法 | 收益 | 代价 / 风险 |
|---|---|---|---|---|
| **L0** | **锁存自动解除** | 障碍持续退到 ≥ `US_NEAR` 且稳定 0.5~1 s → 自动恢复（低档）前进，不必按键 | 最像"智能"的一处，非常显眼 | +1 状态 + ~30 B；⚠️ **与"刹停后决定权交回人"的既定安全口径冲突**（折中方案：只在寻光/自主模式自动恢复，手动模式仍要按键） |
| **L1** | **分级避让 + 决策节流** | 12~21 cm → **弧线绕行**（复用现成弧线动作，车不停）；5~12 cm → 原地转；< 5 cm → 刹停不变；并加"进近区决定一次、保持约 300 ms 再重判" | 车"边走边绕"，不再一顿一顿打转 | ~20 行、+40~60 B，**几乎不新增状态**；风险低。注意弧线半径 ≈0.75 L，**窄通道可能更需要横向空间** |
| **L1b** | **转向力度比例化** | 不用二元"转/不转"，按距离分档给不同转向力度（如用不同的内轮占空比表 / 不同的旋转占空比），像 P 控制那样"越近转得越凶" | 手感更"模拟"、更平滑 | 一张 `code` 表 + 几行，**0 新增状态**；受量化 1.72 cm 与 16 Hz 采样限制 |
| **L2** | **试左 / 交替** | 右转 200~300 ms 后若距离没变大（带滞回）→ 改左转；或"上次右转，这次先左" | 墙角不再死磕右边；**是"有记忆"的第一步** | 1 状态字节 + 1 个时间戳（丢 XRAM）+ ~60 B；判据要防抖，否则左右横跳 |
| **L3** | **卡死脱困（升级式）** | 连续 3 s 距离一直 < `US_NEAR` 且车在动 ⇒ ① 后退一小段 ② 反向转 ③ 停 + 提示音等人 | 真正解决"椅子腿/墙角"这类局部极值 | 2~3 状态 + ~80 B；要与既有的"倒车限速 ≤2 档 + 连续倒车 3 s 自停"协调，别叠加成"倒退跑飞" |
| **L4** | **扫描选边（无舵机的替代）** | 停 → 右转约 45° → 等 60 ms 测距 → 左转约 90° → 测距 → 转到更空的一侧 → 前进 | 唯一能"真的比较左右"的纯固件方案，演示效果最好 | 非阻塞状态机 + 3~4 状态 + ~120 B；一次决策约 **1~1.5 s**（明显"犹豫"），且**转角开环不准**；录制/循迹/回放都不能用它 |
| **L5** | **加硬件**（用户已排除） | ① 超声波装舵机 → 真正的左右测距 ② 加侧向红外（接插件 `ZC` 通道或闲置脚）做"左右有无障碍"布尔量 ③ 加编码器让转角闭环 | 唯一能让左右判断变准的路 | 接线/结构件/新定时资源 + **重新上机验证一轮**；且闲置脚**尚未实测** |
| **L6** | ❌ 模糊/加权/多传感器融合 | — | 观感提升有限 | 明显增加回归面；报告里也容易写成站不住的说法（本车没有可观测量支撑） |

**不可动摇的既有口径**（任何新逻辑必须保留）：录制中超声波不参与；循迹不参与超声波；回放遇障只停车、不绕行；倒车时超声波不参与；主循环不得阻塞。

## 7. 想请外部评审回答的问题（重点）

1. **"扫描选边"值不值？** 在"单向传感器 + 无编码器 + 转角时间开环"的条件下，一次 1~1.5 s 的"转过去量一下"的决策停顿，收益是否大于代价？有没有更省的等价做法？
2. **状态最少、观感最明显的组合是什么？** 就 L0~L4 给一个推荐顺序与理由；有没有我漏掉的经典做法（例如"bug 算法"家族里的哪一条最适合单传感器非阻塞实现）？
3. **L1 的方向性风险**：远距离用"弧线绕行"、近距离才"原地转"，在窄通道/桌腿密集场景里会不会反而更糟？分档阈值该按什么定？
4. **L0 的安全冲突**：自动脱困/自动恢复 与"刹停后决定权交回人"是否必然冲突？有没有既不失控又能"看起来会自己想办法"的折中？
5. **比例化（L1b）在 16 Hz、1.72 cm 量化下是否真的能"更平滑"**，还是只是噪声被放大？需不需要滤波（中值/滞回），代价多大？
6. **零成本改进**：有没有纯"参数/提示/节流"层面的改动（不新增状态、不改安全口径），能明显改善观感？例如门限重定（现在是 21 cm 就开始躲）、提示音/显示反馈、决策节流时间。
7. **对"维持现状、不改"这个决定，你反对吗？** 如果反对，请给出**一条**你认为最该做的改动，并说明它能带来什么、风险是什么。

## 8. 决策背景（供评审参考，不影响你的独立判断）

- 用户明确**不接受增加硬件**（舵机/侧向传感器/编码器都不加）。
- 当前固件已**上机验证通过**并处于定版状态；按本工程规矩，**任何固件改动都会作废既有回归结果，必须重跑回归并重新烧录三个变体**。
- 临近交付/答辩，用户倾向**冻结不改**；这份材料是为了确认"有没有被忽略的、低风险高收益的一条"。
- 结论如果同样是"不值得改"，我们就正式把避障冻结在当前形态，并把理由写进开发记录。
