### 2.4 执行器与人机

| 项 | 说明 |
|---|---|
| 电机 | 2 只直流减速电机，L293D 双 H 桥驱动 |
| 方向图案（`P0` 低 4 位 `IN1..IN4`） | 停止 `00H` / 前进 `05H` / 后退 `0AH` / 原地左转 `06H` / 原地右转 `09H` |
| 调速 | `ENA`/`ENB` **软件 PWM**：周期 20 tick = **2 ms = 500 Hz**，占空比 **5% 一档**（20 档量化） |
| 档位 | **0~5 档**：0 = 停，1~5 = 占空比 **20 / 40 / 60 / 80 / 100%** |
| 差速转弯 | 内轮占空比按表取值（当前 = 外轮的 **40%**）→ "弧线转弯"（两轮**都正转**） |

| 蜂鸣器 | 无源，方波由中断产生（约 1 kHz），低电平发声 |
| 按键 | 板载 **S3**（短按加档 / 长按切模式）、**S4**（短按减档 / 长按开关全局避障） |

## 3. 软件地基（已实现、可直接复用）

### 3.1 时基与中断（这是全系统的地基）

| 资源 | 配置 | 用途 |
|---|---|---|
| **Timer0** | **方式 2**（8 位自动重装），重装值 **164** → ≈ **99.8 µs / tick** | **唯一的系统时基**：红外脉宽测量、松键超时、软件 PWM、所有计时 |
| **Timer1** | 方式 2，`TH1`=`0FDH` | 串口 9600 波特率（调试）。**不可再作他用** |
| 外部中断 INT0/INT1 | **未使用** | 红外解码是**主循环轮询**实现的（靠 100 µs tick 量脉宽，已实测可行） |
| 10 ms 节拍 | = 计满 **100 tick** | 报告里录制/回放的计时单位 |

> ★ **架构硬约定**：**主循环永远不直接写 `P0`**。`P0` 由 Timer0 中断每 99.8 µs 组装一次
> （方向位来自 `DIRBITS`，`ENA`/`ENB` 来自 PWM 比较，蜂鸣器位来自 `BUZB`）。
> 这样"主循环改方向"和"中断打 PWM"不会互相踩。

### 3.2 已实现的六块功能（全部上机验证过）

| 块 | 功能 | 关键行为 |
|---|---|---|
| ① | 电机层 | `Motor_Set(action, speed)` 统一出口、软件 PWM、档位显示、蜂鸣器、按键调速 |
| ② | 红外遥控 | NEC 解码（含短引导码变体 + 重复帧识别）、方向控制、遥控调速 |
| ③ | 模式状态机 | 手动 / 寻光 / 循迹；**长按 S3 循环切换**；**遥控数字键 1/2/3 直选模式**；模式代号显示 |
| ④ | 寻光 | 读两路光敏，朝有光侧走 |
| ⑤ | 循迹 | 双探头差分，含**脱线超时**（约 0.5 s） |
| ⑥ | 避障 | **不是模式，是全局"闸门"**（见 3.3） |

**动作码表**（这就是 `Motor_Set` 的输入）：

| 码 | 含义 |
|---|---|
| `00H` | 停止 |
| `01H` | 前进 |
| `02H` | 后退 |
| `03H` | 原地左转 |
| `04H` | 原地右转 |
| `05H` | **弧线左转**（两轮都正转、左轮慢）|
| `06H` | **弧线右转**（两轮都正转、右轮慢）|

### 3.3 避障"闸门"（块⑥，**理解现有行为的关键**）

避障用**超声波**判档，用一个 4 态状态机 `AVST` 决定"要不要改写动作"：

| 距离 | 状态 | 行为 |
|---|---|---|
| **≥ 21 cm** | `AV_FREE` | 放行，按原动作走 |
| **5~21 cm** | `AV_TURN` | **把动作改写成"原地右转"** → 绕开 |
| **< 5 cm** | `AV_HOLD` | **刹停 + 锁存**（车不动，**间歇响约 0.7 s**，决定权交回遥控） |
| — | `AV_HUMAN` | 遥控已接管：完全放行；距离回到 ≥ 5 cm 后自动回 `AV_FREE`（避障重新武装） |

另有**滞回**：进入刹停用 5 cm，**解除**要退到约 **12 cm**（否则读数抖动会反复跳）。
**车头红外（`P3.7`）是冗余通道**：量程只有 1~2 cm，一旦检测到就**等同于"<5 cm"**，走同一条路径。

**作用范围**：**只有"手动"和"寻光"两个模式参与避障；循迹模式不参与**（这是用户明确要求的）。
- 手动：5~21 cm 自动右转绕开；<5 cm 刹停 + 锁存 + 间歇响。
- 寻光：5~21 cm 同样绕开；**<5 cm 不刹停，而是"退回手动模式"**（响一声，不锁存）。
- **长按 S4 约 1 s 可以整体关掉避障**（这是"车被避障拦住不动"时的救急手段）。

### 3.4 遥控器键位表（21 个码）

| 面板/含义 | 码值 | 状态 |
|---|---|---|
| 前进 | `46H` | ✅ 实测确认 |
| 后退 | `15H` | ✅ 实测确认 |
| 左转 | `44H` | ✅ 实测确认 |
| 右转 | `43H` | ✅ 实测确认 |
| 停止 | `40H` | ✅ 实测确认 |
| 加档（面板数字键 `6`） | `5AH` | ✅ 实测确认 |
| 减档（面板数字键 `4`） | `08H` | ✅ 实测确认 |
| 数字键 `1`/`2`/`3` → 直选模式 | `0CH`/`18H`/`5EH` | ⚠️ **码值是结构推断的，未实测** |
| 数字键 `5`（原"模式键"） | `1CH` | 功能已取消（按了等于"不认识的键"） |
| 数字键 `7`/`8`/`9` | `42H`/`52H`/`4AH` | 可从码表结构确定，未实测 |
| **剩余未占用码** | **`45H` `47H` `07H` `09H` `16H` `19H` `0DH`** | 共 7 个，**"码值已知、但对应面板上哪个按钮未知"** |

> ★ **重要教训**：这颗遥控器的**码值表是可靠的**（21 个码都验证过结构），但**"哪个码是面板上哪个按键"这一层推断错得很惨**
> （实测 `08/1c/5a` 是数字键 `4/5/6`，**不是**原先推断的 `7/8/9`）。
> 所以：**按键名一律以实测为准**，认错的后果很轻（不认识的键只响一声、电机不动，**不会乱跑**）。

### 3.5 可复用的"现成零件"（写新功能直接调）

| 例程 | 作用 |
|---|---|
| `MOTOR_SET_ACT` | **统一电机出口** `Motor_Set(action, speed)`：入 = 动作码 + 档位，内部会自动过避障闸门 |
| `BEEP` | 非阻塞蜂鸣（入 = 半周期个数；真正翻转在中断里，**不拖慢主循环、不会错过红外帧**）|
| `TICK_GET` | 读 16 位 tick 时基到 `R4:R5`（所有超时/计时都靠它）|
| `SHOW_STATE` / `SHOW_MODE` | 数码管显示档位 / 模式代号（`D3` 亮 = 在动）|
| `IR_RECV` | 收一帧红外（**最多阻塞 25.6 ms**），出 `IRSTAT`：0 = 完整帧 / 2 = 帧被拒 / 3 = 重复帧 |
| `KEY2ACT` | 键值 → 动作码（含"前进中按左右 = 弧线"的判断）|
| `MODE_GOTO` | 跳模式（共用副作用：清动作、补默认档、刷显示、响一声）|
| `KEY_SCAN` | 板载按键扫描（20 ms 去抖 + 短按/长按区分）|

### 3.6 主循环结构（每趟循环做的事）

```
MAIN_LOOP:
    AV_GATE            ; ① 测一次超声波/红外，只更新 AVST（不改电机）
    MODE 分支:
        手动 -> 收红外 -> DO_KEY（打印/换挡/动作/显示/响）
        寻光 -> LIGHT_STEP 一步；再收红外（只认"停止"和"模式直选""加减档"）
        循迹 -> TRACK_STEP 一步；同上
    松键超时判定       ; ② 约 300 ms 没新帧 -> 视为松手（"按住才走"的动作停车）
    KEY_SCAN -> 板载按键（加档/减档/长按切模式/长按开关避障）
```

**当前手感约定**（用户逐条调出来的，新功能不能随便破坏）：

- **前进 = 按一下一直走**（锁定式；只有"前进"有这个待遇）
- **后退 / 左转 / 右转 / 弧线 = 按住才走，松手约 0.3 s 停**
- **车停着按左/右 = 原地转；车在前进时按左/右 = 画弧线**（松手回到前进）
- 被刹停锁存后，**任意遥控键**算"人来接管"，锁存解除

| **片内扩展 RAM（`MOVX @DPTR`）** | **一个字节都没占** | **256 B 全空** ← 报告里那个 240 B 缓冲就打算放这儿 |
| 直接寻址 `DATA` | 用到 `5FH` | `60H`~`7FH` **还剩 32 B** |
| `IDATA` 128 B | 未用 | 备用 |
| **定时器** | Timer0 已被 PWM + 时基占满；Timer1 已被串口占 | ⚠️ **没有空闲定时器**（但 100 µs tick 可以做任意分频） |
| **中断** | INT0 / INT1 都空着 | **可用** |
| **空闲引脚** | `P1.7`（图纸无连线）；`P1.4`/`P1.5`（2 脚接插件，用途未定）；`P1.6`（网标 `P16`，未定） | ⚠️ 三个都**未实测**，要用得先上机探测（有 `lightscan.hex` 这种现成的"逐脚扫描"工具） |
| ⚠️ 不可用 | `P0.7`（中断组装 `P0` 时会 OR 成 1）；`P3.x` 全占满 | — |

## 5. 原创新功能（动作录制/回放）的**报告硬指标**

这份报告的方案本身是**完整的、可实现的**，指标如下（如果继续用这个方向，就按这个做）：

| 项 | 报告要求 |
|---|---|
| 动作单元 | **3 B**：动作码 1 B + 时长低 1 B + 时长高 1 B，**时间单位 10 ms**（单动作最长 655.35 s） |
| 缓冲区 | **240 B = 80 条**，放**片内扩展 RAM**，用 `MOVX @DPTR`（**不能用 `MOVX @Ri`**，见第 7 节） |
| 相邻同类动作合并 | 连续相同动作**不新建条目**，只累加时长 |
| 状态机 | **手动 / 录制 / 回放 / 安全停止** 四态；**停止键最高优先** |
| 进入录制 | **清空上一段未保存记录** + 复位当前动作时长 + 蜂鸣器提示 |
| 录制中 | 10 ms 节拍累加时长；**超过规定时间没收到方向键重复码 → 当前动作切"停止"**（防松键后继续跑） |
| 退出录制 | 结束键 / 停止键 / **缓冲区满**（满即封存 + 停车 + 提示） |
| 进入回放 | **有效记录数 ≥ 1**，0 条**拒绝**并提示 |
| 回放中断 | 停止键、**任意方向键**、记录结束 |
| ★ 回放安全 | **回放中前方检测到障碍 → 立即中断回放并停车**（注意：与块⑥ 的"转向绕开"**语义不同**） |
| 掉电保存 | 可选扩展 **24C02 EEPROM**（报告里是"可选"，套件里**未确认有**） |

**报告的验收标准表（表 5）**：

| 测试项 | 验收标准 |
|---|---|
| 基础遥控 | 每个按键与预设电机动作一致，停止键能及时停车 |
| 录制正确性 | 录"前进—左转—前进—停止"：**条目顺序正确；连续前进被合并，无冗余条目** |
| 回放一致性 | 同一序列连续回放 **3 次**：**动作顺序完全一致**；**每个动作持续时间误差 ≤ ±5%**；3 次落点散布 ≤ ____ cm（现场实测填入） |
| 中断安全性 | 回放中按停止键/方向键，**电机在 ≤ 20 ms（2 个控制节拍）内停止** |
| 边界条件 | 空记录回放被拒绝且有明确提示；录到 80 条上限自动封存并停车提示；**长按方向键后松键 ≤ 0.3 s 转停止**；**不死机、不越界** |

**方案自评的"创新点"**（报告第 3.1 节，写得其实挺硬）：

> 不保存红外**载波和原始波形**，而是把遥控操作转换成机器人能理解的**语义化动作**（"以何种运动方式行驶了多久"）。
> 原始波形数据量大且与遥控协议绑定；语义化编码**存储小、且换遥控器/加蓝牙后上层模块仍可复用**。

## 6. 硬约束清单（新方案不能违反的）

1. **`P0` 主循环不许直接写** —— 必须走 `DIRBITS`/`DUTY_A`/`DUTY_B`，`P0` 由中断组装。
2. **访问扩展 RAM 只能用 `MOVX @DPTR`** —— `MOVX @Ri` 会拿 `P2` 当高 8 位地址（`P2` 是数码管段选），一用数码管就花。
3. **不能用 `P0.7` 当输入/输出**（中断把 `P0.7` OR 成 1）。
4. **验收版固件必须关掉串口打印**（9600 下每字符约 1 ms，打一行会错过下一帧红外 → 遥控"没反应"）。
5. **主循环不能长时间阻塞** —— 唯一允许的阻塞是 `IR_RECV`（最多 25.6 ms）；所有延时/计时要用 100 µs tick，不用软件延时。
6. **`IR_RECV` 只有"完整帧"能用** —— 按住不放时遥控器发的是 NEC **重复帧**（`IRSTAT = 3`），它**到不了帧处理分支**。
7. **`P2` 整口被数码管占死**（含 `P2.0` 的 D3），不能再挪作他用。
8. **`P1.4`/`P1.5`/`P1.6`/`P1.7` 要用必须先上机探测** —— 不能按图纸推断（本项目已被"图纸说未使用、实际有功能"坑过）。
9. **失败要安全**（fail-safe）：读不到超声波回波时**当成"够远"**，所以极近距离反而可能漏检 —— 这也是加红外冗余的原因。
10. **数码管只有 1 位** —— 任何"显示状态"的设计都必须能塞进 1 个字符（或靠闪烁/蜂鸣编码）。

## 7. 已知的坑与教训（会影响新功能的设计）

| # | 坑 | 后果 / 对策 |
|---|---|---|
| 1 | 遥控器是 **NEC "短引导码"变体**（引导码高电平约 2.25 ms，不是 4.5 ms） | 标准 NEC 解码会把**每个完整帧都当重复帧丢掉** → 表现为"完全没反应"。当前固件用"短引导码两段式判定"解决 |
| 2 | **循迹探头不是比较器整形输出**，是分压节点直接进 MCU | 报告若按"经 LM393 整形"写就错了；好在**实测电平稳定**，不影响功能 |
| 3 | **车头红外对管（`P3.7`）极性折腾了三版** | 最后改成**上电自动校准极性**（以开机瞬间电平为"无反射"参考）——**错误的极性最多让这一路失效，绝不会把车锁死** |
| 4 | "同键去重"曾把**真实按键**吃掉 | 现象：遥控加/减档**只能调一次**。修法：**彻底删掉去重**（重复帧本来就到不了那里） |
| 5 | 避障锁存状态曾被"永不清除" | 现象：前进**偶尔中断、还不响**（因为进了"接管态"被静音了）。修法：**接管态只用一次**，本次动作结束就收回 |
| 6 | 避障曾**绕过"档位即前进"这条路径** | 现象：手动模式下**避障失效**（车不躲）。根因：那条路径只写电机、没写"当前动作"变量，闸门以为"车没在动" |
| 7 | 体积受 Eval 2048 B 限制 | 已解决（工具链限制用户已处理）。但**调试打印 434 B**，验收版必须关 |
| 8 | 汇编短跳只有 −128~+127 | 代码一多就报 `TARGET OUT OF RANGE`，要改写成"反向短跳 + `LJMP`"（项目里已踩过两次） |
| 9 | 超声波插座**线序和 HC-SR04 模块脚序相反** | 直插会不工作甚至发热，必须**按板上丝印一根根接** |
| 10 | 板上**没有稳压器**，MCU 直连电池轨 | 用 4 节镍氢；~~**USB 和电池不能同时接**~~ → ✅ **2026-09-20 作废**（同时接也能正常下载，见 §2.5） |
| 11 | 图纸/文档里"未接传感器"的结论被推翻过 3 次 | **"没找到 ≠ 证明没有"** —— 一切以实测为准 |

1. **在"创新功能"这一栏，什么样的选题对这门课最划算？**

   评分里"成品验收 20% **综合、创新**"、且要求**答辩现场演示**。
   现有方案（动作录制回放）与官方第 3 项直接对应 —— **换掉它是不是明智？**

2. **如果保留"路径存储与复现"这个大方向，怎样让它更像"创新"而不是"照抄报告"？**
   例如：多段路线存储与选段回放？录制时同步记录**档位/弧线**（比报告的动作码表更细）？
   回放时叠加避障与超时保护？录制数据用 `P1.4/P1.5` 外接 EEPROM 掉电保存？
   把"录制"扩展成"示教 + 编辑"（比如录制中允许按键修正）？

3. **如果换成别的创新点，在这个硬件上哪些是"做得出来且好演示"的？**
   硬件能提供的**唯一连续量是超声波距离**；其余全是二值量（红外反射、光敏、按键）。
   **没有**编码器、陀螺仪、摄像头、语音。
   在这个约束下，"创新"应该往哪走（例如：超声波跟随/定距巡航、沿墙走、地图/栅格记忆、
   自动避障探索 + 路径回放、多传感器融合决策、状态机可视化……）？

4. **"创新性"在答辩里怎么说得站得住**（评分看的是"综合、创新"）？
   是"新颖的题目"重要，还是"同一题目里新颖的实现/论证"重要？

5. **换方向的成本**：已交的课题报告整篇是按"录制回放"写的（含动作码表、状态机、存储规划、测试验收表）。
   如果换题目，报告要重写多少？**有没有"保留这套编码与状态机框架、只换应用层"的省力路线？**

6. **风险**：离验收时间有限，基础功能已经跑通（这是稳的分数）。
   创新功能做不完/做砸了会不会**反而拖累"成品验收"**？该选"小而稳"还是"大而炫"？
