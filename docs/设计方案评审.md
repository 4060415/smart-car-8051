## 〇、一句话结论

**创新功能那部分（语义化动作录制/回放）是这个方案最扎实的地方，思路对、编码省、安全机制也齐；
真正有问题的不是"做什么"，而是两件事：① 报告里一半的硬件描述与实物不符（引脚、位号、供电都对不上）；
② 基本功能里的"循迹/避障/寻光"在硬件层面有三个没闭合的前提，其中"循迹与避障共用同一对探头"这一条
会让报告里的"综合模式"在物理上就不成立。**

## 一、先说站得住的地方（这些不要改）

| 项 | 为什么好 |
|---|---|
| **语义化录制**（只存"动作码+时长"，不存红外波形） | 这是真正的创新点，而且理由写得对：波形与遥控协议绑定、数据量大；机器人要复现的是"怎么动了多久"。换遥控器/加蓝牙后上层复用 —— 这个论证站得住 |
| **3 B/单元、240 B、80 条** | 编码紧凑，且我实测过 STC89C52RC 有 512 B RAM，**装得下**（`docs\代码体积预算.md`）；240 B 不占 2 KB 代码额度 |
| **相邻同类动作合并** | 省存储的关键，正确 |
| **统一 `Motor_Set(action)` 出口** | 手动与回放共用，改电机方向只改映射表 —— 解耦正确，且现有 `remote.asm` 的 `MOTOR_SET_ACT` 已是它的原型 |
| **安全机制成体系** | 停止键最高优先 / 回放任意键中断 / 空记录拒绝 / 满则封存提示 / 上电先关使能 —— 这一组是报告里最像工程的部分 |
| **不动机器硬件、复用套件** | 符合课程"复用原套件"的要求，风险最小 |

## 二、硬件事实层：9 处与实测不符（报告必须改口径）

完整对照表见 `docs\固件审计_Step1.md` 第 6.1 节，这里只列最会被追问的：

| 报告写的 | 实测是 | 后果 |
|---|---|---|
| 0038 输出 → `P3.2`(INT0)，**用外部中断解码** | `P3.3`(INT1)；`P3.2` 是按键 S4；**全工程没有任何程序用外部中断** | 报告的核心时序图错了；答辩问"你怎么解码的"会答不下去 |
| 数码管段码由 **`P0`** 输出 | **`P2.7`~`P2.1`**（顺序还反着），`P0.6`=蜂鸣器、`P0.0~P0.5`=电机 | 引脚分配整块错 |
| 电机方向 **`P2.x`**、EN=PWM | 方向+使能 = **`P0.0`~`P0.5`** | 同上 |
| 蜂鸣器 **`P1.x`** | **`P0.6`** | 同上 |
| 循迹/避障/寻光信号"经 LM393 整形后送 `P1`/`P2`" | 循迹/避障探头实测在 **`P3.5`/`P3.6`**，且这两个脚上的网**够不到 IC5**（没有比较器整形，是分压节点直接进 MCU） | 与报告"W1/W2 调灵敏度"的说法冲突 |
| 避障 = 红外对管 **V7/V4** + `IC3` | 实测在用的是接 `P3.5`/`P3.6` 的那两个探头 + 你加的**超声波**；`V7/V4`+`IC5` 的输出**没追到 MCU 任何脚** | 报告点名的位号与在用的探头**对不上号** |
| `S3` = **复位键**（电路分析报告第 2 章） | `S3` = **`P3.4` 用户按键**（上拉+按下为低），已跑通 | 两份报告互相矛盾且都与实物不符 |
| "10 ms 统一节拍" | 实际 Timer0 是 **100 µs tick**（方式 2 自动重装）；**Timer1 被串口 9600 占着** | 报告没提 Timer1 的占用，资源规划不完整 |
| 逻辑电源"经**稳压/分压**" | 元器件清单与图纸里**没有 7805/AMS1117 之类**，而 MCU 的 VCC(40) 追线确认**直接接电池轨 `VCCBAT`** | ⚠️ **实车风险**：4 节新碱性电池空载 6.0~6.4 V > STC89C52RC 的 5.5 V 上限 |

> 最后一条不只是"报告写错"，是**可能烧板子**的问题。答辩前务必确认：要么板上真有个没被识别的降压件，要么报告这句删掉、并改用镍氢电池/串二极管。

## 三、方案层面的问题（真正影响"能不能做出来、能不能验收"）

### 3.1 ❗ 循迹与避障共用同一对红外探头 —— "综合模式"在物理上不成立

- 报告表 1/表 2 把"循迹、避障"都归到同一组红外对管（V7/V4，或实测在用的那两个）；
- 而实际硬件上，**同一对反射式探头不能同时朝下（看地面黑线）又朝前（看障碍物）** —— 装法互斥；
- 但报告的功能清单里写着"**循迹、避障、寻光可切换模式综合运行**"，验收也要求综合模式。

**结论**：这一条是方案里最大的逻辑漏洞。两条出路，二选一并在报告里写死：

| 出路 | 做法 | 代价 |
|---|---|---|
| **A（推荐）** | 避障改用你**已经上机跑通**的超声波 HC-SR04（`P1.2`/`P1.3`），循迹保留朝下的红外探头 → 两者物理独立，综合模式才成立 | 报告里要补超声波模块（现在**器件表里根本没有它**） |
| B | 明确写成"循迹与避障共用同一组探头，靠**改变安装朝向**切换，属分时使用，不是同时运行" | 综合模式降级为"模式切换"，不能说"综合运行" |

### 3.2 ❗ 寻光只有一路且未闭环

- "向光照较强一侧转向"需要**左右两路**比较；而追线只闭合了 **`P1.1` ← 光敏比较器 IC3 的 `OUTA`**，
  `IC3` 的 `OUTB` **去向没追到 MCU**，`P1.6` 通过网标号连到传感底板接插件但**用途未定**；
- 而且 `P1.1` 这一路**从未上机验证过**（现有程序里没有任何一行读光敏）。

**结论**：报告把寻光当"已具备的硬件能力"来写，实际上**两路都不确定**。开工前必须实测（见 `docs\固件审计_Step1.md` 阶段 0.1）。

### 3.3 ❗ 录制的触发前提依赖"NEC 重复码"，而这只遥控器可能不发

- 报告 3.3 写"若超过规定时间未收到方向键**重复码**，程序将当前动作切换为停止" —— 它把"按住键会发重复码"当作既定前提；
- 但本工程自己的文档里已经记着一条实测提示：**"如果按住键时小车一颠一颠的，说明这只遥控器不发 NEC 重复码"**
  （`firmware\remote\remote.asm` 顶部注释，`HOLD_MODE` 就是为这个情况准备的两套模式）。

**结论**：录制"前进 2 秒"到底靠什么判定（重复码？松键超时？还是按一下开始/再按一下结束）——
报告必须**先写清这个前提，并给出两种遥控器都能用的判定方式**，否则录出来的时长是随机的。

### 3.4 ⚠️ 纯开环回放 vs 验收标准"终点偏差在课程允许范围内"

- 方案是**纯时间开环**：按 10 ms 节拍重放动作，没有编码器、没有测速反馈；
- 而表 5 的验收标准写"运动方向与示教顺序一致；**终点偏差保持在课程允许范围内**"。

**结论**：电池电压下降、地面摩擦、轮胎打滑会让同一段程序每次跑的距离都不同，**开环下这个标准基本靠运气**。
建议把验收标准改成可测量、且方案能保证的形式，例如：

> "动作**顺序**与示教一致；各动作**持续时间误差 ≤ ±5%**（用数码管/串口打印实测）；
> 终点重复性以**同一电量下连续 3 次回放的落点散布**衡量，不承诺绝对位置精度。"

（报告第 7 章其实已经把"编码器/闭环纠偏"列为后续改进 —— 那验收标准就应该同步降级，两处不能自相矛盾。）

### 3.5 ⚠️ PWM 调速：电气约束和时间资源都没做预算

- 报告说"改变 L293D EN 端 PWM 占空比"调速，但**没提**：EN 接在 **P0** 口，而 P0 是**开漏**、靠 10 K 排阻上拉 —— 上升沿偏慢，
  PWM 频率不能随意提高（这也是现有 `remote.asm`/`usfollow.asm` 都明确写"本程序只做低速开关，不做 PWM"的原因）；
- 报告的 Timer 规划里：Timer0 要管 10 ms 节拍，**Timer1 已被串口 9600 波特率占用**（调试期必需），
  红外解码又声明用外部中断 —— 那么 PWM 由谁产生？**报告没回答**。

**结论**：PWM 的可行方案我建议写清：**在 Timer0 的中断里做软件 PWM**（100 µs 分辨率，
PWM 频率取 100~200 Hz、8~16 级占空比），既不动 Timer1、也不影响红外解码。报告的"定时资源"一节要补这段。

### 3.6 ⚠️ 避障只有一句话，没有策略、也没有测距手段

- 表 2 写"前方红外反射检测障碍，遇障转向绕行" —— 但"绕行"需要回答：转多少度？转多久？绕过后怎么回到原方向？失位了怎么办？
- 而且**红外反射只能给"有/无"**，没有距离，无法判断"要不要绕、绕多远"。

**结论**：若采纳 3.1 的出路 A（超声波），避障就能有距离门限，策略可以写实（远了走、近了停/退、贴太近则转向）；
纯红外只能做"碰到就转，转完接着走"，属"试探式"，报告应如实这么写。

### 3.7 一位数码管承载不了"档位 + 模式 + 录制状态"

报告要求数码管显示：档位 0~9（表 2）+ 当前模式（表 2 末行）+ 录制/回放提示。
**1 位数码管只有一个字符位**，这几种信息必须定义显示策略，报告里没有。建议：

| 场景 | 显示 |
|---|---|
| 手动模式 | 档位数字 `0`~`9` |
| 循迹/避障/寻光模式 | 字母/符号（如 `t` / `A` / `L`，或固定数字 `1/2/3`） |
| 录制中 | 闪烁的 `r`（或录制条数，每存一条闪一下） |
| 回放中 | 闪烁的 `P`（或当前动作序号） |
| 错误 | `E` + 蜂鸣器音型区分（满/空记录/中断） |

### 3.8 ⚠️ 存储落位与字节序没定义

- 报告只说"240 B 缓冲区""按动作码、低字节、高字节连续存放"，但没说
  **放片内 128 B 直接寻址区？IDATA？还是片内扩展 RAM（`MOVX`）** —— 这决定代码怎么写；
- 也没写**帧结构**（有没有包头/记录条数/结束标记），回放靠什么判断"动作结束"。
- 实测提醒：STC89C52RC 的 512 B = 256 标准 + 256 片内扩展（`MOVX` 访问）。
  **别用 `MOVX @Ri`** —— 它拿 `P2` 当高 8 位地址，而 `P2` 整口是数码管段选，一访问就把显示打花；用 `DPTR`。

### 3.9 ⚠️ 回放中遇到障碍不处理（安全隐患）

报告把"回放中叠加避障与超时保护"放进第 7 章"后续改进"。但**回放的车是真的会跑的**，
演示时前方有墙而它照直撞过去，是现场事故。建议把"**回放中前方检测到障碍 → 立即中断回放并停车**"
提为**本期必须**（若已装超声波，这条几乎不增加成本）。

### 3.10 ⚠️ 断电即失

240 B 在 RAM，掉电清空。报告把 24C02 列为"可选"。**演示前一断电，示教就白录了。**
顺带一个发现：追线显示 **`P1.4`/`P1.5` 接一个 2 脚接插件、各带 4.7 K 上拉** —— 这个电气形态**很像 I²C**，
很可能就是给 24C02 留的口（`P1.4`=SDA / `P1.5`=SCL）。要做掉电保存，就是这两个脚，**但需要先实测确认**。

## 四、报告完整性：缺什么

| 缺的东西 | 为什么必须补 |
|---|---|
| **MCU 引脚分配表**（40 脚逐一：端口 / DIP40 脚号 / 功能 / 电平） | 这是这类课程报告的**标准必备节**，答辩必问"引脚怎么分配的"；而报告正文里出现的引脚恰好全是错的。我这边已经有实测表（`docs\引脚表_原理图追线.md`），可直接整理成附录 |
| **资源预算表**（Flash / RAM / 定时器 / 中断 / 代码体积） | 报告说"资源受限条件下实现"，却没有任何占用数字。我这边有实测账单：`remote.asm` 1147 B、正式固件预算 713~938 B、RAM 用量 ~25 B（`docs\代码体积预算.md`） |
| **器件表与实物不一致** | 实物上装了**超声波 HC-SR04**（`P1.2/P1.3`，已上机），报告器件表里没有；反过来报告点名的 `V7/V4` 与在用的探头对不上号 |
| **可测量的验收标准** | "课程允许范围内"这类措辞无法自测。改成百分比/次数/门限（见 3.4） |
| **三份文档口径统一** | 方案设计报告 / 课题报告 / 局部功能电路图分析三份文档对同一硬件给出不同说法（`P3.2` vs `P3.3`、`P0` vs `P2`、`S3` 复位 vs 按键），交上去会互相打脸 |
| 时间基准的精度说明 | 晶振 **11.0592 MHz**（不是 12 MHz），10 ms 节拍 = 100 × 99.8 µs ≈ 9.98 ms，报告可写明这个误差量级 |

## 六、一句话总结

**做的东西是对的，写的东西和板子对不上，个别前提没落地。**
把"引脚/位号/供电"这三类描述换成实测口径、把"循迹与避障共用探头"和"寻光两路未确认"这两个前提解决掉，
方案的骨架是能撑住课程验收和"动作录制回放"这个创新点的。

| 项 | 为什么好 |
|---|---|
| **语义化录制**（只存"动作码+时长"，不存红外波形） | 这是真正的创新点，而且理由写得对：波形与遥控协议绑定、数据量大；机器人要复现的是"怎么动了多久"。换遥控器/加蓝牙后上层复用 —— 这个论证站得住 |
| **3 B/单元、240 B、80 条** | 编码紧凑，且我实测过 STC89C52RC 有 512 B RAM，**装得下**（`docs\代码体积预算.md`）；240 B 不占 2 KB 代码额度 |
| **相邻同类动作合并** | 省存储的关键，正确 |
| **统一 `Motor_Set(action)` 出口** | 手动与回放共用，改电机方向只改映射表 —— 解耦正确，且现有 `remote.asm` 的 `MOTOR_SET_ACT` 已是它的原型 |
| **安全机制成体系** | 停止键最高优先 / 回放任意键中断 / 空记录拒绝 / 满则封存提示 / 上电先关使能 —— 这一组是报告里最像工程的部分 |
| **不动机器硬件、复用套件** | 符合课程"复用原套件"的要求，风险最小 |

## 二、硬件事实层：9 处与实测不符（报告必须改口径）

完整对照表见 `docs\固件审计_Step1.md` 第 6.1 节，这里只列最会被追问的：

| 报告写的 | 实测是 | 后果 |
|---|---|---|
| 0038 输出 → `P3.2`(INT0)，**用外部中断解码** | `P3.3`(INT1)；`P3.2` 是按键 S4；**全工程没有任何程序用外部中断** | 报告的核心时序图错了；答辩问"你怎么解码的"会答不下去 |
| 数码管段码由 **`P0`** 输出 | **`P2.7`~`P2.1`**（顺序还反着），`P0.6`=蜂鸣器、`P0.0~P0.5`=电机 | 引脚分配整块错 |
| 电机方向 **`P2.x`**、EN=PWM | 方向+使能 = **`P0.0`~`P0.5`** | 同上 |
| 蜂鸣器 **`P1.x`** | **`P0.6`** | 同上 |
| 循迹/避障/寻光信号"经 LM393 整形后送 `P1`/`P2`" | 循迹/避障探头实测在 **`P3.5`/`P3.6`**，且这两个脚上的网**够不到 IC5**（没有比较器整形，是分压节点直接进 MCU） | 与报告"W1/W2 调灵敏度"的说法冲突 |
| 避障 = 红外对管 **V7/V4** + `IC3` | 实测在用的是接 `P3.5`/`P3.6` 的那两个探头 + 你加的**超声波**；`V7/V4`+`IC5` 的输出**没追到 MCU 任何脚** | 报告点名的位号与在用的探头**对不上号** |
| `S3` = **复位键**（电路分析报告第 2 章） | `S3` = **`P3.4` 用户按键**（上拉+按下为低），已跑通 | 两份报告互相矛盾且都与实物不符 |
| "10 ms 统一节拍" | 实际 Timer0 是 **100 µs tick**（方式 2 自动重装）；**Timer1 被串口 9600 占着** | 报告没提 Timer1 的占用，资源规划不完整 |
| 逻辑电源"经**稳压/分压**" | 元器件清单与图纸里**没有 7805/AMS1117 之类**，而 MCU 的 VCC(40) 追线确认**直接接电池轨 `VCCBAT`** | ⚠️ **实车风险**：4 节新碱性电池空载 6.0~6.4 V > STC89C52RC 的 5.5 V 上限 |

> 最后一条不只是"报告写错"，是**可能烧板子**的问题。答辩前务必确认：要么板上真有个没被识别的降压件，要么报告这句删掉、并改用镍氢电池/串二极管。

## 三、方案层面的问题（真正影响"能不能做出来、能不能验收"）

### 3.1 ❗ 循迹与避障共用同一对红外探头 —— "综合模式"在物理上不成立

- 报告表 1/表 2 把"循迹、避障"都归到同一组红外对管（V7/V4，或实测在用的那两个）；
- 而实际硬件上，**同一对反射式探头不能同时朝下（看地面黑线）又朝前（看障碍物）** —— 装法互斥；
- 但报告的功能清单里写着"**循迹、避障、寻光可切换模式综合运行**"，验收也要求综合模式。

**结论**：这一条是方案里最大的逻辑漏洞。两条出路，二选一并在报告里写死：

| 出路 | 做法 | 代价 |
|---|---|---|
| **A（推荐）** | 避障改用你**已经上机跑通**的超声波 HC-SR04（`P1.2`/`P1.3`），循迹保留朝下的红外探头 → 两者物理独立，综合模式才成立 | 报告里要补超声波模块（现在**器件表里根本没有它**） |
| B | 明确写成"循迹与避障共用同一组探头，靠**改变安装朝向**切换，属分时使用，不是同时运行" | 综合模式降级为"模式切换"，不能说"综合运行" |

### 3.2 ❗ 寻光只有一路且未闭环

- "向光照较强一侧转向"需要**左右两路**比较；而追线只闭合了 **`P1.1` ← 光敏比较器 IC3 的 `OUTA`**，
  `IC3` 的 `OUTB` **去向没追到 MCU**，`P1.6` 通过网标号连到传感底板接插件但**用途未定**；
- 而且 `P1.1` 这一路**从未上机验证过**（现有程序里没有任何一行读光敏）。

**结论**：报告把寻光当"已具备的硬件能力"来写，实际上**两路都不确定**。开工前必须实测（见 `docs\固件审计_Step1.md` 阶段 0.1）。

### 3.3 ❗ 录制的触发前提依赖"NEC 重复码"，而这只遥控器可能不发

- 报告 3.3 写"若超过规定时间未收到方向键**重复码**，程序将当前动作切换为停止" —— 它把"按住键会发重复码"当作既定前提；
- 但本工程自己的文档里已经记着一条实测提示：**"如果按住键时小车一颠一颠的，说明这只遥控器不发 NEC 重复码"**
  （`firmware\remote\remote.asm` 顶部注释，`HOLD_MODE` 就是为这个情况准备的两套模式）。

**结论**：录制"前进 2 秒"到底靠什么判定（重复码？松键超时？还是按一下开始/再按一下结束）——
报告必须**先写清这个前提，并给出两种遥控器都能用的判定方式**，否则录出来的时长是随机的。

### 3.4 ⚠️ 纯开环回放 vs 验收标准"终点偏差在课程允许范围内"

- 方案是**纯时间开环**：按 10 ms 节拍重放动作，没有编码器、没有测速反馈；
- 而表 5 的验收标准写"运动方向与示教顺序一致；**终点偏差保持在课程允许范围内**"。

**结论**：电池电压下降、地面摩擦、轮胎打滑会让同一段程序每次跑的距离都不同，**开环下这个标准基本靠运气**。
建议把验收标准改成可测量、且方案能保证的形式，例如：

> "动作**顺序**与示教一致；各动作**持续时间误差 ≤ ±5%**（用数码管/串口打印实测）；
> 终点重复性以**同一电量下连续 3 次回放的落点散布**衡量，不承诺绝对位置精度。"

（报告第 7 章其实已经把"编码器/闭环纠偏"列为后续改进 —— 那验收标准就应该同步降级，两处不能自相矛盾。）

### 3.5 ⚠️ PWM 调速：电气约束和时间资源都没做预算

- 报告说"改变 L293D EN 端 PWM 占空比"调速，但**没提**：EN 接在 **P0** 口，而 P0 是**开漏**、靠 10 K 排阻上拉 —— 上升沿偏慢，
  PWM 频率不能随意提高（这也是现有 `remote.asm`/`usfollow.asm` 都明确写"本程序只做低速开关，不做 PWM"的原因）；
- 报告的 Timer 规划里：Timer0 要管 10 ms 节拍，**Timer1 已被串口 9600 波特率占用**（调试期必需），
  红外解码又声明用外部中断 —— 那么 PWM 由谁产生？**报告没回答**。

**结论**：PWM 的可行方案我建议写清：**在 Timer0 的中断里做软件 PWM**（100 µs 分辨率，
PWM 频率取 100~200 Hz、8~16 级占空比），既不动 Timer1、也不影响红外解码。报告的"定时资源"一节要补这段。

### 3.6 ⚠️ 避障只有一句话，没有策略、也没有测距手段

- 表 2 写"前方红外反射检测障碍，遇障转向绕行" —— 但"绕行"需要回答：转多少度？转多久？绕过后怎么回到原方向？失位了怎么办？
- 而且**红外反射只能给"有/无"**，没有距离，无法判断"要不要绕、绕多远"。

**结论**：若采纳 3.1 的出路 A（超声波），避障就能有距离门限，策略可以写实（远了走、近了停/退、贴太近则转向）；
纯红外只能做"碰到就转，转完接着走"，属"试探式"，报告应如实这么写。

### 3.7 一位数码管承载不了"档位 + 模式 + 录制状态"

报告要求数码管显示：档位 0~9（表 2）+ 当前模式（表 2 末行）+ 录制/回放提示。
**1 位数码管只有一个字符位**，这几种信息必须定义显示策略，报告里没有。建议：

| 场景 | 显示 |
|---|---|
| 手动模式 | 档位数字 `0`~`9` |
| 循迹/避障/寻光模式 | 字母/符号（如 `t` / `A` / `L`，或固定数字 `1/2/3`） |
| 录制中 | 闪烁的 `r`（或录制条数，每存一条闪一下） |
| 回放中 | 闪烁的 `P`（或当前动作序号） |
| 错误 | `E` + 蜂鸣器音型区分（满/空记录/中断） |

### 3.8 ⚠️ 存储落位与字节序没定义

- 报告只说"240 B 缓冲区""按动作码、低字节、高字节连续存放"，但没说
  **放片内 128 B 直接寻址区？IDATA？还是片内扩展 RAM（`MOVX`）** —— 这决定代码怎么写；
- 也没写**帧结构**（有没有包头/记录条数/结束标记），回放靠什么判断"动作结束"。
- 实测提醒：STC89C52RC 的 512 B = 256 标准 + 256 片内扩展（`MOVX` 访问）。
  **别用 `MOVX @Ri`** —— 它拿 `P2` 当高 8 位地址，而 `P2` 整口是数码管段选，一访问就把显示打花；用 `DPTR`。

### 3.9 ⚠️ 回放中遇到障碍不处理（安全隐患）

报告把"回放中叠加避障与超时保护"放进第 7 章"后续改进"。但**回放的车是真的会跑的**，
演示时前方有墙而它照直撞过去，是现场事故。建议把"**回放中前方检测到障碍 → 立即中断回放并停车**"
提为**本期必须**（若已装超声波，这条几乎不增加成本）。

### 3.10 ⚠️ 断电即失

240 B 在 RAM，掉电清空。报告把 24C02 列为"可选"。**演示前一断电，示教就白录了。**
顺带一个发现：追线显示 **`P1.4`/`P1.5` 接一个 2 脚接插件、各带 4.7 K 上拉** —— 这个电气形态**很像 I²C**，
很可能就是给 24C02 留的口（`P1.4`=SDA / `P1.5`=SCL）。要做掉电保存，就是这两个脚，**但需要先实测确认**。

## 四、报告完整性：缺什么

| 缺的东西 | 为什么必须补 |
|---|---|
| **MCU 引脚分配表**（40 脚逐一：端口 / DIP40 脚号 / 功能 / 电平） | 这是这类课程报告的**标准必备节**，答辩必问"引脚怎么分配的"；而报告正文里出现的引脚恰好全是错的。我这边已经有实测表（`docs\引脚表_原理图追线.md`），可直接整理成附录 |
| **资源预算表**（Flash / RAM / 定时器 / 中断 / 代码体积） | 报告说"资源受限条件下实现"，却没有任何占用数字。我这边有实测账单：`remote.asm` 1147 B、正式固件预算 713~938 B、RAM 用量 ~25 B（`docs\代码体积预算.md`） |
| **器件表与实物不一致** | 实物上装了**超声波 HC-SR04**（`P1.2/P1.3`，已上机），报告器件表里没有；反过来报告点名的 `V7/V4` 与在用的探头对不上号 |
| **可测量的验收标准** | "课程允许范围内"这类措辞无法自测。改成百分比/次数/门限（见 3.4） |
| **三份文档口径统一** | 方案设计报告 / 课题报告 / 局部功能电路图分析三份文档对同一硬件给出不同说法（`P3.2` vs `P3.3`、`P0` vs `P2`、`S3` 复位 vs 按键），交上去会互相打脸 |
| 时间基准的精度说明 | 晶振 **11.0592 MHz**（不是 12 MHz），10 ms 节拍 = 100 × 99.8 µs ≈ 9.98 ms，报告可写明这个误差量级 |

## 六、一句话总结

**做的东西是对的，写的东西和板子对不上，个别前提没落地。**
把"引脚/位号/供电"这三类描述换成实测口径、把"循迹与避障共用探头"和"寻光两路未确认"这两个前提解决掉，
方案的骨架是能撑住课程验收和"动作录制回放"这个创新点的。
