# 一、三件日常操作

## 1.1 编译

```powershell
cd D:\工程实践_迁移

# 正式固件
powershell -NoProfile -ExecutionPolicy Bypass -File firmware\car\build.ps1

# 诊断/工具程序（-Name 换文件名）
powershell -NoProfile -ExecutionPolicy Bypass -File firmware\diag\build.ps1 -Name lightscan
powershell -NoProfile -ExecutionPolicy Bypass -File firmware\remote\build.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File firmware\selftest\build.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File firmware\modtest\build.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File firmware\probe\build.ps1 -Name probe2
```

- 工具链自动探测（当前命中 **`D:\keli\C51\BIN`**：`A51.EXE` → `BL51.EXE` → `OH51.EXE`），路径列表写在 `build.ps1` 顶部。
- **不需要打开 µVision**；命令行走完整条链。
- 每次编译都看这一行：`Program Size: data=8.0 xdata=0 code=NNN`
  → **`code=` 就是代码体积**，Eval 版上限 **2048**（超了直接链接失败）。
- 产物：`.hex`（烧录用）、`.obj/.abs`、`.lst`（清单）、`.m51`（映射）、`.build.log`（日志）。
- ⚠️ **改 `build.ps1` 必须保持纯 ASCII**：Windows PowerShell 把无 BOM 的 UTF-8 当 GBK 读，中文注释会报语法错。

## 1.3 看串口（本项目的"示波器"）

**硬件链路**：`P3.1(TXD)` → CH340 → USB → **COM7**，固定 **9600 bit/s、8 位、无校验、1 位停止（8N1）、无流控**。

### 三种看法

| 方式 | 怎么做 | 适合 |
|---|---|---|
| **① 脚本读（推荐）** | `powershell -NoProfile -ExecutionPolicy Bypass -File tools\read_com.ps1 -Port COM7 -Seconds 15` | 想把日志留档 / 发给别人看 |
| ② 任意串口助手 | 打开 COM7 @9600 8N1 | 想实时盯着看 |
| ③ **不看串口** | 数码管 + D3 灯 + 蜂鸣器 | 手边没电脑，或程序本来就是给你"盲读"设计的 |

**方式①的日志落点**：`firmware\_serial_read.log`（脚本自己定死在那个位置，见 `tools\read_com.ps1` 第 25 行）。
所以"日志给我看"= 你跑一次脚本，我去读文件，**你不需要会看串口**。

### 为什么读不到 —— 按这个表排查

| 现象 | 原因 | 对策 |
|---|---|---|
| `FAILED to open COM7` | **STC-ISP 还开着**，它占着串口 | 先关掉 STC-ISP 再跑脚本 |
| 打开了但一个字都没有 | 程序那段打印**已经过去了**（只在上电后几秒内打印） | **先开脚本，再拨 S1 关→开**让程序重跑一遍（`ramtest` v2.1 起会一直重复打印，没这个限制） |
| 全是乱码 | 波特率/校验位不对 | 确认 **9600 8N1 无流控**（本项目程序固定 9600：`TH1=0FDH`、`SMOD=0`） |
| 出现一堆 STC-ISP 的握手文字 | 那是下载工具的，不是程序输出 | 正常，重新冷启动后再读 |
| `COM7` 不见了 | 拔了 USB（跑车时本来就该拔） | 插回 USB；**COM3~6 是蓝牙虚拟口，别选** |
| 行是断的、不完整 | 打印途中被复位/断电 | 正常，重跑一次 |

### 串口在什么时候是"被占用"的

同一时刻只能有一个程序打开 COM7：

- **STC-ISP**（下载时）—— 占用；
- `tools\read_com.ps1` 或串口助手 —— 占用；
- 两者会互相抢，**先关下载器再看串口**。

# 三、每个程序的"串口输出契约"

贴日志给我时按这张表对照，一眼就能看出是哪个程序、读到哪一步。

| 程序（hex） | 开机横幅 / 输出样式 | 怎么读 |
|---|---|---|
| `firmware\car\car_asm.hex` | `=== SMART CAR MAIN FIRMWARE (block 1: motor + gear) ===`<br>`gear N  duty=XX%` | 每次变档打一行：档位 + 实际占空比 |
| `remote\remote.hex` | `=== IR REMOTE CAR v1 ... ===`<br>`K=46 FWD` / `! IR frame rejected, lead lo=5A hi=2D` | 每收到一个新键打一行；**被拒帧会打实测脉宽**（NEC 应为 `lo≈5A`、`hi≈2D`，单位 100 µs）。**测遥控器键值就用它** |
| `selftest\selftest.hex` | `=== SELFTEST v1  STC89C52 @11.0592MHz  UART 9600 8N1 ===` | 全件自检的分段输出 |
| `modtest\modtest.asm` | `=== MODTEST v1  obstacle probe + IR remote ... ===`<br>`P1.3=0` / `HB FF FF 7F BF` | 扫 P1/P2/P3 找哪个脚在翻转。⚠️ 它的红外守的是**错脚 P3.2**（真脚是 P3.3） |
| `diag\usfollow.hex` | `=== ULTRASONIC FOLLOW CAR v1 ... ===`<br>`D=xxcm T=ticks` | 超声波距离与回波 tick |
| `diag\usfollow2.hex` | `=== ... v2 ... ===` `line: D=cm T=ticks A=action` | 同上 + 当前动作 |
| `diag\uscheck.hex` | `=== ULTRASONIC WIRING CHECK ===` | 超声波**接线**判定（结果同时显示在数码管：`1` 正确 / `2` 接反 / `0` 没模块 / `9` 异常） |
| `diag\lightscan.hex` | `=== LIGHT SENSOR PIN SCAN (lightscan) ===`<br>`-> pin id N = L`<br>`levels 1..9 = 110110011` | **寻光脚位**：脚号 1..9 对应 `P1.0 P1.1 P1.4 P1.5 P1.6 P1.7 P3.7 P3.5 P3.6`；`->` 行 = 哪只脚变了、变成什么电平；`levels` 行 = 9 只脚当前电平快照 |
| `diag\tracktest.hex` | `=== TRACK / AVOID PROBE TEST (tracktest) ===`<br>`L=0 R=1 C=1  -> digit 1` | **循迹极性**：`L=P3.5`、`R=P3.6`、`C=P3.7`；脚后面的 `*` = 采样期间抖动；`digit` = `L+2R+4C`（某位为 1 = 那只脚低） |
| `diag\ramtest.hex` | `=== ON-CHIP EXTENDED RAM TEST (ramtest v2) ===`<br>`[1] IDATA 0x80-0xFF : errors = 00`<br>`[2] XRAM  0x0000-0x00FF : errors = 00`<br>`first bad addr = 0xHHHH  read = 0xHH`<br>`verdict: 7seg=8 ...`<br>`[hold] IDATA err=00  XRAM err=00`（每 0.5 s 一行） | 缓冲放哪的判据：`8` 通过 / `7` 要 `AUXR=0` / `E` 不行 / `F` 更糟 |
| `diag\motorspeed.hex` | `=== MOTOR SPEED / DIFFERENTIAL TEST (motorspeed) ===`<br>`step N  duty L/R = XX/XX%` | 九步自动循环（档位 + 差速转弯）。**块① 已覆盖它，可不烧** |
| `diag\irprobe.hex` | `=== IR ACTIVITY PROBE ... ===`<br>`IR activity #N` | **"遥控器活不活"专用**：不依赖串口、不依赖协议，只要 `P3.3` 上有电平活动就计数。**数码管计数 +1、D3 亮、松手后"嘀"一声** → 数字在涨 = 遥控器+接收头+接线都是好的 |
| `probe\probe2.hex` | 无串口（看轮子/蜂鸣器动作） | 每脚"抽 i 下" |

## 4.2 `P0` 输出图案（动作 → 图案，已实测）

`b0..b3 = IN1..IN4`，`b4 = ENA`，`b5 = ENB`，`b6 = 蜂鸣器(1=静音)`，`b7 = 1`

| 动作 | P0 图案 | 方向位（低 4 位） | 说明 |
|---|---|---|---|
| 停止 | `0C0H` | `00H` | `ENA`/`ENB` 一起拉低 = 电机断电（滑行） |
| 前进 | `0F5H` | `05H` | IN1 + IN3（两轮同向） |
| 后退 | `0FAH` | `0AH` | IN2 + IN4 |
| 左转 | `0F6H` | `06H` | IN2 + IN3（原地左转） |
| 右转 | `0F9H` | `09H` | IN1 + IN4（原地右转） |

> `P0` 是**开漏口**：写 1 只是"放开"，高电平靠板上 **10K 排阻**上拉 → 上升沿偏慢，
> 适合低速开关与**低频** PWM（本项目用 500 Hz），不适合高频 PWM。

## 4.3 三个极性结论（阶段 0 实测，2026-09-18）

| 传感器 | 条件 | 电平 |
|---|---|---|
| 寻光 `P1.1`(左) / `P1.0`(右) | **见光** | **低（0）** |
| | **遮住** | **高（1）** |
| 循迹 `P3.5`/`P3.6` | **白底（有反射）** | **低（0）**，且**电平稳定**（无抖动） |
| | **黑线（无反射）** | **高（1）** |
| 遥控键值（`cmd` 字节） | 前进 `46H` / 后退 `15H` / 左转 `44H` / 右转 `43H` / 暂停 `40H` | 其余键值待补（用 `remote.hex` 测） |

> ⚠️ **最容易踩的坑**：`config.h` 里那个名字叫 `TRACK_ACTIVE_LOW`（"低 = 触发"），
> 但**循迹时"压黑线"读到的是 `1`（高）**——"低"指的是"**看到白底**"。
> 写循迹判断请用 `if (TRACK_L == 1)` 表示"左侧压线"。

# 五、资源占用（开发时要记住的预算）

## 5.1 定时器与中断

| 资源 | 配置 | 用途 |
|---|---|---|
| **Timer0** | **方式 2**（8 位自动重装），`TH0=TL0=`**164** → 92 机器周期 ≈ **99.8 µs** | 100 µs 硬件时基中断：① 10 ms 节拍（计满 100 次）② 红外脉宽测量 ③ 软件 PWM ④ 松键/超时判定 |
| **Timer1** | **方式 2**，`TH1=TL1=`**0FDH**，`SMOD=0` | 串口 **9600** 波特率发生器（调试用）。**不可再作他用** |
| 外部中断 INT0/INT1 | **未使用** | 红外解码是**轮询**实现的（不用中断，已验证可行） |
| 串口 | 方式 1，`SCON=50H` | 调试输出；`P3.1` 同时是 ISP 下载口 |

- 晶振 **11.0592 MHz**（不是 12 MHz）→ 机器周期 **1.0851 µs**；10 ms 节拍实际是 **9.98 ms**（−0.2%）。
- 软件 PWM：`PWMC` 0..19 与 `DUTY_A/B` 比较 → **20 tick = 2 ms = 500 Hz**，占空比 5% 一档。
- ★ **`TMOD` 是共用寄存器**：`22H` = T1 方式 2 + T0 方式 2（同时用串口和 100 µs 时基就写这个）。

## 5.2 存储

| 区域 | 容量 | 用途 |
|---|---:|---|
| Flash（代码） | 8 KB | 程序 |
| **代码体积上限** | **2048 B**（Eval 版限制，**只算 code 不算 data**） | 每次编译看 `code=` |
| 直接寻址 RAM `DATA` | 128 B（用户区 `30H`~`7F` = 80 B） | 运行变量（本项目用 8~25 B） |
| 间接寻址 RAM `IDATA` | 128 B | 备用 |
| **片内扩展 RAM（`MOVX`）** | **256 B —— 实测可读写** | **240 B 动作缓冲区放这里** |

> ⚠️ 访问扩展 RAM **只能用 `MOVX @DPTR`**。`MOVX @Ri` 会拿 **`P2`** 当高 8 位地址，
> 而 `P2` 整口是数码管段选，一用就把显示打花（已实测确认 `@DPTR` 不影响 `P2`）。

|---|---|---|
| 供电轨 | `VCCBAT`（电池）与 `USB5V` 两条**独立**轨 | 引脚表 §1.6 |
| **板上没有稳压件** | 元件清单里搜不到 7805/AMS1117 等；**MCU 的 `VCC`(40) 直接接电池轨** | 引脚表 §1.6 |
| ⚠️ 超压风险 | 4 节**新碱性**电池空载 **6.0~6.4 V** > STC89C52RC 的 **5.5 V** 上限 | 同上 |
| 稳妥做法 | 用 **4 节镍氢 1.2 V（4.8 V）**，或串一只二极管降 0.7 V | 同上 |
| ~~**USB 与电池不要同时接**~~ | ❌ **2026-09-20 作废**：用户实测同时接也能正常冷启动下载。"两条轨互灌"从未被独立验证过 | 待办与风险 B1 更正块 |
| `S1` 的拓扑 | **在 USB 这一路**；电池那条轨绕过它（或并联） | 待办与风险 B1（三次实测对比） |
| 电机电源 `VS` | 来自电池轨 → **没上电池时电机不会转**（逻辑电路仍可由 USB 供电工作） | 据此可"只插 USB 测逻辑、装电池测电机" |

# 七、踩过的坑（现象 → 原因 → 对策）

| # | 现象 | 原因 | 对策 |
|---|---|---|---|
| 1 | 红外收不到 / 守错脚 | 0038 接的是 **`P3.3`(INT1)**，`P3.2` 是按键 S4 | 代码守 `P3.3`；`modtest.asm` 里守还是错脚，别照抄 |
| 2 | 数码管整片错位一位 | 段序是**反的**：a=P2.7 … g=P2.1，且 `P2.0` 是 D3 灯不是段选 | 段码表按 `bit7..bit1 = a..g`、`bit0 = D3(1=灭)` 写 |
| 3 | 电机不转 / 转了但方向不对 | 电机在 **`P0`** 不是 `P1`；`ENA`/`ENB` 由 MCU 驱动（不是跳 VCC） | 用 4.2 的图案；左右轮对应关系错就换 `LEFT_REVERSE`/`RIGHT_REVERSE` |
| 4 | 蜂鸣器不响或只"哒"一声 | 它是**无源**的，必须给**方波**；PNP 驱动**低电平发声** | 用中断产生方波（本项目：每 5 tick 翻一次 ≈ 1 kHz） |
| 5 | 一开 PWM 电机就乱抽 / 方向乱 | 主循环与中断**同时写 `P0`** 互相踩 | ★ 约定：**主循环永不写 `P0`**，只改 `DIRBITS`/`DUTY_A/B`，`P0` 由中断组装 |
| 6 | 一访问缓冲区数码管就花 | 用了 `MOVX @Ri`（拿 `P2` 当高 8 位地址） | 用 **`MOVX @DPTR`** |
| 7 | 汇编报 `TARGET OUT OF RANGE` | `SJMP`/条件跳转只有 **−128..+127** | 长跳用 `LJMP`（我在 `lightscan` 上踩过一次） |
| 8 | 读 `.lst` / `.build.log` 全是乱码或带空格 | 这两个文件是**混合编码**（UTF-16 的工具输出 + UTF-8 的脚本标题） | 用 `grep` 工具读，或按字节解码后 `-replace "`0",''` |
| 9 | `.ps1` 里写中文就报语法错 | PowerShell 把无 BOM 的 UTF-8 当 GBK 读 | **`.ps1` 保持纯 ASCII**（`.md`/`.asm` 不受影响） |
| 10 | 链接报 `RESTRICTED VERSION WITH 0800H BYTE CODE SIZE LIMIT` | Keil **Eval 版限 2048 B 目标码**（只算 code） | 关调试打印；真超了换 ASEM-51/SDCC（免费无限制） |
| 11 | 下载总是失败 | ~~电池和 USB 同时接着 → 断 `S1` 也断不了电~~ ⚠️ **2026-09-20 这条原因已被推翻**（同时接也能下载）。真遇到下载失败，先按"冷启动时机不对 / `P3.0`·`P3.1` 虚焊 / 晶振 / 型号串口选错"排查 | 拨 `S1` 关→数 1~2 秒→开，多试几次；确认型号 `STC89C52RC`、串口 `COM7` |
| 12 | 串口打不开 / 读不到 | STC-ISP 占着串口；或程序那段打印已经过去 | 关 STC-ISP；先开脚本再拨 `S1` 重启 |
| 13 | 选了 COM3~6 连不上 | 那几个是**蓝牙虚拟串口** | 只选 **COM7** |
| 14 | 超声波模块插上去不工作甚至发热 | 板上插座线序 `1=GND 2=Echo 3=Trig 4=VCC` 与 **HC-SR04 模块自身脚序正好相反** | **按板上丝印一根一根接**，不能直插 |
| 15 | 按报告"经 LM393 整形"写循迹，结果读到的是模拟节点 | `P3.5`/`P3.6` 的网**够不到 IC5 比较器**，是分压直接节点 | 按实测写（极性见 4.3；实测电平**稳定**，不需要额外整形） |
| 16 | 图纸说某个脚"未使用"，实际有功能 | `P1.0` 图纸判"无连线"，**实测是寻光第二路** | 图纸 ≠ 实物；**"没找到"不等于"证明没有"**，以实测为准 |
