# Token 消耗评估 —— 工程实践_迁移

> **数据源**：DSH 逐请求账本 `~/.dsh/storages/session_projcache/sessions/<sid>.json` 的
> `record.rows.contextTimeline.val.requests[]`（**1 个元素 = 1 次 LLM 请求 = 1 个 step**），
> 辅以 `contextActivity.days`（按天）、`turnOutline.turns[]`（轮）与
> `~/.dsh/storages/usage-stats-cache.json`（官方定价与真实计费采样）。
>
> **统计范围**：工作区 `D:\工程实践_迁移`（`workspace.json` 中 `7d4397f4-…`）的 23 个会话；
> 时间为 UTC+8。生成脚本 `tools/token_steps.py`，原始数据 `tools/token_steps.json`。

## 0. 口径（不看会误读数字）

- **step（步）= 一次模型请求**。一轮（turn，你发一次话）里模型要「请求→调工具→再请求」很多次，
  所以 514 轮对应 **5,544 步**，平均一轮 10.8 步。
- **`prompt`（输入）是该次请求携带的全部上下文**：系统提示 + 28 个工具定义（实测 7,559 tokens）
  + 全部历史消息。同一段上下文会被反复重发，所以**输入总量随步数被成倍放大**。
- **`cacheRead`** = 其中命中前缀缓存的部分，单价约为未命中输入的 1/30。
- **`uncached` = prompt − cacheRead`**，按全价计费的**真实新增输入**。
- **`output`** = 模型生成量，含思考链与工具调用参数。
- 下表「输入合计」是**按请求累加**的服务端输入量，**不等于「读了多少不重复的字」**。

## 4. 每个步骤花了多少 —— 分布

单步（1 次请求）的输入量分布（n=5,544 步）：

| 分位 | 单步输入 tokens | 说明 |
|---|---|---|
| P10 最轻 | 72,022 | 会话 `de7eca3a` 第 2 轮第 11 步 |
| P25 | 170,095 | 会话 `546c3655` 第 30 轮第 5 步 |
| P50 中位 | 336,662 | 会话 `546c3655` 第 7 轮第 1 步 |
| P75 | 531,779 | 会话 `8d5efa7e` 第 22 轮第 10 步 |
| P90 | 662,183 | 会话 `27310e4c` 第 29 轮第 3 步 |
| P99 最重 | 776,485 | 会话 `39c402ce` 第 52 轮第 1 步 |

**关键结论：单步成本几乎完全由「这轮对话已经多长了」决定，而不是这一步干了什么。**

- 单步 **中位 336,662 tokens**、**P99 776,485 tokens**：单步成本呈「长会话地板抬高」而不是尖峰。
- 最直观的例子：`27310e4c` 第 37 轮从第 14 步到第 19 步，连续 6 次请求的输入都是 **78.9 万~79.2 万 tokens**——那是在**轮询/等待**，每轮询一次就为整段历史付一次全价。
- 因此「哪一步贵」几乎不取决于这一步在干什么，只取决于**它排在一段多长的上下文后面**。
- 单步**新增**上下文（本步 `prompt` 相对上一步的增量）平均仅 **1,007 tokens**，也就是说：**每步真正新增的信息量约 1k，但每步都要把整段上下文重发一遍**。

## 7. 为什么这么贵（三个放大器）

1. **固定底盘大**：系统提示 + 28 个工具定义约 **9.3k tokens**（其中工具定义实测 **7,559**，
   其中 `workflow` 一项 1001、`subagent_fork` 377、`pwsh` 1109）。**每一次请求都要重付这份底盘。**
2. **长会话重发**：一亿 tokens 级的会话（`39c402ce` 863 步）平均每步上下文 **443k tokens**。
   上下文一直不压缩，尾部的每一步都在为前面所有工作付费。
3. **工具输出直接进上下文**：`pwsh`/`read`/`grep` 的原始输出没有自动摘要。
   glob 全项目扫描、整份读 116 KB 的 `main.c`、读 29 KB 的 README —— 这些在 AGENTS.md 里
   已被明令禁止，属于**可省而未省**的部分。

## 8. 可操作的省钱项（按收益排序）

| 措施 | 预期收益 |
|---|---|
| 长会话到 200~300 步就 `/compact` 或开新会话，别一路跑到 800+ 步 | 最大项。尾部长尾的每步成本 ∝ 全长 |
| 严守 AGENTS.md 的搜索纪律：`glob` 只带 `firmware/` 前缀，不整份读 `main.c`/`README.md` | 减少单步上下文激增（P99 那类 790k 步骤）|
| 把「一次性大输出」改成 `pwsh` 里先过滤/截断再回传 | 工具输出是上下文增长主来源 |
| fork 会话要克制：`7fc2ee62`/`39c402ce` 这类同前缀双跑会整份重付 | 本次至少 2 份重复账 |
| 轮询/等待型空转：`27310e4c` 第 37 轮 6 步共约 474 万 tokens，只产出 3k 输出 | 等一次 ≈ 付一次全上下文全价 |
| 高频轻任务（改注释、跑构建）换更小模型/更低 effort | 输出单价敏感 |
