## 2. ★ 阶段 1：上电首验（30 秒，**验启动与栈**）

**这是 C 版和汇编版最不一样的地方**：C 版把栈放在 `SP=7FH`，
也就是压栈后实际写 `80H~FFH`（间接寻址区）；汇编版是 `SP=60H`。

| # | 操作 | 预期 | 不对意味着 |
|---|---|---|---|
| 1-1 | 冷启动，**什么都不按** | 数码管稳定显示 **`0`**，不响、电机不转 | **栈或启动代码有问题** → 停下，见第 7 节 |
| 1-2 | 盯 10 秒 | 显示**纹丝不动**，不闪、不复位 | 同上（栈踩到变量 / 看门狗式复位） |
| 1-3 | **短按 S3** 一下下按 | 档位 `1`→`2`→…→`5`，**每下一声响**，**D3 亮**，电机转 | 按键/中断坏了 |
| 1-4 | **短按 S4** | 档位递减到 `0`，到 0 后再按**无反应** | 同上 |
| 1-5 | 长按 **S3** 约 1 秒 | 显示 `L` → 再长按 `t` → 再长按回档位（**绕圈**） | 模式状态机坏了 |

> 1-3 之后电机应该**平稳地转**（100 Hz 驱动）。若一顿一顿的 → 见阶段 3。

## 3. ★★ 阶段 2：红外解码（**C 版第一风险，第一个要证的**）

> **为什么排最前**：`meas_level()` 是"轮询量脉宽"，C 的循环比汇编慢。
> 若循环太慢会**整圈跳过一次电平变化** → 整帧解不出来。
> 这条不过，后面所有遥控相关的东西都测不了。

| # | 操作 | 预期 | 不对意味着 |
|---|---|---|---|
| 2-1 | 车架空，按遥控**「前进」** | 车前进（持续走），**响一声** | 红外没解出来 → 见 7.1 |
| 2-2 | 按遥控**「停止」** | **立即停**，显示不变 | 同上 |
| 2-3 | 按**「左转」/「右转」** | **按住才转，松手停** | 同上 |
| 2-4 | 按**「加档」**（数字键 6）**连续按 5 次** | 档位**一档一档连续加**到 5 | ★ 只能加一次 = **丢帧/去重逻辑错**，见 7.1 |
| 2-5 | 按**数字键 1 / 2 / 3** | 显示在 `档位` / `L` / `t` 之间**直接跳** | 红外时好时坏 → 见 7.1 |
| 2-6 | **按住**「前进」不放 3 秒 | 车**一直走不停顿**（遥控器发重复帧） | 一顿一顿 = 重复帧没被正确识别 |

**2-1 ~ 2-6 全过 ⇒ C 版红外解码成立**，可以往下了。

## 4. ★ 阶段 3：中断余量（**C 版第二风险**）

> ### ★★ 2026-09-21：这一项**已经量化了，不用再凭感觉验**

**怎么量**：`tools\c51_isr_time.py` 读 `main_abs.LST`，建控制流图，求**最坏路径**和**典型路径**的机器周期。

```powershell
python tools\c51_isr_time.py firmware\c51\main_abs.LST timer0_isr
```

**判据（★ 不是"必须 < 92 周期"，那个判据是错的）**：

| 界线 | 值 | 含义 |
|---|---:|---|
| 一个 tick | **92 周期 / 99.83µs** | T0 方式2 自动重装 ⇒ **溢出周期固定**，与中断长短无关 |
| **硬线** | **184 周期（2 个 tick）** | 方式2 只有**一个**溢出标志 TF0：一个中断里挤进 **≥2 次**溢出，标志被合并 ⇒ **真的丢计数**。★ 进中断时 TF0 由硬件清零，所以"1 次溢出"不会丢 |
| 软线 | 92 周期（1 个 tick） | 超过它，那一 tick 主循环**一点 CPU 都拿不到**（突发卡顿，**不是丢时间**） |

**C7 实测**：最坏 **114** 周期（123.7µs = 124%）、典型 **36** 周期（39.1µs = **39%**）
⇒ **114 < 184，不丢时基**；主循环约拿到 61% 的 CPU（汇编版中断约 24%）。

**所以下面这几条现在是"确认性测试"，不是"排雷"**：

| # | 操作 | 预期 | 超了的表现 |
|---|---|---|---|
| 3-1 | 档位 1~5 各跑一遍 | 转速**平滑递增**，无抖动、无突然顿挫 | 顿挫 |
| 3-2 | 听蜂鸣器提示音 | 清脆的 **1 kHz**，不是沙哑/断续 | 音调怪 |
| 3-3 | 阶段 2 的 2-1~2-6 再走一遍 | **与刚才完全一致，不丢帧** | 红外间歇失效 |
| 3-4 | 让车**连续转 5 分钟** | 电机/驱动芯片**不烫**、显示不乱、行为不漂 | 发热 = 有东西在丢拍 |
| **3-5** | ★ **读数标定**：拿卷尺把挡板放到车前 **15cm**，看 `us_scope.hex` 显示的数字 | 约 **8~9**（15 ÷ 1.72） | 等比偏小 = 时基被拖慢（距离判据是按 tick 定的，会整体失准） |

### ★★ 新增：避障新模型（C1 / C2 / C3，**必须先看这张表**）

> 2026-09-20 按你的要求把避障拆成**两条独立通道**。**既有验收表里的避障判据已经不能直接套用了**，
> 照下面这张表和 C1~C3 三条测。

| | **红外**（车头对管 P3.7，量程 1~2cm） | **超声波**（5~21cm） |
|---|---|---|
| **触发时的动作** | ★ **直接刹车**（刹停 + 锁存 + 间歇响）<br>**绝不转向避让** | 5~21cm：原地右转避让<br><5cm：刹停 + 锁存 |
| **手动** | ✅ 全局生效 | ✅ 受开关控制 |
| **寻光 `L`** | ✅ 全局生效 | ✅ 受开关控制 |
| **循迹 `t`** | ✅ **全局生效（新）** | ❌ **不参与** |
| **能不能关掉** | ❌ **关不掉**（"最后一道"的定位） | ✅ 长按 S4 / 按数字键 5 |
| 触发后的锁存 | ✅ 有（要按遥控才解除） | ✅ 有（<5cm 那档） |

**为什么循迹只要红外、不要超声波**：超声波那一档是"**原地右转避让**"，
在循迹下会把车从黑线上推开、直接废掉循迹；而红外**只刹车、不改写动作码**，
所以放进循迹是安全的。代码里这两条走的是**不同函数**（`ir_brake` vs `av_gate_hold`），
谁也不会串到谁。

> ⚠️ **上电前提（比以前更重要了）**：红外极性是**上电时自动校准**的
> （以那一刻 `P3.7` 的电平为"无反射"参考）。
> 因为红外现在**关不掉**，**上电时车头 1~2cm 内绝对不能有东西** ——
> 否则极性会反，车会"面前没东西却一直刹停"。真遇到了：**把车挪开重新上电**即可。

### ★ C1：遥控**数字键 5 = 超声波避障开关**

> **背景**：数字键 5（码值 `1C`）原来是"循环切模式"键，**R14 起那个功能已取消**
> （改由数字键 1/2/3 直选模式），所以这个键一直空着。
> 2026-09-20 把它**改成超声波避障开关**，与"**长按 S4**"完全等效 ——
> 区别只是遥控上够得着（不用把手伸到车上），且**不占长按的 1 秒**。
> ⚠️ **这是 C 版独有的改动**：汇编版 `car_asm.asm` 里数字键 5 **什么都不做**。

| # | 操作 | 预期 | 不对意味着 |
|---|---|---|---|
| C1-1 | **手动**模式按数字键 **5** 一下 | 蜂鸣器**两声短响**（开）→ 再按一下**一声长响**（关），如此交替 | 键值不对（真码值不是 `1C`？）→ 用诊断版看串口打出的 `K=` |
| C1-2 | 长按 **S4** 一下 | 与按 5 **表现完全一致**（两声 = 开、一声长 = 关） | 两条路不一致 |
| C1-3 | 进 **寻光 `L`**，按 **5** | 同样能开/关 | 只在手动模式下加了判断 |
| C1-4 | **录制中**按 5 | 能开/关，且**不影响录制**（记录仍是动作+档位，回放照常） | 多加了录制守卫 |
| C1-5 | **回放中**按 5 | **不生效**（这是**故意**的，见 `main.c` 里那段注释） | — |
| C1-6 | ★ 关掉超声波后，车**正在"太近刹停锁存"** 状态 | 锁存**被解开**（"救急"路径仍有效） | 关的时候没清 `avst` |

### ★★ C3：循迹下**只有红外刹车**、没有超声波避让

| # | 操作 | 预期 | 不对意味着 |
|---|---|---|---|
| C3-1 | 进 **循迹 `t`**，黑胶带压住两个探头让车走 | 正常循迹（显示 `t`，不受避障干扰） | — |

| C3-4 | 手拿开 | 停响，车仍停着 | — |
| C3-5 | 按遥控**任意键** | 退出锁存，**循迹继续**（车重新贴线跑） | 锁存解不掉 |
| C3-6 | 循迹中按 **5** 关超声波 | 表现**不变**（循迹本来就不参与超声波） | 循迹下错误地受开关影响 |

> **C3-3 的"数码管仍是 `t`"是个好判据** —— 如果它变成档位数字，说明刹车路径用错了显示函数。

### ★★★ C6 / C7：超声波改成非阻塞之后，要重测的就是这 5 条

> 用户实测原话：**"1、上电时需要按一下 S3 遥控才有反应；2、超声避障还是失效"** ——
> 这两条**很可能同源**：C6 之前 `us_read()` 是**阻塞**的，主循环被白等，遥控自然采不到帧。

| # | 操作 | 预期 | 说明 |
|---|---|---|---|
| **C7-1** | 上电后**什么都不按**，直接拿遥控按方向键 | **立刻就有反应**（数码管跟着变） | ★ 直接验"主循环还被不被阻塞"。这就是用户报的第 1 条 |
| **C7-2** | 手放车前 **10~15cm**，手动档**前进** | 车**原地右转避让**（不是撞上去） | ★ 这就是用户报的第 2 条 |
| **C7-3** | 手放到车前 **<5cm** | **刹停 + 锁存**（不动，按键才恢复） | 近区刹停 |
| **C7-4** | 长按 S4（或遥控 **5**）关掉超声波，手再放 10~15cm | **不避让、直行** | 开关真的管用 |
| **C7-5** | 遥控**连按方向键 10 次以上** | 每次都响应，**不丢键** | ★ 丢键 = 主循环又变慢了 |

> ⚠️ **C7 之后 `main.hex` 变了**（3031 字节 code；HEX 文件 8558 B，SHA256 `D01C4BBD1551FFF3…`）
> ⇒ 上机前**必须重烧**：
> ```powershell
> powershell -NoProfile -ExecutionPolicy Bypass -File firmware\c51\build_c_abs.ps1
> # 出 firmware\c51\main.hex
> ```

**C7 一句话**：`us_read()` 从"**触发 + 原地等回波**"改成
"**取上次结果 + 必要时发一个 13µs 触发脉冲就立刻返回**"，
回波宽度交给**中断**按 99.83µs 精确累加。
⇒ 模块哪怕完全没响应，主循环也**一次都不等**，遥控不会被饿死。

**若 C7-1 仍然不行**：说明还有**第二个**卡主循环的地方 ⇒ 走下面"第 2 步 / 第 3 步"抓数据，别反复重烧。

### ★★ 避障不听话时：按这个顺序查（**别猜，一步步来**）

避障有两条通道 + 一个开关，"没反应"有好几种成因，而且**其中好几种都是静默的**（不响、不亮）。
按下面顺序查，每一步都能砍掉一半可能。

#### 第 0 步：先看有没有"响声"（0 秒，站着看）

| 车的表现 | 说明它在哪条路 |
|---|---|
| 停住 + **响一声** + 之后每 ≈0.7s 再响 | 被**刹停锁存**了（红外 或 超声波 <5cm） |
| **不转、不停、完全不响** | ⚠️ **静默放行** —— 只有三种可能：**开关关了** / **循迹模式** / **超声波读到"够远"** |

#### 第 1 步：确认开关和模式（5 秒，不用重烧）

1. 数码管内容：`0`~`5` = 手动（正常）；`L` = 寻光；**`t` = 循迹 → 超声波是故意不参与的**
2. **按遥控数字键 `5` 一下**（或长按 `S4`），听：
   - **两声短响** = 刚才是**关**的 → 现在打开了 → **再试一次避障**
   - **一声长响** = 刚才是开的 → 现在关了 → **再按一下**恢复

> ★ **开关每次上电都复位成"开"**。所以"拔电重上电"是最快的复位办法 ——
> 如果你怀疑开关被误碰关了，**断电重上电再试一次**，10 秒就能排除。
> （曾用"关掉时数码管闪烁"来显示状态，**用户不要，已撤掉**：现在只靠切换时那一声提示。）

#### 第 2 步：验超声波（1 分钟，要烧一次）★ **这一步能把"硬件"和"我的代码"夹死**

**有 4 个现成程序，别搞混** —— 硬件一样，但**测距的代码路径完全不同**：

| 烧哪个 | 谁在测距 | 数码管含义 | 回答什么问题 |
|---|---|---|---|
| **`firmware\diag\usprobe.hex`** | 它**自己**的汇编代码 | **`-`** = 没回波；**`0`~`9`** = 距离 = **数字×5cm** | ★ **模块 + 接线好不好** |
| **`firmware\diag\us_scope.hex`** | ★ **`main.c` 里那一份 `us_read()`**（C7 起**非阻塞**，20ms 轮询一次） | **`E`** = 等不到回波上升沿（模块没响应触发）<br>**`H`** = 回波来了但够远（≥12 tick≈21cm）<br>**`0`~`9`** = **正常量到**，数字就是固件用的 tick 数（距离 ≈ 数字×1.72cm） | ★ **"是不是我的 `us_read()` 测不到、卡在哪一步"** |
| `firmware\diag\uscheck.hex` | 它自己的（**D3 那半已修**，见下） | `1`/`2`/`0`/`9` = 接线判定 | 只回答**接线对不对** |
| `firmware\diag\usfollow.hex` / `usfollow2.hex` | 跟随小车整套 | — | 整机联调用 |

**两条一起跑，结论是唯一的**（手放在车前 ~10~15cm 不动）：

| `usprobe` | `us_scope` | 结论 |
|---|---|---|
| 有数字 | 有数字（`6`~`9`） | ✅ 硬件和 `us_read()` **都能测** ⇒ 问题在**避障逻辑 / 开关**，不在测距 |
| **`-`** | `-` | 硬件这层就没回波 ⇒ 查模块 / `Trig` 线 / 供电 |
| 有数字 | **`-`** | ★ **硬件是好的、是 `main.c` 的 `us_read()` 有问题** ⇒ 报给我，我改代码 |

`us_scope.hex` 怎么出：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File firmware\c51\build_c_abs.ps1 -Scope
# 出 firmware\diag\us_scope.hex（★ 车全程停车，不会乱跑）
```

> ★ **它不编任何串口打印代码**（C5 起就是如此）—— 那是刻意的：
> `prt_boot()` 在**第一次写数码管之前**就要打印，而 `put_char()` 里是 `while(!TI);`，
> ⇒ **串口一出问题程序就死在那儿、数码管永远全灭**。自测版必须只显示、不打印。
> 要原始数值就把数码管读数 ×1.72cm 换算：**避障判据是 3（<5cm 刹停）和 12（<21cm 右转避让）**。

> ### ⚠️⚠️ 2026-09-21：`uscheck.hex` 的 **D3 判据本身是坏的**（已修，别再拿它判硬件）
>
> `uscheck` 的流程是 `MOV P1,#0FFH`（Trig 已经是高）→ 后面只写 **`SETB P1.3`** ——
> **没有先拉低，所以根本没有上升沿**。而 HC-SR04 是**靠 Trig 上升沿触发**的
> ⇒ 模块不会测距 ⇒ Echo 永远不变高 ⇒ **D3 永远是灭的**，
> 与模块好坏**无关**。当时就是被这条"假警报"带偏到硬件上去了。
>
> 对照：`car_asm.asm`（汇编版正式固件，上机验证过）和 `usprobe.asm` 都是
> **`CLR → SETB → 延时 → CLR`** —— 那才叫脉冲。**`uscheck.asm` 是三个里唯一漏了 `CLR` 的。**
> ⇒ **已修**（补上 `CLR` 再 `SETB`，`uscheck.hex` 已重编）。
> 它前一半的**接线判定**（数码管 `1`/`2`/`0`/`9`）**照旧有效** —— 那部分只看空闲电平，没问题。

> ⚠️ **接线大坑**（`uscheck.asm` 头注释里记着）：板上插座 `CSB1` 顺序是
> **`1:GND 2:Echo 3:Trig 4:VCC`**，而 HC-SR04 模块自己的顺序是
> **`VCC Trig Echo GND`** —— **正好反**！**直接把模块按原样插上去 = 电源接反**，
> 模块不工作甚至可能已经损坏。

#### 第 3 步：烧诊断版抓一行数据（硬件没问题时才需要）

烧 `main_dbg.hex`，抓串口，每 0.5 秒（或状态一变）会打一行：

```
! IR=0 AV=1 D=08 OF=1 M=0
```

| 字段 | 含义 |
|---|---|
| `IR=` | **车头红外**是否检测到（0/1） |
| `AV=` | 闸门状态：`0`FREE / `1`TURN（原地右转避让）/ `2`HOLD（刹停锁存）/ `3`HUMAN（遥控已接管）/ ★ **`4`ARC（弧线右绕，C17 新增）** |
| `D=` | **超声波实测距离**，单位 tick ≈ 1.72cm；`FF` = 读不到 / 够远 |
| `OF=` | **超声波开关**（0/1） |
| `M=` | 模式：`0`手动 / `1`寻光 / `2`循迹 |

**对照判读**（手放在车前 ~15cm，让车朝障碍走）：

| 看到什么 | 说明 |
|---|---|
| `D=FF` | 超声波**根本没量到**（当"够远"了）→ 回到第 2 步查硬件 |
| `D` 在 `0C`~`13` 之间、`AV=4` | ✅ **正常（C17）**，此时车应该**边前进边向右拐**（弧线绕） |
| `D` 在 `03`~`0B` 之间、`AV=1` | ✅ **正常**，此时车应该原地右转 |
| `IR=1`（手离得还有 10cm 就 1） | ⚠️ **车头红外在误报** —— 它现在全局且关不掉，会**抢在超声波前面刹车**（`AV=2`） |
| `OF=0` | 超声波开关**被关了** → 按一下**数字键 5**（两声=开） |
| `M=2` | 在**循迹**模式：超声波**故意**不参与，只有红外刹车 |
| `AV=0`（一直） | 闸门没介入 → 不是避障的问题，去查电机/驱动 |

> ⚠️ 诊断版开着打印，**遥控接收会变差**（会漏帧）—— 排避障时不用按遥控，没影响。
> 抓完记得**烧回 `main.hex`**。

## 7. 出问题了怎么办（**先换诊断版**）

### 7.0 第一步永远是：烧诊断版

C 版**正常版没有任何串口输出**（`DEBUG_UART=0`，这是为了不让打印拖累红外接收）。
所以一旦遥控不对，先出诊断版：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File firmware\c51\build_c_abs.ps1 -Debug
# 烧 firmware\c51\main_dbg.hex（code=3640 B）
```

然后**先关掉 STC-ISP**（否则串口被占），再读串口：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\read_com.ps1 -Port COM7 -Seconds 60
# 日志落点：firmware\_serial_read.log
```

### 7.1 串口怎么判读（诊断版）

| 串口看到 | 含义 | 下一步 |
|---|---|---|
| `K=46`（按前进时） | **解码正常** | 问题不在红外，去查别处 |
| `! IR rej lo=.. hi=..` | **见到边沿但没解成 NEC** | 看这两个数：NEC 应为 `lo≈90`、`hi≈45`（单位 100µs） |
| `lo` 明显**偏大** | 量到的低电平比标准长 | ★ **C 版轮询偏慢**（`meas_level` 每圈太久）→ 报告给我 |
| 按什么都打出**同一个** `K=` | 从帧中间才开始解 | 同上，轮询太慢 |
| **完全没有任何字符** | 连下降沿都没等到 | 查 `P3.3` 接线 / 红外头供电；不是软件问题 |

> ⚠️ 诊断版**开着打印，红外本来就会漏帧**（9600 baud 下一个字符约 1 ms，
> 打一行 40 字符要 42 ms，而一整帧 NEC 只有 67 ms）。
> 所以：**诊断版只回答"解码逻辑对不对"，不能用它测手感**。

### 7.2 现象 → 先查哪里

| 现象 | 最可能的原因 | 处理 |
|---|---|---|
| 上电数码管不亮 / 乱码 / 反复复位 | ★ **栈**（`SP=7FH` 用到 `80H~FFH`）或启动代码 | 立即停手，把现象告诉我 —— 要改布局重编 |
| 显示 `0` 正常，但按键完全没反应 | 中断没起来 | 查 `ET0/EA/TR0`（`init_all` 末尾） |
| 按键能加档、电机能转，**遥控完全没反应** | ★ 红外 | 见 7.0 / 7.1 |
| **电机声音比汇编版"闷"、转速略不同** | ✅ **正常，不是 bug** | C 版 PWM 是 **100 Hz**（汇编版 500 Hz），报告评审本来就要求 100~200 Hz |
| 电机顿挫 / 蜂鸣器沙哑 / 红外时好时坏 | ★ **ISR 超过 99.83 µs，丢 tick** | 见阶段 3，把现象告诉我 |
| 避障明明该刹停却不刹 | 超声波没接好 / `US_STOP` 门限 | 见 `联调记录.md` 第 739 行那组（R12 后 5 cm 才刹） |
| 回放按 `8` 完全不动 | 空记录（闪 `E`）或安全终止 | 先确认录进去了（进录制时应有 `r` + 一声） |

> ⚠️ **总结一句**：C 版第一次上机，**任何一个"看起来像老问题"的现象，都要先怀疑是移植引入的**，
> 不要默认"汇编版这样、C 版也这样"。**只回"第几步 / 看到什么"**，别自己解释原因。
