# 超声波跟随小车（`firmware\diag\usfollow.asm`）

> 状态基准：2026-09-17 晚。**程序已写好、已编出 hex，并已上机跑通（用户实测确认，2026-09-17）。**
> 目标器件 STC89C52RC @ 11.0592MHz；产物 `firmware\diag\usfollow.hex`（`code=1375` B，占 Keil **Eval 版 2048 B 上限的 64%**）。
> ⚠️ 还差一份**串口日志留档**（`firmware\_serial_read.log`），报告要用，见 `docs\待办与风险.md` B5。

一句话：用一个超声波模块（HC-SR04 类）测前方距离，让小车**跟在目标后面 20~30cm** 走 ——
远了追、太近退、距离合适就停着等。

## 1. 超声波模块接在哪（先看这个）

### 1.1 图纸结论

| 板上 4P 插座（XH2.54，图纸位号 **CSB1**） | 网标号 | 去 MCU | DIP40 | 把握 |
|---|---|---|---|---|
| **第 2 脚** | `P12EC`（EC = Echo） | **P1.2** | 第 3 脚 | ✅ 确定（网标号同名相连，闭环） |
| **第 3 脚** | `P13TR`（TR = Trigger） | **P1.3** | 第 4 脚 | ✅ 确定（同上） |
| **第 1 脚** | 直接画了一个接地三角符号 | GND | — | ⚠️ 较高（符号明确，但这根网上没有文字标号） |
| **第 4 脚** | 画了电源符号，旁边文字 `VCCBAT` | VCC（电池轨） | — | ⚠️ 较高（同上） |

来历：`docs\引脚表_原理图追线.md` 第 2 节。**复现命令**（想自己再看一遍就敲这个）：

### 1.2 ⚠️ 三个必须先知道的坑

**坑 1（背景知识）：发货清单里没有"超声波模块"这一项。**
`2.发货清单（元器件清单）.pdf` 里只有一个 **4P XH2.54 插座**，没有超声波头
（清单里能认出来的件：L293D、STC89C52、LM393、0038、5528、S8550、数码管、蜂鸣器、电机、4P/6P/7P 座、
电位器、11.0592M 晶振……）。所以模块是**另配的**（本次上机用的就是自备模块）。
> 手上没有模块的话，先跑 `firmware\diag\follow.asm`（红外反射探头跟随），那个不用额外买件。

**坑 2：插座顺序和 HC-SR04 的引脚顺序是反的，别直接怼上去。**
- 板上插座**按脚号**是：`1=GND  2=Echo  3=Trig  4=VCC`
  （图纸上这 4 个脚是从上往下画的 1→4；实物请以插座丝印的脚号为准，XH2.54 座上一般印了 "1"）
- HC-SR04 模块自己的脚：`VCC / Trig / Echo / GND`
- 直接插 = **把 VCC 插到 GND 上**。必须用 4 根杜邦线按标号一根一根接：

| 模块 | → 插座 |
|---|---|
| VCC | 第 **4** 脚 |
| Trig | 第 **3** 脚 |
| Echo | 第 **2** 脚 |
| GND | 第 **1** 脚 |

**坑 3：接之前用万用表核一遍**（图纸 ≠ 实物，这是本工作区一贯的规矩）。
不装模块、只上电（USB 供电即可），量插座四脚对电池负极的电压：
**第 1 脚 ≈ 0V、第 4 脚 ≈ 电池电压**，第 2/3 脚是信号脚（不要拿它俩当电源）。
若量出来第 1 脚是 VCC、第 4 脚是 GND，**以实测为准**，把接线按实测反过来 —— 但**先别插模块**，回来告诉我。

> **Trig/Echo 接反了怎么办**：症状是串口一直打 `no echo`、小车一步不走。
> 把 `usfollow.asm` 顶部这两行对调，再编一次即可（就一处）：
> ```asm
> US_TRIG     BIT     P1.3
> US_ECHO     BIT     P1.2
> ```

> **电源提醒（沿用 `docs\待办与风险.md` B2）**：板子给的是电池轨 `VCCBAT`。
> 4 节**新碱性**电池空载 6.0~6.4V，不但超 STC89C52RC 的 5.5V 上限，也超 HC-SR04 的 5.5V 上限。
> 用 4 节镍氢（4.8V）或串一只二极管最稳。

## 2. 程序怎么动作

| 中值距离 | 动作 | P0 图案 |
|---|---|---|
| **> 28 cm** | 前进追 | `0F5H`（IN1+IN3，两轮同向） |
| **14 ~ 28 cm** | 停（保持距离） | `0C0H`（ENA/ENB 一起拉低 = 电机断电滑行） |
| **< 14 cm** | 后退让开 | `0FAH`（IN2+IN4），**同时每轮短鸣**（倒车提示） |
| 约 4m 内量不到东西 | 先按"追"处理 | —— |
| 连续 30 轮（≈4 秒）没回波 | **安全停车待机** + 串口报警 + 响一声 | `0C0H` |

细节（都是为了让它在门限附近**别抽**）：

- **迟滞 6cm**：已经在走的时候，要跌到 **< 22cm** 才停；停着的时候要涨到 **> 28cm** 才走。
- **三次测量取中值**：每轮测一次，把最近三次排个序取中间那个（`MED3`）—— 一次异常读数不会带动整车。
- **每轮末尾固定等 60ms**：HC-SR04 要求两次触发间隔 ≥ 60ms（触发太密会把上一次的回波当这一次的）。
  加上测距和串口打印，实际触发间隔约 90~160ms。
- **上电闭锁**：**必须先成功量到一次回波，电机才允许动**。
  模块没插 / 接线错 / 坏了 → 车原地不动（而不是"量不到就往前冲"）。
- **测得距离换算**：`cm = Echo高电平机器周期数 ÷ 53`（1 周期 = 1.0851us；1cm 往返约 53.4 周期，
  所以偏大约 0.8%，对 14/28cm 的门限毫无影响）。想更准就改 `CM_DIV`。

## 3. 板子上的反馈（不看串口也能用）

| 器件 | 含义 |
|---|---|
| **数码管** | **距离的十位**：`2` = 20~29cm、`3` = 30~39cm …… 超过 90cm 一律 `9`。只有一位，两位数显示不了 |
| **D3 灯（P2.0）** | **亮 = 电机在动**，灭 = 停着 |
| **蜂鸣器（P0.6）** | 开机"滴"一声 = 程序在跑；后退（太近了）时每轮短鸣；判断"目标丢失"时也响一声 |

> 注意 `P2.0` **不是**数码管段选（段序是 `a=P2.7 … g=P2.1`），这是图纸追线的结论，见 `config.h` 第四节。

## 4. 串口（9600 8N1，COM7，P3.1）

```
D=025cm T=0342  A=STOP      <- 距离 25cm（中值），本轮 Echo 高电平 0x0342 个机器周期，正在保持
D=041cm T=0567  A=FWD       <- 41cm，在追
D=---cm (no echo)     T=----  A=BACK   <- 本轮没有回波
```

- `T` 是**本轮原始测量**（4 位十六进制，机器周期）。拿卷尺校距离就用它：`cm ≈ T十进制 ÷ 53`。
  若系统性偏大/偏小，按比例改 `CM_DIV`（偏大 5% → 改成 55/56；偏小 → 51/52）。
- 打印节流：**动作一变立刻打印**，否则每 4 轮一行（大约每 0.4~0.6 秒）。
- 读日志：
  ```powershell
  powershell -NoProfile -ExecutionPolicy Bypass -File tools\read_com.ps1 -Port COM7 -Seconds 300
  ```
  （跑之前先关掉 STC-ISP，否则串口被占。）

> 下载时用 S1 开关断电重启即可。⚠️ 2026-09-20 更正：~~**拔掉电池、只插 USB**~~ **不用拔电池** ——
> USB+电池同接也能冷启动下载（见 `docs\待办与风险.md` B1 更正块）。

**验收判据（按顺序做，一步不过就别急着下一步）：**

1. **不插模块，只上电**：串口应打印开机 banner，然后
   `! self-check: Echo reads HIGH while idle -> check module/wiring`（因为 Echo 脚悬空读到高），
   数码管跳 `9`，**车轮一动不动**（上电闭锁生效）。这一步同时验证了"没接模块也绝不乱跑"。
2. **接好模块再上电**：banner 后面应变成 `self-check: Echo idle = LOW (ok)`，并有"滴"一声。
3. **架空小车**（轮子悬空），拿一本书在探头前面慢慢移动 10cm ↔ 50cm：
   - 串口 `D=` 应该跟着变（30→50 时 `T` 也变大）；
   - 数码管十位跟着变：1x→`1`、2x→`2`……；
   - 30cm 以上轮子向前转，10~13cm 时向后转，20~25cm 停。
4. **落地跟人走**：人站在车前 30~40cm 慢慢往前走，小车应该跟上来；人停下，小车在 20~30cm 处停住；
   人退到它跟前 10cm 以内，它会往后让一点。人走远超过 4m，约 4 秒后它自己停下并打印 `!! target lost`。

## 6. 不符合预期时怎么查

| 现象 | 多半是什么 |
|---|---|
| 串口一直 `no echo`，车一步不走 | 接线（Trig/Echo 反了、没插上、VCC/GND 反了）；或模块坏。**先量插座第 1/4 脚电压** |
| 开机就打印 `Echo reads HIGH while idle` | Echo 脚没有真正接到模块（悬空被内部弱上拉拉高） |
| `T` 一直是 `0000` 或 `FFFF` | 触发没发出去（Trig 脚错）/ Echo 一直高（线接错） |
| 距离显示恒定不变 | Echo 接在了别的脚上（对照第 1 节表格重接） |
| 距离偏大/偏小一个固定比例 | 声速/晶振差：改 `CM_DIV`（见第 4 节） |
| 在门限附近走走停停 | 迟滞不够就把 `GO_HI` 调大、`HOLD_LO` 调小（差值就是迟滞） |
| 前进/后退方向反了 | `PAT_FORWARD` 与 `PAT_BACK` 对调（`remote.asm` 里也一样的两行） |
| 左轮右轮反了（原地转） | 本程序不转弯，用不到；真要转弯见 `config.h` 的 `LEFT_REVERSE/RIGHT_REVERSE` |
| 打印正常但轮子不转 | L293D 的 `ENA/ENB`：图案里 b4/b5 必须是 1；空载量 P0.4/P0.5 应为高 |

## 7. 想调的参数都在哪

`firmware\diag\usfollow.asm` 顶部“一、常量”一节：

| 常量 | 现值 | 作用 |
|---|---|---|
| `GO_HI` | 28 | 停着时，超过这个距离就走（cm） |
| `HOLD_LO` | 22 | 走的时候，跌到这个距离以下就停（与 `GO_HI` 的差 = 迟滞） |
| `BACK_HI` | 14 | 停着时，近于这个距离就往后退 |
| `BACK_LO` | 8 | 后退时，退到这个距离以上就停 |
| `CM_DIV` | 53 | 机器周期 → cm 的除数（校准用） |
| `LOST_MAX` | 30 | 连续多少轮没回波就安全停车（每轮约 90~160ms） |
| `PRT_DIV` | 4 | 串口每几轮打一行 |
| `BEEP_CYCLES` | 12 | 短鸣长度（1kHz 半周期数） |

## 8. 和 `firmware\diag\follow.asm`（红外跟随）的区别

| | `follow.asm`（红外反射） | `usfollow.asm`（本程序，超声波） |
|---|---|---|
| 探头 | 板上已有：`V2→P3.5`、`V3→P3.6`（朝前装） | 需要**自备**超声波模块，接 4P 插座 |
| 得到的信息 | 左/右两路**有无**（≈10cm 内有没有） | 一路**距离**（4cm~4m），带数值 |
| 能做的事 | 左有右无 → 左转对准，两个都有 → 停 | 前进/后退/保持**距离**，不能转向 |
| 门限 | 固定（探头灵敏度电位器调） | 14/22/28cm 可改 + 迟滞 |
| 上机状态 | ❓ 未单独确认（整机自检走过，但没专门测它） | ✅ 已上机跑通 |

> 两者合起来就是 PPT 里的"红外避障 + 超声波避障"两个功能项。
> 想再进一步：超声波管**前后距离**、红外两路管**左右对准**，两者揉在一个程序里做"跟人对准"。
