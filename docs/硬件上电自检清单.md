# 智能移动机器人 硬件上电自检清单

> 适用套件：STC89C52RC 主控 + L293D 双 H 桥 + 0038 红外接收 + LM393 比较 + 1 位共阳数码管 + 无源蜂鸣器（S8550 驱动）
> 目的：焊接完成后，**按最不容易烧板子的顺序**逐级验证，每级都有明确的通过判据。
> 原则：**先目视、再静态量、再 USB 上电、最后才用电池**；任何时候发现芯片发烫立即断电。
>
> ✅ **2026-09-17 状态：本清单的各阶段已在实物上跑通**（`probe2` / `selftest` / `modtest` / `remote` / `usfollow`
> 全部上机正常）。下面这些判据现在当**回归检查表**用（换板、改版、重新焊时再走一遍）。
> 逐项结论见 `docs\上机验证记录.md`。

## 阶段 0  断电目视检查（不装 IC、不接电池、不插 USB）

| 检查项 | 通过判据 | 不通过怎么办 |
|---|---|---|
| 焊点质量 | 焊点呈光亮的锥形，无虚焊、无拉尖、无连锡 | 重点看 IC 座相邻脚、L293D 的 16 脚、排针、晶振 |
| IC 座方向 | 缺口/圆点与丝印缺口一致 | 装反了整块板都不工作 |
| 电解电容（1000µF/10V） | 长脚=正极，外壳带条纹一侧=负极，与丝印 + 号一致 | 反接上电会鼓包甚至爆 |
| 二极管 / S8550（PNP） | 丝印条带方向与板上图形一致 | 无丝印时用后面阶段 1 的二极管档确认 |
| 数码管 | 缺口/小数点位置与板上丝印一致，方向不能反 | 装反会显示乱码，不一定坏 |
| 0038 红外接收头 | 接收窗口朝外无遮挡，三个脚没装反 | 装反必换 |
| 红外对管 V7/V4、光敏电阻 | 引脚没有互相碰、没有插错位（对管一般有长短脚） | — |
| 排针/插座 | 没有歪斜、没有漏焊 | — |

> 上电前务必确认：**没有任何焊锡渣/剪断的引脚残骸**留在板上（特别是 L293D 和 MCU 座之间）。

## 阶段 1  静态检查（万用表，仍然不上电）

没有万用表也建议买一个几十块的，后面调 LM393 阈值、量电压都要用。

1. **电源对地电阻（最关键的防短路一步）**
   - 不装电池、不插 USB，万用表电阻档测 5V/电源正极 ↔ GND。
   - 判据：应有几百 Ω ~ 几 kΩ 的读数（板上电容在充电，读数会缓慢变化）。
   - **接近 0 Ω = 有短路，绝对不要上电**，先排查电源走线和 IC 座。
2. **电源开关 S1**：拨动开关，通断档确认开/关状态正确。
3. **二极管/三极管极性**（万用表二极管档）
   - 硅二极管：正向压降约 0.5~0.7V，反向不通。
   - S8550（PNP）：找到基极 B（与另两脚都构成 PN 结），发射结压降略大于集电结；**以板上丝印和图形为准**，不要凭记忆下结论。
4. **通断检查**：GND 排针与电池负极、与 CH340 模块 GND、与 L293D 的 GND 脚（4/5/12/13）之间应导通。

## 阶段 2  首次上电：只用 USB（推荐现在就做）

USB 下载口经 CH340 模块给板子供电，**电流受限、电压稳定在 5V，是最安全的首考环境**。

> ⚠️ **USB 供电时请把电池盒开关 S1 拨到关（或先不装电池）**。4 节新碱性电池空载电压可达 6.4V，超过 STC89C52RC 的 5.5V 工作上限；只有板上确实有 5V 稳压（如 7805）时才可以同时接。先按原理图确认这一点。
>
> ⚠️⚠️ **2026-09-20 更正**：上面这条**超压提醒仍然成立**，但**"USB 与电池不能同时接"这个说法作废** ——
> 用户实测：USB + 电池同时接着，拨 `S1` 关→开 就能**正常下载**（`docs\待办与风险.md` B1 更正块）。
> 所以"同时接"本身不是问题，**问题只是电压**：别用满电的 4 节碱性电池。

1. **插 USB，手不要离开插座**（方便随时拔），观察 10~20 秒：
   - 有无冒烟、异味、异常发烫。
2. **发烫检查**（手指背面轻碰，别用指腹，烫了会本能缩手）：
   - STC89C52、L293D、CH340、S8550 —— **任一明显烫手立即拔 USB**。
   - 正常情况：微温或室温。
3. **量 5V 轨**：万用表直流档量下载口附近的 5V 与 GND，应为 **4.75 ~ 5.25V**。
   - 只有 2~3V：电源走线有虚焊/限流电阻装错/负载短路。
4. **量 MCU 座第 40 脚(VCC) 对第 20 脚(GND)**，应为 5V 左右。
   - 注意：**如果 MCU 还没插，量的是座子上的电压，也是 5V**。
5. **有没有数码管乱亮/全亮**：MCU 没程序时引脚为高电平，共阳数码管的段由 MCU 拉低才亮，所以**不亮是正常的**；常亮全 8 说明有段脚对地短路或数码管装反。
6. **蜂鸣器有没有一直响**：正常应该不响。一直响说明 V1(S8550) 基极被拉低或三极管装反。

> **通电状态下绝对不要插拔 IC、数码管、电机、杜邦线。**

## 阶段 3  电池供电与电源检查

USB 自检通过后再上电池。

1. 装 4 节电池（建议用电压一致的新电池，**不要新旧混用**）。
2. S1 打开，重复阶段 2 的发烫检查和 5V 测量。
3. **量电池盒输出**（开关打开、带载）：4 节碱性电池空载约 6.0~6.4V，带载会降到 5.5~6V。若低于 5V，电机一转就复位/重启 —— 换电池。
4. ~~若板上无稳压，**不要同时插 USB 和开 S1**。~~ → ⚠️ **2026-09-20 更正**：**可以同时插**（用户实测同时接也能正常下载冷启动，见 `docs\待办与风险.md` B1）。
   要防的是**电压**：满电的 4 节碱性（6.0~6.4V）超过 MCU 的 5.5V 上限 —— 用 **4 节镍氢（约 4.8V）**，或串一只二极管降 0.7V。

操作步骤：

1. 打开 STC-ISP，单片机型号选 **STC89C52RC**，串口号选 **COM7**，波特率保持默认。
2. **不用 hex 就能先验链路**：点【检测MCU选项】→ 然后冷启动。能读回芯片信息就说明 MCU、晶振、串口链路全通。
3. **冷启动下载**（STC 的关键点）：
   - 点【下载/编程】→ **然后才**给板子上电。
   - USB 供电时：点完下载再**拔插一次 USB**；电池供电时：点完下载再拨 S1。
   - 握手成功会显示进度并提示"操作成功"。
4. 失败排查：
   - 一直是"正在检测单片机" → 冷启动时机不对（多试几次），或 P3.0/P3.1 虚焊，或晶振没起振。
   - 提示校验和错误 → 最高波特率调到 9600 或 2400 再试（老芯片 + 长 USB 线容易失败）。
   - 串口列表里没有 COM7 → 换一根 USB 线（有些线只供电不通信），或 CH340 虚焊。

## 阶段 5  引脚识别固件（两个程序，一次拿到完整引脚表）

见 `开发环境与工具链.md` 的构建方法（`firmware\probe\build.ps1 -Name 程序名`）。

### 5.1 第一支：`probe.asm`　✅ 本机已实测通过

复位后依次给 `P0.0→P0.7、P1.0→P1.7、P2.0→P2.7` 共 24 个引脚输出 4Hz 方波，每脚 4 秒、脚间静默 2 秒，无限循环。

**实测结论**：STC-ISP 提示"操作成功"，两个轮子**交替**抖动 → 证明 ① 下载链路通 ② 晶振起振、MCU 在跑 ③ L293D 与两个电机都正常 ④ 两路电机由**不同引脚**分别控制（不是共用 EN）。

### 5.2 第二支：`probe2.asm`　← 用它把引脚表问出来

`probe.asm` 要你"数第几片"，盯两分半钟很容易数错。`probe2.asm` 改成**程序自己报序号**：**第 i 个引脚就抽动 i 下**，你只要数电机抽了几下。流程：

1. **起始标记**：P1+P2 全部引脚一起翻转 3 次 → **两个轮子各抽 3 下**（证明程序在跑、两个电机都活着）。
2. 静默约 3 秒。
3. **P1 组**：
   - 组标记：P1 全部引脚一起翻转 2 次 → 若两个轮子各抽 2 下，说明电机就在 P1 口上，这组就是你要的；
   - 静默约 2.3 秒；
   - `P1.0` 抽 **1** 下 → 停 2.5 秒 → `P1.1` 抽 **2** 下 → … → `P1.7` 抽 **8** 下。
4. 静默约 4 秒，**P2 组**同样结构。
5. 静默约 4 秒，**P0 组**同样结构（P0 是开漏口，只有低电平有效的负载会响应，属正常）。
6. 静默约 4 秒，回到第 1 步无限循环。

**怎么读**：

- **"抽 i 下" = 第 i 位（bit i-1）**。左轮抽 3 下 → 接在 `P1.2`。
- **同一个轮子可能在相邻两位都抽动**，次数正好是相邻两个数（例如抽 3 下和抽 4 下）—— 正常且有用：这两根就是该电机的两个方向脚（IN1/IN2），属于同一路 H 桥。
- **组标记决定是哪个口**：哪个组的组标记能让器件动，器件就在哪个口。组顺序 = P1 → P2 → P0。
- 数码管某段闪几下、蜂鸣器"哒哒"响几下，同样按次数定位引脚。

**注意**：P3 口（P3.0/P3.1 下载串口、P3.2 红外接收）完全不碰，避免与 0038 输出抢电流。测试时**把小车架起来让轮子悬空**。

### 5.3 第三支：`selftest.asm`　← 全部件自检（串口输出文字日志）

前两支都要你"看现象、数次数"。这支换了思路：**用下载用的那个串口（P3.0/P3.1 → CH340 → COM7）把结果打印成文字**，9600 8N1，日志直接读，不用数闪烁。

- 源码：`firmware\selftest\selftest.asm`；产物：`selftest.hex`（1455 字节，占 Eval 上限 68%）
- 读日志：`tools\read_com.ps1`（默认 COM7 / 9600，日志落到 `firmware\_serial_read.log`）。**读之前必须关掉 STC-ISP**，否则串口被它占着。

三个阶段（上电自动开始，之后 B↔C 无限循环）：

| 阶段 | 时长 | 做什么 | 能验证什么 |
|---|---|---|---|
| **A** 逐引脚激励 | ~60 s | 依次对 P1.0~P1.7、P2.0~P2.7、P0.0~P0.7 每脚输出 **4Hz 方波 2 秒** + **1kHz 方波 0.25 秒**，动作前先打印 `[序号] P1.0:` | 电机（抽动）、数码管（段闪/半亮）、蜂鸣器（1kHz 时发清晰音）。**"看终端最后一行 → 再看板子"** 就能把引脚对上号 |
| **B** 输入扫描 | ~40 s | 反复读 P1/P2/P3（屏蔽 P3.1 自身发送），任一位变化就打印 `B P1 xx` | 按 S3/S4；白纸/黑胶带过循迹探头；挡住避障探头、遮光敏电阻；拧 W1/W2（都能看到某位翻转） |
| **C** 红外解码 | ~40 s | 轮询 P3.2，检测到信号就打印引导码低/高电平时长 + 解出的 `addr ~addr cmd ~cmd` + NEC 互补校验 | 0038 接收头是否工作、协议是不是 NEC、**每个按键的码值**（对比键值表校验集 `08 16 18 1C 5E 5A 42 52 4A 09`） |

**额外白送的两个验证**：

1. **晶振**：串口能打出**可读文字**就说明波特率是对的；9600 只在校验频率为 11.0592 MHz 时成立 —— 所以"文字不乱码"= 晶振频率正确。
2. **MCU + 下载链路**：能烧进去并跑起来，本身就是验证。

**注意**：A 阶段 P0 是开漏口，写 1 只是"放开"，所以接在 P0 上的**高电平有效**负载不会动，属正常；测试时仍要把小车架起来。

## 阶段 6  分模块验证

| 模块 | 怎么测 | 通过判据 |
|---|---|---|
| 数码管 SM1 | 探测固件走到它那几脚时，对应段闪烁 | 每段独立可控，无整段不亮（不亮=该段虚焊/限流电阻错） |

## 故障速查

| 现象 | 最可能原因 |
|---|---|
| 一插 USB 就发烫/冒烟 | 电源正负极短路、IC 装反、电解电容反接 → 立即断电，回阶段 1 |
| 5V 只有 2~3V | 电源走线虚焊、限流电阻装错、负载短路 |
| 下载一直检测不到单片机 | 冷启动时机不对 / P3.0、P3.1 虚焊 / 晶振未起振 / 没选对型号 |
| 数码管常亮全 8 | 段脚对地短路、数码管装反 |
