## 三、修掉的 Bug（症状 → 根因 → 修法）

### ★ 最重要的一个：红外遥控"按了完全没反应"

| 项 | 内容 |
|---|---|
| 症状 | 上电正常（响 3 声 + 显示 `8`），但按遥控器**毫无反应**；换了"关掉串口打印"等办法都不行 |
| 怎么定位 | 写了个**串口抓取**流程：把拒绝帧的**原始 32 位字节**打出来 → 抓到 `! IR rej lo=59 hi=2B a=FF b=00 c=00 d=00`（连按 5 次一致） |
| 判读 | `lo=59`(89 tick) / `hi=2B`(43 tick) → **引导码完全正常**；但 `a=FF b=00 c=00 d=00` → 数据位全挤进了第一个字节 |
| 根因 | `IR_SETBIT` 里位掩码推进用 **`RL A`**：它是 8 位循环左移，`80H→01H` **永远不归零**，`JNZ` 永远成立 → 字节序号 `PTRIDX` 永不前进。**加上**掩码只在"1"位推进（`0` 位不推进）→ 位序也错 |
| 影响面 | 这个 bug 从 `remote.asm` 一路继承下来 —— 也就是说**之前"测过能用"其实只验证了时序，解码一直是坏的** |
| 修法 | 掩码推进挪到 `IR_NEXTBIT`（**每一位都推进**）；`RL` → `CLR C` + `RLC`，用进位判断换字节 |
| 验证 | 重烧后串口打出 `K=46 FWD` / `K=15 BCK` / `K=43 RGT` / `K=40 STP` —— **全部正确** |

### 其它（按发现顺序）

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| 1 | 汇编报 `TARGET OUT OF RANGE`（**踩了 3 次**） | 主循环附近加代码，把 `JZ MAIN_LOOP` 顶出了 ±128 字节射程 | 改成 `JNZ <就近标签>` + `LJMP MAIN_LOOP` |
| 2 | 汇编报 `INVALID REGISTER` | **8051 没有 `MOV Rn,Rn`**（写了 `MOV R6,R4`） | 一律过 `ACC` 中转 |
| 3 | A51 第 1 行报 `SYNTAX ERROR` | `.asm` 存成了**带 BOM 的 UTF-8** | 存**无 BOM UTF-8**（每次改完都验前 3 字节） |
| 4 | `MOTOR_SET_ACT` 调用多了会跑飞 | 有条路径 `PUSH ACC` 后直接跳结尾，**漏 `POP`** | 改用 `R6` 暂存，完全不用 PUSH/POP |
| 5 | 蜂鸣器偶发怪音 | `BEEP` 改 `BUZLEFT`/`BUZB` 时没关中断 | 改动期间 `CLR EA`/`SETB EA` |
| 6 | 按住遥控车一颠一颠 / 松手不停 | NEC **重复帧**被当成"帧被拒" | 引导码高电平分两段：1.2~2.5 ms 判为重复帧（刷新"还按着"）；<1.2 ms 才拒绝 |
| 7 | 按遥控"完全没反应"，串口总解出同一个值 `2C` | 9600 baud 下**每个字符约 1 ms**，打一行 40 字符要 42 ms，而一帧 NEC 只有 67 ms → 打印期间错过下一帧开头 | 加 `DEBUG_UART` 开关，**正式用必须是 0**（顺带省 434 B） |
| 8 | 诊断结论一度判成"短引导码遥控器"（**错的**） | 解析日志时**漏看了折行**（续行以空格开头），只解析了第一行 | 解析前先按记录拼回折行；完整时序证明是标准 NEC |
| 9 | 寻光模式把档位减到 0 时电机不停 | `GEAR==0` 直接 `RET`，保持上次动作 | 显式套 `ACT_STOP` |
| 10 | 寻光/循迹下 D3 不亮 | 模式动作没写 `CURACT` | 模式动作写入 `CURACT` 并每趟刷新显示 |
| 11 | **有障碍物时遥控完全失灵**（用户实测报的） | 避障第一版拦停时 `LJMP IR_KEYSCAN`，**跳过了整条遥控处理路径** | 只更新 `AVBLK` 标志、不跳过输入；由 `MOTOR_SET_ACT` 统一拦"动" |
| 12 | 转向避让版：障碍拿开后**一直右转** | 避让把 `DIRBITS` 改成右转并留在那里 | 障碍解除时把 `CURACT` 重新套用 |
| 13 | 循迹**左右转向反了**（用户实测报的） | 我按"朝检测到线的那侧转"推理，与该车探头装法刚好相反 | 先让用户按遥控"左转"确认电机本身没反，再只翻循迹两行 |

## 四、关键设计决定（为什么这么做）

| 决定 | 理由 |
|---|---|
| 用 **A51 汇编**而不是 C | C 编出来体积是汇编的 2~3 倍，会撞 Keil Eval 版 **2048 B** 上限 |
| **主循环永不写 `P0`**，只改影子变量，`P0` 由 Timer0 中断组装 | 否则"主循环改方向"和"中断打 PWM"互相踩，电机会乱抽 |
| 动作码→电机图案只保留 **`MOTOR_SET_ACT` 一个出口** | 手动/模式/回放全走它；也是报告里 `Motor_Set(action,speed)` 的落点。**避障也在这个出口拦**，所以任何路径都绕不过 |
| **一个 100 µs tick 走天下**（Timer0 方式 2）：PWM、蜂鸣器方波、红外脉宽、各地超时都用它 | Timer1 被串口波特率占了；不再另开定时器，中断服务程序短 |
| 红外解码**不用外部中断**，主循环轮询 `P3.3` | 与报告"外部中断"的说法不同，但**已在实物验证**；且不影响 PWM/按键 |
| 超声波测距**用 100 µs tick**，不改成 Timer0 方式 1 | 方式 1 会破坏 PWM/蜂鸣器/红外时基。代价是分辨率 ≈1.72 cm —— 所以**只做门限比较、不换算 cm** |
| 避障 = **全局闸门**（不是模式） | 安全保护应该在任何模式下都在岗；`S4` 长按开关 |
| 避障做**转向避让**而不是刹车 | 用户要求；转开就能继续走，演示效果更好 |
| 前进/后退**锁定式**，左转/右转按住才转 | 用户要求：按一下让它走一段；转向要能随时停 |
| **诊断优先用"不用串口"手段**（数码管/蜂鸣器/指示灯） | 用户看不到串口输出；实在需要时我用 `read_com_stream.ps1` **自己抓**，不麻烦用户读数 |

### 值得记住的技术点（都是这次踩出来的）

1. **`CURACT` 是避障闸门的判据** —— `AV_GATE` 用 `CURACT != 0` 判断"本来在不在动"。
   所以**任何让车动起来的路径都必须同时设 `CURACT`**，否则车在走却不避障（= **P4**）。
   全程序只有 `APPLY_GEAR` 和 `MOTOR_SET_ACT` 两处写电机，前者原来漏了这一步。
2. **避障状态字节全程序只有 `AG_FREE` 一处会清零** —— 所以"**跳过 `AV_GATE`**"时必须**显式清它**，
   否则它会卡在"避让"态，把每个动作都改写成"右转" → **车一直原地打转**（= **R2** 实现时的坑）。
   （该字节在 R3 时从 `AVBLK`（2 态）改名并扩成 `AVST`（4 态）—— 见 `car_asm.asm` 的 `AV_*` 常量。）
3. **R1 会撞上"松手超时"** —— `IR_HOLDCHK` 的 300 ms 超时**只豁免前进/后退**。
   若把"回手动保持切换前的动作"照搬成**转向**，会在 300 ms 后被它停掉、达不到需求；
   实现成"**按档位继续前进**"才既满足需求、又符合块① "档位非 0 = 前进"的既有语义。
4. **`BEEP` 是非阻塞的**（真正翻转在 Timer0 中断里做）—— 所以 R4 里"锁存期间反复响"
   **不会**拖慢主循环、也**不会**错过红外帧。要是它是阻塞式的，这个做法就不成立。
