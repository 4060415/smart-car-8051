## 2. 关于"运行过程中偶发突然停车"（**未定位，不作为 C17 修改目标**）

此前测试中发现：

> 小车运行过程中存在极少数情况下突然停车、数码管显示 `0`。

现有判断：

| 项 | 结论 |
|---|---|
| 性质 | **偶发**（不能稳定复现） |
| 可能性排序 | 硬件 / 电源（带载欠压）/ 接触 / MCU 复位 因素**可能性较大** |
| 与 C17 的关系 | **没有足够证据**证明由 C17 避障逻辑造成 |
| 当前处置 | **不作为 C17 的软件修改目标** |

### 处理原则

**不要为了消除这个偶发现象而修改：C17 避障状态机 / PWM 底层 / 超声波状态机 / 主循环结构。**

除非后续测试能够明确证明以下三条**同时成立**：

1. 问题可以**稳定复现**；
2. 能够**定位到具体软件路径**；
3. 能够**排除**硬件、电源及复位因素。

否则**保持现有代码不动**。

> 📌 **本工程已有的排查线索**（做这件事时从那里起步，别从零开始）：
> `docs\排查_遥控偶发失灵.md` 顶部**"待查"节**已经记了这个现象（"跑着有时突然停车 + 数码管显示 0"，
> 特征：**转弯/弧线时更容易、只在车真在地上跑时出现（架空从不）** ⇒ 倾向"带载欠压复位"，但未定案），
> 并给了**三个 0 成本判据**（D3 是否变亮 / 按 `8` 是否变空记录 / 数码管是否先 `4→3→2→1→0`）与串口判读表。

## 3. 冻结内容（**不得随意改变**）

### 3.1 避障状态（`avst`）

```text
AV_FREE  = 0   /* 放行：无障碍 */
AV_TURN  = 1   /* 近区：原地右转避让 */
AV_HOLD  = 2   /* 太近：刹停 + 锁存，决定权交回遥控 */
AV_HUMAN = 3   /* 遥控已接管：放行（接管只用一次） */
AV_ARC   = 4   /* 中区：弧线右绕（C17 新增） */
```

### 3.2 距离分区（判据由 tick 阈值决定，不要求把 tick 与厘米理解成绝对精确）

```text
< 5 cm      → AV_HOLD  → 立即停车（锁存）
5 ~ 12 cm   → AV_TURN  → 原地右转避让
12 ~ 21 cm  → AV_ARC   → 弧线右绕
≥ 21 cm     → AV_FREE  → 正常运行
```

> ⚠️ **量化的实际情况**（1 tick ≈ 1.72 cm，判据是 `<`）：
> `d ≤ 6` tick（≲10.3 cm）→ 原地转；`d = 7~11`（≈12.0~18.9 cm）→ 弧线；`d ≥ 12`（≥20.6 cm）→ 放行。
> 上机时**不要拿 5 / 12 / 21 cm 整去卡边界**（见 `docs\C7上机测试清单.md`「C17 新增」的 C17-12）。

### 3.3 涉及的模式边界（同样是冻结口径）

| 场景 | 超声波 | 车头红外（`P3.7`，1~2 cm） |
|---|---|---|
| 手动 | ✅ 参与 | ✅ 参与（**最高优先级，关不掉**） |
| 寻光 `L` | ✅ 参与（<5 cm 时退回手动，**R7（寻光 <5 cm 退回手动）**） | ✅ |
| 循迹 `t` | ❌ 不参与 | ✅ |
| 录制中 | ❌ 不参与（**C14（录制中超声波不参与）**） | ✅ |
| 回放中 | ❌ 走自己的安全逻辑（**遇障只停车终止，绝不绕行**） | ✅ |
| 倒车 `ACT_BACK` | ❌ 不参与 | ✅ |

## 4. 280 ms 决策保持机制（**是有意的"最小保持时间"，不只是滤波**）

处于 `AV_ARC` / `AV_TURN` 时，**进入动作后的约 280 ms 内不因距离变化而重新切换避障状态**
（常量 `AV_DEC_TICKS = 2800`；进避让本身是**立即**的，只有"改主意"要等窗口）。

目的：防止超声波读数在边界附近波动时，`ARC`/`TURN` 两种动作**快速来回切换**。

因此**允许并预期**出现：

```text
开始 ARC → 障碍物距离突然恢复安全范围 → 仍继续 ARC 一小段时间 → 280 ms 到期 → 重新判断 → 恢复正常
```

> ✅ 这是 C17 的**有意行为**，**不是需要立即修复的 bug**。

---

## 5. 紧急停车优先级（**不得为了"保持 280 ms"而屏蔽**）

`< 5 cm` 属于紧急状态，判据在保持窗口**之前**：

```text
AV_ARC / AV_TURN → 距离进入 <5 cm → 立即 AV_HOLD → 停车
```

> ★ 这是当前避障逻辑的**重要安全优先级**，任何后续修改都不得破坏。
> 同理：**车头红外触发也是立即的**（它比超声波更靠前）。

---

## 6. 静止状态保护（**不得删除或弱化**）

代码中存在针对 `cur_act == ACT_STOP`（车本来就停着）的保护，目的：

> 小车已停止时，避障逻辑**不能因为检测到"距离安全"就自行把车重新启动**。

**特别禁止**出现：

```text
小车停止 → 超声波检测安全 → 避障模块自动执行 FORWARD
```

（实现上体现为：`av_gate()` 的"保持"分支与"分档"分支**都**先判 `if (cur_act == 0) return;`。）

---

## 7. 倒车逻辑（**不要为了简化状态机而删除倒车分支**）

`av_gate()` 里对 `cur_act == ACT_BACK` 有专门分支：
倒车时**不得被前向超声波逻辑改写成前进/右转**（超声波朝前，倒车时读数没有意义）。

---

## 8. `cur_act` 的现状（**本阶段不重构**）

`cur_act` 目前同时承担：当前用户动作 / 正常运动状态 / 避障判断依据 / 录制动作 / 播放动作 / 电机输出的部分依据。

> 这种设计**并不理想**，但目前**没有证据**证明它已经导致实际功能错误。

⇒ **当前阶段不要为了"代码结构更漂亮"而重构 `cur_act`。**
若未来确实要改，**单独建立任务**「重构动作状态变量」，并做**完整回归**；**不得在普通功能修改中顺便重构**。

## 9. 超声波模块（**冻结**）

现阶段**不要求也不允许**在没有验证的情况下修改：

* ❌ Timer ISR
* ❌ 超声波测距状态机
* ❌ 测距时序（含 60 ms 节流）
* ❌ 共享变量（`us_last_d` / `us_last10` / `us_seen` / `us_valid` / `us_st` / `us_wid` …）
* ❌ `us_read()` 的调用机制（非阻塞：主循环只发触发、取结果）

若未来发现明确的超声波数据冲突问题，应**单独分析**方向：
> "超声波数据统一采集 + 多模块读取缓存"

**而不是**直接在 C17 避障逻辑里临时打补丁。
