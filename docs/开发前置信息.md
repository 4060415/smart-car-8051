# 一、工具链与下载

## 1.1 编译：Keil C51 命令行三步

不必打开 µVision，直接用命令行（装好 Keil C51 后，三个 exe 在同一目录下）：

```
A51.EXE  xxx.asm              ->  xxx.obj      （汇编）
BL51.EXE xxx.obj TO xxx.abs   ->  xxx.abs      （链接，打印 Program Size）
OH51.EXE xxx.abs              ->  xxx.hex      （Intel HEX，STC-ISP 能烧）
```

- 链接那一步会打印 **`Program Size: ... code=NNN`** —— 这就是代码体积，**每次都要看**。
- **Keil C51 评估版（未注册）限制目标码 2048 字节**，超了直接链接失败。
  两条推论：① **只算 `code`，不算 `data`**（大数组/缓冲放 RAM 不吃这个额度）；
  ② 卡点在**链接器**，所以是"写到最后才报错"——**所以要边写边量**。
- 评估版还有一条：程序起始地址在 `0x0800`，且不支持浮点。
- 想一键编译，可以把上面三行封进 `.bat` / `.ps1`（Windows 注意：**`.bat`/`.ps1` 里别写中文注释**，
  PowerShell 会把无 BOM 的 UTF-8 当 GBK 读而报语法错；`.asm` 里的中文注释不受影响）。
- ⚠️ **`.asm` 必须存成"UTF-8 无 BOM"**：带 BOM 的源文件会让 A51 在第 1 行报
  `SYNTAX ERROR` + `ILLEGAL CHARACTER`（后面还会连锁报一堆未定义符号）。
  Windows PowerShell 的 `Set-Content -Encoding UTF8` **会加 BOM**，写脚本生成源码时要改用
  `[System.IO.File]::WriteAllText($path, $text, (New-Object System.Text.UTF8Encoding($false)))`；
  记事本另存时选"UTF-8"而不是"UTF-8 带 BOM"。

## 1.2 汇编语言与常用语法

- 用 **A51 汇编**（Intel/Keil 风格）：伪指令 `EQU` / `DATA` / `BIT` / `ORG` / `DB` / `END`；
  指令 `MOV` / `MOVX` / `MOVC` / `DJNZ` / `CJNE` / `SETB` / `CLR` / `JB` / `JNB`。
- 中断向量用 `ORG` 摆在开头，例如：
  ```
      ORG  0000H
      LJMP MAIN
      ORG  000BH          ; Timer0 中断
      LJMP T0_ISR
      ORG  0030H
  MAIN:
      MOV  SP, #60H       ; 栈
  ```
- ⚠️ `SJMP` 和条件跳转的跳距只有 **−128..+127 字节**，代码长了会报
  `TARGET OUT OF RANGE` → 改用 `LJMP`。
- ⚠️ `PUSH` 之后任何一条路径都必须 `POP`，否则栈越用越歪、几十次调用后跑飞。

③ 打开 .hex  ->  点【下载/编程】  ->  ④ 然后给板子冷启动

- 换电脑后 **COM 号会变**，每次在设备管理器里认一下"CH340"那个口。

## 1.4 串口（调试的主要手段）

- 板上用 **`P3.1`(TXD)** 经板载 CH340 转 USB；固定 **9600 bit/s、8 位、无校验、1 位停止（8N1）、无流控**。
- 同一时刻**只能有一个程序占用串口**：下载软件开着的时候串口助手打不开，反之亦然。
- 读不到输出时的三个常见原因：① 下载软件还开着占着口；② 程序那几行打印**已经过去了**
  （先开串口，再给板子复位/重新上电）；③ 选错端口。
- 没有串口助手也能开发：**数码管 + 板载 LED + 蜂鸣器**就是最省事的输出设备
  （很多测试程序就是按"不用串口也能读结果"设计的）。

# 二、硬件接口（写代码要用的电平事实）

## 2.1 引脚

| 端口 | 功能 | 电平逻辑 |
|---|---|---|
| `P0.0`~`P0.3` | L293D `INPUT1~4`（电机方向） | 见 §2.2 |
| `P0.4` / `P0.5` | `ENA` / `ENB`（电机使能） | **高 = 使能**；可 PWM 调速 |
| `P0.6` | 蜂鸣器（S8550 PNP 驱动） | **低 = 发声**；**无源，必须给方波** |
| `P0.7` | 未使用（只有 10 K 排阻上拉） | 写 1 |
| `P1.0` / `P1.1` | 光敏比较器输出（右 / 左） | **见光 = 低；遮住 = 高** |
| `P1.2` / `P1.3` | 超声波 `Echo` / `Trig` | — |
| `P1.4` / `P1.5` | 2 脚接插件，各带 4.7 K 上拉（疑 I²C） | 用途未定 |
| `P1.6` | 网标号 `P16` → 传感底板接插件 | 用途未定 |
| `P1.7` | 图上无连线 | 未使用 |
| `P2.7`~`P2.1` | 数码管 **a b c d e f g** | **共阳：写 0 点亮**；⚠️ **顺序是反的**（a 在最高位 P2.7） |
| `P2.0` | 指示灯 D3 | 写 0 亮；**不是段选** |
| `P3.0` / `P3.1` | `RXD` / `TXD`（下载 + 串口） | 9600 8N1 |
| `P3.2` | 按键 **S4** | **低 = 按下**（10 K 上拉） |
| `P3.3` | **红外接收头 0038 输出** | 空闲高；收到 38 kHz 载波为低 |
| `P3.4` | 按键 **S3** | **低 = 按下** |
| `P3.5` / `P3.6` | 红外反射式探头（左 / 右） | **有反射（白底）= 低；无反射（黑）= 高**，电平稳定 |
| `P3.7` | 未接传感器 | 不用 |

## 2.2 电机：`P0` 输出图案

`b0..b3 = IN1..IN4`，`b4 = ENA`，`b5 = ENB`，`b6 = 蜂鸣器(1=静音)`，`b7 = 1`

| 动作 | P0 图案 | 低 4 位（方向位） |
|---|---|---|
| 停止 | `0C0H` | `00H`（`ENA`/`ENB` 一起拉低 = 断电滑行） |
| 前进 | `0F5H` | `05H`（IN1+IN3） |
| 后退 | `0FAH` | `0AH`（IN2+IN4） |
| 左转 | `0F6H` | `06H`（IN2+IN3，原地） |
| 右转 | `0F9H` | `09H`（IN1+IN4，原地） |

> `ENA`/`ENB` **是 MCU 驱动的**（不是跳线到 VCC）→ **必须显式拉高电机才会转**，也可以用来 PWM 调速。

## 2.3 极性与遥控键值

| 传感器 | 条件 → 电平 |
|---|---|
| 光敏 `P1.1`(左) / `P1.0`(右) | **见光 → 低（0）**；遮住 → 高（1） |
| 红外反射探头 `P3.5` / `P3.6` | **白底（有反射）→ 低（0）**；**黑线 → 高（1）** |
| 按键 `S3` / `S4` | **按下 → 低（0）** |
| 遥控器键值（NEC `cmd` 字节） | 前进 `46H`、后退 `15H`、左转 `44H`、右转 `43H`、暂停 `40H` |

> ⚠️ **名字陷阱**：如果代码里有个开关叫"低电平有效"（例如 `TRACK_ACTIVE_LOW`），
> 要知道这里的"有效"指的是"**看到白底**"——而**"压到黑线"读到的是 `1`（高）**。写判断时别想当然。

## 2.4 数码管与蜂鸣器

- 段码：`bit7..bit1 = a b c d e f g`（**1 = 灭**），`bit0` 给指示灯 D3（1 = 灭）→ 直接 `MOV P2, A` 即可。
- 现成段码（含 D3 灭）：`0=03H 1=9FH 2=25H 3=0DH 4=99H 5=49H 6=41H 7=1FH 8=01H 9=09H`。
- 蜂鸣器**无源 + PNP**：**不给方波就不响**。省事做法：在定时器中断里每几个 tick 翻一次引脚
  （例：100 µs tick 每 5 次翻一次 ≈ 1 kHz），主循环完全不用为它阻塞。

## 2.5 电气约束（会踩的）

- **`P0` 是开漏口**：写 1 只是"放开"，高电平靠板上 10 K 排阻上拉 → 上升沿偏慢，
  **只适合低速开关和低频 PWM**（500 Hz 量级没问题，几十 kHz 就别想）。
- **`P2` 整口被数码管段选占用** → 想用片内扩展 RAM 时，**只能用 `MOVX @DPTR`**；
  `MOVX @Ri` 会拿 `P2` 当高 8 位地址，一访问就把显示打花。
- `PSEN`(29) / `ALE`(30) 未连接，`EA`(31) 拉高（用片内 ROM）—— 正常，不用管。

# 三、资源与约定

## 3.1 定时器与中断

| 资源 | 常用配置 | 说明 |
|---|---|---|
| **Timer0** | **方式 2**（8 位自动重装），`TH0=TL0=`**164** → 92 机器周期 ≈ **99.8 µs** | 做 100 µs 硬件时基；10 ms 节拍 = 计满 100 次 |
| **Timer1** | **方式 2**，`TH1=TL1=`**0FDH**，`SMOD=0` | 串口 **9600** 波特率。**要用它做别的就得放弃串口** |
| `TMOD` | **`22H`** = `T1 方式 2 + T0 方式 2` | 是共用寄存器，改 T0 方式时别把串口带歪 |
| 外部中断 INT0/INT1 | 可选 | 收红外边沿可用 INT1(`P3.3`)；纯轮询也能解码 |
| 串口 | 方式 1，`SCON=50H` | 9600 8N1 |

- 晶振 **11.0592 MHz**（不是 12 MHz）→ 12T 模式下机器周期 **1.0851 µs**；所以 10 ms 节拍实际是 9.98 ms。
- 要做 PWM：用 Timer0 的 100 µs tick 做**软件 PWM**，**20 tick = 2 ms = 500 Hz**，占空比 5% 一档（0~100%）。
- ★ **接口约定**：如果由中断去组装/驱动 `P0`（PWM、蜂鸣器方波），**主循环就不要再直接写 `P0`**，
  只改"方向 / 占空比 / 蜂鸣器"这几个影子变量 —— 否则两边互相踩，电机会乱抽。

## 3.2 存储

| 区域 | 容量 | 说明 |
|---|---:|---|
| Flash（程序） | 8 KB | 评估版编译器限 **2048 B 目标码**（只算 `code`） |
| `DATA`（直接寻址 `30H`~`7F`） | 80 B | 全局变量；`0x20`~`0x2F` 是位寻址区（16 B，可放 128 个位变量） |
| `IDATA`（间接寻址 `80H`~`FFH`） | 128 B | 用 `@R0`/`@R1` 访问 |
| **片内扩展 RAM（`MOVX`）** | **256 B** | 需要大数组/缓冲时用它（`MOVX @DPTR`，见 §2.5） |

> STC89C52RC 标称 **512 B RAM** = 256 B 标准（`DATA` + `IDATA`）+ 256 B 片内扩展。

# 四、各模块的现成做法（省得从零试）

## 4.1 红外遥控解码（0038 + NEC）

- 0038 输出接 **`P3.3`**：**空闲高**，收到 38 kHz 载波时拉低 → 解调出的是"反向基带脉冲"。
- NEC 时序：引导码 低 ≈9 ms + 高 ≈4.5 ms；数据位用"低 0.56 ms + 高 0.56/1.69 ms"区分 0/1；
  32 位 = 地址 + ~地址 + 命令 + ~命令（后两字节互补，可用来自检）；按住不放发的是**重复帧**（引导码 + 短高电平）。
- 实现思路（不用外部中断也能跑）：用一个 **100 µs 的硬件 tick** 做时基，
  **在主循环里轮询 `P3.3` 的电平跳变**并测量高/低持续时间，再按上面的门限判 0/1。
  这样不阻塞、也不用关中断。
- ⚠️ 有些遥控器**不发重复帧** → 想用"按住 = 持续动作"，必须自己加"超时即视为松手"的判定，
  否则执行/记录出来的持续时间是随机的。

## 4.2 超声波测距（HC-SR04）

- `Trig` 给 **≥10 µs 高电平**触发；`Echo` 变成高电平，**高电平宽度 ∝ 往返距离**（约 58 µs/cm）。
- 测宽办法：用 tick 计数（100 µs 一格时精度约 ±1.7 cm）；要更细可用 `Timer0` 方式 1 做 1 µs 级计数，
  但**注意别破坏已经在用的方式 2 时基**。
- ⚠️ **接线坑**：模块自己的脚序通常是 `VCC / Trig / Echo / GND`，
  而板上插座可能是 `1=GND / 2=Echo / 3=Trig / 4=VCC` —— **正好相反，不能直插**，按丝印一根一根接。
- 小技巧：模块会把 Echo 主动拉低、Trig 是高阻 —— 上电后读这两个脚的空闲电平，就能判断线有没有接反。

## 4.3 红外反射式探头（循迹 / 避障）

- 原理：红外发射管 + 接收管；**有反射（白/浅色/近处物体）→ 接收管导通 → 节点被拉低**。
- 实测这两个探头（`P3.5`/`P3.6`）**输出是干净的 0/1**（采样几十次不抖），不需要额外整形比较器。
- 循迹：探头朝下，**白底 = 0、黑线 = 1**。
- 避障：同一对探头**朝前**（装法与朝下互斥 —— **同一对探头不能同时朝下循迹又朝前避障**）。
- ⚠️ 只有两个探头时，**分不清"线在正中"和"完全脱线"**（都是 `00`）→ 必须加超时保护。

## 4.4 数码管 / 按键 / 蜂鸣器 / 电机 PWM

- **数码管**：共阳、段选低电平点亮、段序反（§2.4），直接送段码；D3 可当"在动/在跑"的指示灯。
- **按键**：低电平按下；**必须去抖**（延时 10~20 ms 再确认），并要"松手才认下一次"，
  否则一次按下会触发多次。
- **蜂鸣器**：无源 → 给方波；在定时器中断里翻转引脚，主循环零负担。提示音靠"响多久 / 响几次"区分。
- **电机 PWM**：见 §3.1 的约定（中断组装 `P0`，主循环只改影子变量）。
  低速档可能推不动（有刷减速电机有启动死区）→ **实测最低能转的占空比**，别把 5% 当有效档位。
- **差速转弯**：两轮占空比不同 = 画弧；两轮反向 = 原地转。
  左右轮与驱动通道的对应关系**上板子试一下**再定，最好留个编译开关（如 `LEFT_REVERSE`）方便对调。

## 4.5 引脚/极性不确定时：别猜，写个扫描程序

只读端口的诊断程序非常好写，也很值得写：

1. 先把要观察的端口**全部写 1**（= 放开成输入），其它端口保持安全状态（电机输出写"停"图案）；
2. 主循环里**逐个位读**这些端口，和上一轮比较，**哪位变了就打印/显示哪位**；
3. 用数码管显示"最后变化的那只脚"、用板上 LED 显示"它现在的高低电平"——**不用串口也能读结果**；
4. 另外每 0.5 秒打一行"所有脚当前电平的快照"，便于一次看清全部状态。

用手电筒照/遮光敏、拿白纸和黑胶带过探头、按按键，就能一次把"哪只脚 + 什么极性"问出来。
（本项目的光敏 `P1.1`/`P1.0`、探头 `P3.5`/`P3.6` 的极性和脚位就是这么定下来的。）

# 五、写代码时容易踩的坑

| # | 现象 | 原因 | 对策 |
|---|---|---|---|
| 1 | 电机不转 / 方向不对 | 使能脚是 MCU 驱动的，没拉高；或左右通道搞反 | 用 §2.2 图案；左右不对就加编译开关对调 |
| 2 | 一开 PWM 电机乱抽 | 主循环与中断**同时写 `P0`** | 主循环永不写 `P0`（§3.1） |
| 3 | 数码管整片错位 | 段序是反的（a 在最高位），`P2.0` 不是段选 | 段码按 §2.4 写 |
| 4 | 用片内扩展 RAM 时显示花了 | 用了 `MOVX @Ri` | 改用 **`MOVX @DPTR`** |
| 5 | 红外收不到 | 守着 INT0(`P3.2`)，但接收头接的是 INT1(`P3.3`) | 守 `P3.3`；**通用教程的引脚常与本板不符，以实测为准** |
| 6 | 汇编报 `TARGET OUT OF RANGE` | `SJMP`/条件跳转只有 −128..+127 | 长跳用 `LJMP` |
| 7 | 程序偶发跑飞 | 某条路径 `PUSH` 没配对 `POP`；或中断改了主循环用的寄存器 | 少用 `PUSH/POP`；中断里只动 `ACC`/`PSW` 并保存 |
