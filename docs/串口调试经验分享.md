# 串口调试经验分享（提纲版）

> STC89C52RC · 无仿真器，串口是唯一能看见芯片内部的手段
> 事实源：`docs\正式固件开发记录.md`、`docs\排查_遥控偶发失灵.md`、`firmware\c51\main.c`

## 一、先把串口变成"可关的开关"
- 9600 8N1（`TH1=0xFD`，11.0592 MHz），**1 字符 ≈ 1 ms**
- 四个原语：`put_char` / `prt_str` / `prt_hex` / `prt_hex4`（打时基）
- `DEBUG_UART` 编译开关：关掉变空宏，**0 字节**，源码只有一份（正式版 / `-Debug` 版 / `-Ir` 版）
- 副产品：体积不够时的第一手段——`remote.asm` 里打印占 **368 B ≈ 32%**；关掉省 **434 B**（1508 → 1074 B）

## 二、三个坑（每个一句话）
1. **打印把被测对象弄坏了**：40 字符 42 ms，而一帧 NEC 只有 67 ms → 每帧从中间截断 → **所有键解出同一个值 `2C`**。
   ⇒ 串口占时间、占空间、改时序；怀疑观测手段本身时，**换一种完全不同的手段**（数码管闪两位 + 蜂鸣器，不用串口）交叉验证。
2. **打原始量，不打结论**：把 32 位原始字节全打出来 `! IR rej lo=59 hi=2B a=FF b=00 c=00 d=00`，**连按 5 次完全一致**
   ⇒ 确定性 bug，不是偶发 ⇒ 查出 `RL A` 循环左移永不归零、字节指针不前进。**"一致"比"不同"更有信息量。**
3. **每行带一个单调时基 `T=`**（10 ms 计数，11 分钟才绕回）：`T=` 变小或横幅重现 = 复位。
   **空日志也是证据**：150 秒只有 4 行横幅、0 条键值、0 条拒绝 ⇒ 连下降沿都没等到 ⇒ 问题在硬件，不在固件。

## 三、五条纪律
1. **开关化**：打印包进编译开关，关掉 0 字节
2. **打原始量**：字节、计数、脉宽、时基，不打"我觉得是 XX"
3. **限流**：变化才打 / 0.5 s 一行；打印会改时间行为
4. **先写判据表**：看到 A→结论、看到 B→结论、**什么都没看到→结论**
5. **会互相污染就换无串口手段**：数码管 / 蜂鸣器 / 独立小变体

## 四、收尾一句话
> 串口是唯一能看见芯片内部的眼睛，但它也会遮住一部分视野——
> **会用它是第一步，知道它什么时候在骗你，才是经验。**
