# 智能移动机器人 · 原理说明（v1.1）

> 平台：**STC89C52RC @ 11.0592MHz**（STC89C5xRC 内核 = 8051 兼容，8KB Flash / 512B RAM + 片内 EEPROM）
> 语言：**Keil C51**（工程 `code_v1.0.uvproj`）
> 本文说明**本工程是怎么工作的**：硬件怎么接、外设怎么分、每块功能的原理是什么、关键参数是多少。
> 目录：`application/`（业务逻辑）· `driver/`（器件驱动）· `porting/`（与平台无关的对象/回调层）

## 一、系统总览

### 1.1 信号流

```
        ┌──────────────┐   NEC 编码 38kHz    ┌──────────────┐
        │  红外遥控器   │ ─────────────────► │ 0038 接收头   │──┐ 解调后的基带脉冲
        └──────────────┘                    └──────────────┘  │ (空闲高/载波低)
                                                              ▼
   ┌────────────┐   ┌────────────┐   ┌──────────┐      ┌──────────────┐
   │ 数码管 P2  │◄──│            │   │ INT1(P3.3)│◄─────│ 边沿中断      │
   │ 蜂鸣器 P0.6│◄──│  STC89C52  │◄──┤ 定时器     │      └──────────────┘
   │ 按键 S3/S4 │──►│   主控      │   │ 传感器     │
   └────────────┘   │            │   └──────────┘
                    │            │──►┌──────────┐   ┌──────────┐   ┌──────┐
                    │            │   │ L293D    │──►│ 左电机 M1 │   │ 车轮 │
                    │            │   │ H 桥驱动  │──►│ 右电机 M2 │   └──────┘
                    └────────────┘   └──────────┘   └──────────┘
```

主控采集三类输入（**遥控 / 传感器 / 按键**）→ 在 `app_task.c` 的模式状态机里综合判断
→ 通过统一接口 `SetCCR(左, 右)` 输出两路带符号的 PWM → L293D 驱动两只电机。

### 1.2 软件分层

| 层 | 目录 | 职责 |
|---|---|---|
| 业务层 | `application/` | 模式状态机（`app_task.c`）、电机接口（`app_fans.c`）、显示（`app_disp.c`）、音乐（`app_music.c`） |
| 驱动层 | `driver/` | 器件级：`IR`(遥控)、`Timer0/Timer1`、`Nixie`(数码管)、`button`、`buzzer`、`eeprom`、`OneWire`/`DS18B20` |
| 移植层 | `porting/` | `button_porting` / `buzzer_porting`：把底层引脚/定时器接到对象化的按键与蜂鸣器框架上 |

> 这个"对象 + 回调 + 定时轮询（`xxx_timer_callback`）"的结构是从 STM32 HAL 风格移植过来的
> （见 `buzzer.h` 里的 `BuzzerObjectTypeDef`），所以代码里还留着 `CubeMx`、`ET1` 之类的痕迹。

## 三、定时器与中断：本工程的核心设计

**每个外设配一个定时器，互不干扰**——这是本工程最重要的结构决定。

| 资源 | 工作方式 | 用途 | 中断向量 |
|---|---|---|---|
| **Timer0** | 方式 1（16 位） | **红外 NEC 解码计时**（量引导码与位脉宽） | 不单独用中断，由 INT1 驱动状态机读取 |
| **Timer1** | 方式 1（16 位） | **超声波回波计时**（Echo 高电平宽度） | `interrupt 3`：溢出 = 超时无回波 |
| **Timer2** | 12T，重装 `0xFE33` | **软件 PWM + 系统节拍 + 蜂鸣器/按键轮询** | `interrupt 5` |
| **INT1** | 下降沿触发、高优先级 | 红外接收头 `P3.3` 的边沿中断 | `interrupt 2` |

### 3.1 Timer2 的三个作用（`app_fans.c` 的 `Timer2_Isr`）

重装值 `TH2:TL2 = 0xFE33` = 65075 → 溢出周期 = (65536−65075) × 12/11.0592MHz ≈ **0.5 ms**

每次中断做三件事：

1. **PWM 计数**：`Counter++`，`%10` → 0~9 循环
2. **分频产生系统节拍**：每 10 次中断 → `system_tick++`、`state_machine_timer_cnt=0`
   → **`system_tick` 的周期 = 10 × 0.5ms = 5 ms**（示教/回放的时间戳单位）
3. **轮询回调**：`buzzer_timer_callback()` + `button_timer_callback()`
   → 蜂鸣器发声推进、按键消抖/长按判定**都在中断节拍里做，不占主循环**

### 3.2 为什么这么分

- PWM 需要**稳定且高频**的节拍 → 交给 Timer2（STC 增强定时器，不占 Timer0/1）
- 红外解码需要**微秒级**计时 → 用 Timer0（方式 1 全 16 位，量程足够）
- 超声波回波最长 ~25ms → 用 Timer1（方式 1）+ 溢出中断做超时
- 主循环只做"读标志 → 决策 → 输出"，因此**不会被计时任务阻塞**

### 3.3 中断优先级

`Int1_Init()` 里 `PX1 = 1` → **红外中断设为高优先级**。
理由：红外脉冲宽度最小 560µs，一旦被别的中断拖住就可能判错位；
而 Timer2 的 PWM 中断晚几十微秒无所谓（人眼/电机都看不出来）。

## 四、软件 PWM 调速原理（`application/app_fans.c`）

### 4.1 为什么要 PWM

L293D 是 H 桥：**方向**由 `IN1/IN2`（M1）与 `IN3/IN4`（M2）的高低组合决定；
**速度**则靠"快速通断"——单位时间内导通的比例（占空比）越大，等效电压越高，转得越快。
8051 没有硬件 PWM，所以用定时器中断在软件里"数格子"产生。

### 4.2 怎么产生（10 级）

```
Timer2 每 0.5ms 中断一次:
    Counter = (Counter + 1) % 10          // 0,1,2,...,9 循环

    if (Counter <= CompareL)  →  左桥输出方向电平      ┐
    else                      →  M1A = M1B = 0         ┘ 关断期间两个输入都拉低
    if (Counter <= CompareR)  →  右桥输出方向电平
    else                      →  M2A = M2B = 0
```

- 导通比例 = `(Compare+1) / 10` → **10% 一档**
- PWM 周期 = 10 × 0.5ms = **5 ms → 200 Hz**
- 200 Hz 对直流减速电机足够（远高于机械响应，也不会像几十 Hz 那样抖）

### 4.3 ★ 与"把 PWM 加在 ENA/ENB"的区别

| 做法 | 关断期间 | 电机表现 |
|---|---|---|
| **本工程**：PWM 加在**方向输入** `M1A/M1B`，`ENA/ENB` 常开 | 两个输入都拉低 → H 桥输出短路 | **刹车（制动）**——减速快、电流略大 |
| 另一种常见做法：PWM 加在**使能端** `ENA/ENB`，方向恒定 | 使能关闭 → 输出悬空 | **滑行（续流）**——省电、减速慢 |

两种都合法，本工程选的是"刹车"式，循迹/避障时响应更利落。

### 4.4 统一电机接口：`SetCCR(左, 右)`（**带符号**）

```c
void SetCCR(int8_t ccrl, int8_t ccrr);   // 取值为 -100 ~ +100，超过直接忽略
```

- **符号 = 方向**：正 → 该轮正转；负 → 反转；0 → 见下面的注意点
- **绝对值 = 占空比**：`Compare = |ccr| / 10` → 有效档位是 10 的整数倍
- 一个函数同时表达"两轮各转多快、往哪转"，**差速/原地转都是一次调用**：

| `SetCCR(l, r)` | 左轮 | 右轮 | 车体动作 |
|---|---|---|---|
| `(50, 50)` | 正转 60% | 正转 60% | 直行 |
| `(-50, -50)` | 反转 | 反转 | 后退 |
| `(-60, 40)` | 反转 | 正转 | 原地左转 / 让开障碍 |
| `(10, 80)` | 慢 | 快 | 向右画弧（循迹修正） |
| `(80, 10)` | 快 | 慢 | 向左画弧 |

`MStart()`：开中断 + 两路使能置 1 + 设置初值（上电调用一次）
`MStop()`：两路使能置 0（真正断掉电机）

> ⚠️ **注意点 1（读代码时可能被问到）**：`SetCCR(0, 0)` **并不等于停车**。
> 因为 `ccr=0` 走的是 `else` 分支 → `m_dir = 1`（反转）、`Compare = 0` → 实际输出 **10% 反转**。
> 之所以现场看不出来，是因为 **10% 占空比低于该电机的启动死区**，轮子不转。
> 想真正停车应该用 `MStop()`，或把 `SetCCR` 改成"`ccr == 0` 时强制 `Compare = 0` 且方向位不用"。
>
> ⚠️ **注意点 2**：`MStop()` 里写的是 `ET1 = 0`，但 PWM 实际跑在 **Timer2**（`ET2`），
> 这行是从别处移植残留的、**并不起作用**；真正让电机停下的是 `ENA = ENB = 0`。

### 4.5 速度档 `ccr`

`app_task.c` 里全局 `char ccr = 50`，按键 S3/S4 每次 ±10，越界回绕（>80 → 20，<20 → 80），
所以**可用档位是 20 / 30 / 40 / 50 / 60 / 70 / 80**（≈ 30%~90% 占空比）。
数码管显示 `ccr/10`，即 2~8。

## 五、红外遥控 NEC 解码原理（`driver/IR.c` + `driver/Int1.c`）

### 5.1 物理层

0038 一体化接收头把 **38kHz 调制红外**解调成基带脉冲：**空闲为高，收到载波为低**。
它输出接 `P3.3` = **INT1**。

### 5.2 NEC 帧格式

```
        9ms 低        4.5ms 高        32 位数据（低位在前）           停止位
    ┌──────────┐ ┌──────────────┐ ┌──────────────────────────┐ ┌───────────┐
    │  引导码   │ │   引导码      │ │  地址 8 + ~地址 8 +        │ │  0.56ms   │
    │  (低 9ms) │ │  (高 4.5ms)   │ │  命令 8 + ~命令 8          │ │   低      │
    └──────────┘ └──────────────┘ └──────────────────────────┘ └───────────┘

   每位 = 0.56ms 低 + 高电平（0.56ms → 位 0 ； 1.69ms → 位 1）
   重复帧 = 9ms 低 + 2.25ms 高（按住不放时只发这个，数据不再重发）
```

- **互补校验**：`~地址` 与 `~命令` 必须分别是地址/命令的按位取反，否则判为误码丢弃

### 5.3 本工程的实现路径

**边沿中断 + 状态机 + Timer0 量脉宽**：

```
P3.3 每次下降沿 → INT1 中断
    ↓ 读 Timer0 计数值得出"上一段电平持续多久"
    ↓ IR_State 状态机推进：空闲 → 引导码 → 逐位收 32 位 → 校验
    ↓ 结果写入 IR_Data[4]，置 IR_DataFlag = 1
主循环 app_task_entry() 读 IR_Command 并清零
```

- 用**外部中断**而不是轮询：不占用主循环时间，脉宽抖动也更小
- Timer0 只负责"计时"，中断里做的是"判断"

### 5.4 键值表（`driver/IR.h`，与遥控器码值表一一对应）

| 宏 | 码值 | 宏 | 码值 | 宏 | 码值 |
|---|---|---|---|---|---|
| `IR_POWER` | `0x45` | `IR_0` | `0x16` | `IR_5` | `0x1C` |
| `IR_MODE` | `0x46` | `IR_RPT` | `0x19` | `IR_6` | `0x5A` |
| `IR_MUTE` | `0x47` | `IR_USD` | `0x0D` | `IR_7` | `0x42` |

## 六、超声波测距原理（`app_task.c` 的 `MODE_MANUAL`）

### 6.1 HC-SR04 工作过程

```
Trig(P1.3) 给 ≥10µs 高脉冲
        ↓
模块发出 8 个 40kHz 脉冲，同时把 Echo(P1.2) 拉高
        ↓
Echo 高电平的宽度 = 声波往返时间  →  距离 = 速度 × 时间 ÷ 2
```

本工程代码：

```c
TX = 1; Delay10us(2); TX = 0;        // 发触发脉冲
TR1 = 1; while (RX); TR1 = 0;        // 等 Echo 变低，期间 Timer1 一直计数
Conut();                             // 读 TH1/TL1 换算距离
Timer1 溢出中断: distance_over_flag = 1; RX = 0;   // 超时保护
```

### 6.2 换算与门限

```c
distance_time = TH1*256 + TL1;          // Timer1 计数值（机器周期数）
distance      = distance_time * 2;      // 注释按"1 计数 = 2µs"折算
distance      = distance * 0.17;        // 结果按毫米记
```

> ⚠️ **换算系数要标定**：`×2×0.17` 隐含"**1 个计数 = 2µs**"，那是 **6MHz 晶振**的机器周期；
> 本板是 **11.0592MHz → 1 计数 = 1.085µs**，所以**读数偏大约 1.8 倍**。
> 也就是说：门限 `distance <= 100`（按注释是 100mm）**实际约等于 5~6cm**。
> 建议用卷尺实测 10/20/30cm 标定一遍，把系数改成 `×1.085×0.17`（或直接量出比例）。

### 6.3 ★ 迟滞计数：让避障"稳"而不是"神经质"

直接比较"这一次测到多近"会**抖动**（声波受反射面、气流影响）。
本工程用了一个**饱和计数器** `distance_cnt`（范围 1~10）：

```c
if (distance <= 100 且 没有超时)  distance_cnt++;      // 太近 → 加分
else { distance_cnt--; if (<1) distance_cnt = 1; }    // 够远 → 减分

if (distance_cnt > 10) → 响一声 + SetCCR(-60, 40)     // 连续 10 次"太近" → 后退并转向让开
else if (distance_cnt == 1) → SetCCR(50, 50)          // 回到基线 → 恢复前进
```

**原理**：只有当障碍**持续存在**累计 10 次才触发避让，一次误测不会让车乱动；
障碍离开后计数逐次回落，回到 1 才恢复前进 —— 这就是最简单的**迟滞（hysteresis）**。

## 七、按键：对象化 + 事件回调（`driver/button.c` · `porting/button_porting.c`）

- 每个按键是一个**对象**（`ButtonObjectTypeDef`），带 `id` 和状态；
  `button_register_callback(&button[i], cb)` 注册回调
- 扫描在 **Timer2 的 5ms 节拍**里做：`button_timer_callback()`
  → 消抖、判定短按（`BUTTON_EVENT_PRESSED`）与长按（`BUTTON_EVENT_LONGPRESS`）**都不占主循环**
- 业务侧只需在回调里写"按下时干什么"（`app_task.c` 的 `button_event_callback`）：

```c
case 1（S3）: 短按/长按 → ccr -= 10   (减速)
case 2（S4）: 短按/长按 → ccr += 10   (加速)
       之后统一限幅回绕：>80 → 20；<20 → 80
```

- `last_is_long[]` 用来**吞掉长按之后紧跟的那个短按事件**（否则一次长按会算两次）

## 八、显示与发声

### 8.1 数码管（`driver/Nixie.c`）

- **共阳极**：段码写 **0 点亮**；段选接 `P2.1~P2.7`，且**位序是反的**（`bit7 = a`）
- 段码表（`segment_codes[10]`）：`0x03, 0x9F, 0x25, 0x0D, 0x99, 0x49, 0x41, 0x1F, 0x01, 0x19`
- `Nixie(n)`：直接把段码写 `P2`，然后 `delay(1)` —— **只显示 1 位**，所以不需要扫描刷新
- 当前只用来显示**速度档**（`ccr/10`，2~8）与**歌曲号**（1~4）

### 8.2 蜂鸣器（`driver/buzzer.c`）

- `P0.6` 低电平导通（PNP 管），**无源** → 必须给方波才响
- `buzzer_didi(&buzzer[0], 参数…, 次数)`：**非阻塞**——只在 5ms 节拍回调里推进状态机
- 各模式用**不同的响次数**做提示（切到第几个模式就响几声）→ 不看屏也知道切到哪了

## 九、六种运行模式（`app_task.c` 状态机）

模式用遥控器切换，**切换时统一"停车 + 提示音"**：

```c
IR_START_STOP(0x44) → MODE_AUTO    响 1 声
IR_PREVIOUS (0x40) → MODE_MANUAL  响 2 声
IR_NEXT     (0x43) → MODE_REMOTE  响 3 声
IR_EQ       (0x07) → MODE_LIGHT   响 4 声
IR_VOL_MINUS(0x15) → MODE_LEARN   响 5 声
IR_MODE     (0x46) → MODE_MUSIC ⇄ MODE_AUTO（音乐进出）
```

| 模式 | 名称 | 判据 | 动作 |
|---|---|---|---|
| `MODE_AUTO` | **循迹** | 左右反射探头 `P3.5/P3.6`（压黑线 = 1） | 左压线 → `SetCCR(10,80)` 右修正；右压线 → `SetCCR(80,10)` 左修正；都没压 → `SetCCR(90,90)` 直行 |
| `MODE_MANUAL` | **避障/测距** | 超声波（见第六节） | 迟滞计数触发 → 响 + 后退转向；恢复正常 → 前进 |
| `MODE_REMOTE` | **遥控行驶** | 红外方向键 | `IR_2/3/1/5` = 前/右/左/后，`IR_8` = 停；速度 = `speed[] × ccr` |
| `MODE_LIGHT` | **寻光** | 左右光敏 `P1.1/P1.0`（见光 = 0） | 左亮 → 左转 `SetCCR(0,70)`；右亮 → 右转 `SetCCR(70,0)`；都亮/都暗 → `SetCCR(60,60)` |
| `MODE_LEARN` | **示教回放** | 见第十节 | 录一段动作序列，再按时间自动重演 |
| `MODE_MUSIC` | **音乐** | 见第十一节 | 自动演奏 / 电子琴 / 旋律录制回放 |

## 十、示教 · 学习回放原理（`MODE_LEARN`）

### 10.1 数据结构 —— "动作 + 时长"就是一条记录

```c
struct learn_t {
    uint8_t      move;    // 运动方式：LEARN_STOP/UP/DOWN/LEFT/RIGHT
    unsigned int time;    // 该动作持续的时长，单位 = system_tick (5ms)
};
struct learn_t backup[10];   // 最多 10 段
```

这正是报告里说的**动作单元 = 运动方式 + 持续时间**。

### 10.2 录制（示教）

```
按 IR_7  → learn_start_flag = 1，清空 backup[]，learn_index = 1，last_tick = 现在
按方向键 → 先记"上一段持续了多久"：backup[idx-1].time = system_tick - last_tick
          再记"这一段做什么"    ：backup[idx].move   = LEARN_xx
          last_tick = system_tick（重新起算），idx++
按 IR_9  → 收尾：写最后一段时长，置结束标记，idx 归 1
```

**要点**：时间不是"按键时长的测量"，而是**两次按键之间的间隔**——
每次落笔时，上一条记录的时长才被确定下来。

### 10.3 回放（重演）

```
按 IR_0  → learn_start_flag = 2，last_tick = 现在，idx = 1
每轮主循环：
    若 (system_tick - last_tick) >= backup[idx].time  →  到点了：响一声、idx++、last_tick = 现在
    再按 backup[idx].move 设置 speed[]  →  SetCCR(speed[0]*ccr, speed[1]*ccr)
```

**要点**：回放**不是阻塞式 sleep**，而是每轮主循环比对时间戳——
所以回放期间**遥控仍然能响应、避障/按键也不受影响**（可随时打断）。

### 10.4 局限（报告里可以明说，也可以改进）

- 只有 **10 段**
- 时间戳精度 = `system_tick` = **5ms**
- 记录**存在 RAM**，**掉电丢失**（→ 见下一节的音乐模块，那边把数据写进了片内 EEPROM）

## 十一、音乐模式原理（`app_music.c`，创新功能）

三种玩法，构成 **"示教 → 存储 → 回放"** 闭环：

| 玩法 | 原理 |
|---|---|
| **① 自动演奏** | 内置 4 首曲子（小星星 / 两只老虎 / 欢乐颂 / 生日快乐），循环播放；数码管显示曲目号 1~4 |
| **② 红外电子琴** | 遥控数字键 `1~8` 映射到 do~高音 do，**按下即发声**；数码管显示音阶号 |
| **③ 旋律录制回放** | 把弹奏的**音高 + 时长**写进 **STC89C52RC 片内 EEPROM 第 8 扇区（`0x2E00H`）**，**掉电不丢失**，随时回放 |

### 11.1 发声原理

蜂鸣器无源 → 给对应频率的方波即可：
**音高 → 半周期计数值**：`半周期计数 = 定时器时钟 / (2 × 目标频率)`，
在定时中断里按这个计数翻转 `P0.6`，就得到该音高的方波；换音高就是换这个计数值。
时长用节拍数控制 → 音符 = **(音高, 时长)** 两个量，和动作记录的思路完全一致。

### 11.2 为什么用片内 EEPROM

STC89C52RC 自带 EEPROM（按扇区擦写，512B/扇区）：

| 扇区 | 地址范围 |
|---|---|
| 1~7 | `2000H`~`2DFF` |
| **8** | **`2E00H`~`2FFF`** ← 本工程用这一扇区存旋律 |

- 写之前必须先**擦除整个扇区**（`EraseCommand`），再按字节编程（`PrgCommand`）
- 因为掉电不丢，**关机再开机能回放上次录的旋律** —— 这是比"动作录制"更强的展示点

### 11.3 遥控键位（复用 `IR.h` 的宏）

```
IR_1 ~ IR_8  = 电子琴 do~高音do
IR_POWER     = 自动演奏 ⇄ 电子琴   来回切换
IR_RPT       = 旋律录制 开始/结束
IR_USD       = 回放我录的旋律
IR_PREVIOUS / IR_NEXT = 上一首 / 下一首
IR_MUTE      = 退出音乐模式
```

| 项目 | 数值 | 由来 |
|---|---|---|
| 晶振 / 机器周期 | 11.0592MHz / **1.085µs**（12T） | STC89C52RC |

| PWM 频率 / 级数 | **200Hz / 10 级（10% 一档）** | Counter 0~9 × 0.5ms |
| 速度档 `ccr` | 20~80（步进 10）→ 占空比约 **30%~90%** | `ccr/10` 作为比较值 |
| 系统节拍 `system_tick` | **5ms** | 10 × Timer2 中断 |
| 红外协议 | NEC，引导码 9ms 低 + 4.5ms 高 | 位 0 = 0.56ms 高，位 1 = 1.69ms 高 |
| 红外接收 | `P3.3` → **INT1 下降沿中断**（高优先级） | 0038 接收头 |
| 超声波 | `Trig = P1.3`、`Echo = P1.2`，Timer1 计时 | HC-SR04 |
| 测距门限 | 代码 `distance <= 100`，**实际约 5~6cm**（系数待标定） | 见 6.2 |
| 示教段数 / 时间精度 | **10 段 / 5ms** | `backup[10]` + `system_tick` |
| 旋律存储 | 片内 EEPROM **第 8 扇区 `0x2E00H`** | 掉电不丢 |
| 按键 | S3=`P3.4` 加速、S4=`P3.2` 减速（按下 = 低） | 5ms 节拍扫描 |

## 十三、设计要点小结（答辩时可以这么讲）

1. **资源不打架**：3 个定时器 + 1 个外中断各管一件事（PWM / 红外 / 超声波 / 遥控边沿），
   所以"调速、测距、收遥控、扫按键"能同时进行，互不阻塞。
2. **耗时的事都放到中断节拍里**：按键消抖、长按判定、蜂鸣器发声都由 5ms 回调推进，
   主循环只做"读标志 → 决策 → 输出"，因此**模式切换与回放都能被随时打断**。
3. **一个统一出口管电机**：`SetCCR(左, 右)` 用**符号表方向、数值表速度**，
   差速、原地转、直线都是一次调用 → 上层逻辑极简，也不用担心两个电机写串。
4. **用迟滞抵抗传感器抖动**：避障用 1~10 的饱和计数，而不是单次比较 → 稳定可靠。
5. **数据能掉电保存**：旋律写进片内 EEPROM，实现"示教-存储-回放"闭环。
