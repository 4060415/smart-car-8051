# 二、上电顺序与分级自检流程（每级判据 + 实测结果）

**总原则（原文）**：「**先目视、再静态量、再 USB 上电、最后才用电池**；任何时候发现芯片发烫立即断电」 —— 自检清单 L5。

## 3.2 极性结论汇总（三条硬结论）

| 项 | 结论 | 实测证据（原样照抄） | 出处 |
|---|---|---|---|
| **寻光** | **见光 = 低电平（0）；遮住 = 高电平（1）**，左右两路一致。于是「哪边更亮」⟺「哪边脚是 0」 | 「盖住**左**光敏 → 数码管跳 `2` = `P1.1`；盖住**右**光敏 → 跳 `1` = `P1.0`」；四步表：盖左 `2`/D3 灭（P1.1=高）→ 拿开左侧见光 `2`/D3 亮（P1.1=低）→ 盖右 `1`/D3 灭（P1.0=高）→ 拿开右侧见光 `1`/D3 亮（P1.0=低） | 上机记录 L44、阶段0指南 L66-L89 |
| **循迹** | **有反射（白底）= 低；无反射（黑线）= 高 → 压黑线读到 `1`**；且**电平稳定**，不需要额外整形电路 | 「白纸 → 数码管 `3`（左右都低）；黑色物体 → `0`（左右都高）；两次 D3 都灭 = 电平稳定」；`C`(`P3.7`) 两次都是高，说明它没接传感器 | 上机记录 L45、L70、L89；阶段0指南 L148-L164 |
| **寻光/循迹共用的命名陷阱** | `config.h` 里的 `TRACK_ACTIVE_LOW`（「低 = 触发」）中的「低」指的是「**看到白底**」；**写循迹判断要用 `if (TRACK_L == 1)` 表示「左侧压线」** | 「⚠️ 这就是 `TRACK_ACTIVE_LOW` 这个名字最容易坑人的地方 —— **『压线』要判 `== 1`，不是 `== 0`**」 | 阶段0指南 L161、工作须知 L188-L190、前置信息 L134-L135 |

**寻光算法表（据此写）**：左 `0` 右 `1` = 左侧更亮 → 向左转；左 `1` 右 `0` → 向右转；都 `0` = 正对光源 → 直行/保持；都 `1` = 都暗 → 停车或原地慢转找光（阶段0指南 L93-L98）。

**循迹算法表（据此写）**：`00` 都在白底 → 直行；左 `1` 右 `0` → **向左修**；左 `0` 右 `1` → **向右修**；`11` → 停车或按上次偏差找线（阶段0指南 L167-L173）。
> ⚠️ 但同时注意：**「循迹转向方向（左/右）」本身是存疑项**，见 3.4 与第七节。
