|---|---|

| "检查函数声明、变量类型、C51 编译错误" | 现有代码是 **15 个 Keil A51 汇编源文件**，编译链是命令行：`A51.EXE → BL51.EXE → OH51.EXE`，由 `firmware\*\build.ps1` 封装 |
| "用 Keil 工程编译" | 实际可用的编译命令：`powershell -File firmware\remote\build.ps1`（自动找 `D:\keli\C51\BIN`，产出 hex + `build.log`） |

**这条不是小事，它决定了后面 90% 的工作方式**：C51 的"函数声明/变量类型"检查在这套代码上不适用；
但**编译验证依然可以真实执行**（命令行工具链装好且在跑，`code=` 数字每次都能拿到）。

**语言选择建议：继续用 A51 汇编。** 理由是有实测数字支撑的：正式固件预算 713~938 B（占 Eval 版 2048 B 上限的 35%~46%），
而 C51/SDCC 生成的 8051 代码通常是手写汇编的 2~3 倍，改用 C 很可能**真的撞 2 KB 上限**（见 `docs\代码体积预算.md` 第五节）。
报告里"正式 C 固件"的提法需要相应改成"汇编实现"（或只在非关键模块用 C）。

### 6.2 ❗ 三个真实的技术缺口（会直接卡住功能实现）

**(1) 寻光功能的硬件路径没有闭环（最严重）**

- 追线结果：`P1.1`（DIP40 第 2 脚）的网 **bbox=(2051,1028)-(3284,1378)**，远端正好落在 `(3284,1378)[OUTA]`
  —— 即 **`P1.1` ← `IC3` 的 `OUTA`**，而 `IC3` 这一簇（`IC3`/`LM393`/`W1`/`W2`/`RL1`/`RL2` 坐标 x≈3000~3750）
  正是**光敏电阻那一组**。所以 **`P1.1` 极可能是寻光通道 A**。
- 但 `IC3` 的 **`OUTB`（3380.97,1385.37）落在一根只有 4 段的短网上，去向没追到 MCU**；
  `P1.6` 则通过同名网标号 `P16` 连到传感底板右下角的接插件（`(2938,2007)→(3050,2007)`），**用途未定**。
- **结论：寻光只用得了 1 路（`P1.1`，且未经实测），"左右比较判断光源方向"所需的两路都不确定。**
  → **开工前必须做一次实测**：照 `modtest.asm` 的"扫端口"思路写一个程序，
  用手电筒/遮光分别照左右光敏，看**哪个脚翻转**（重点盯 `P1.1`、`P1.6`、`P1.4`、`P1.5`、`P3.7`）。
  在拿到结果前，寻光模式**不能按"通用 51 小车教程"假定电平**。

**(2) 循迹的黑白极性从未实测**

- `config.h` 只写了 `TRACK_ACTIVE_LOW 1`（节点低 = 触发），来历是"探测过"，但
  **"黑线算触发还是白底算触发"没有实测记录** —— 而循线算法的整个判断方向取决于它。
- → 开工前用白纸/黑胶带在探头下面过一遍，看 `D5`/`D6` 灯和数码管读数（`follow.asm` 就能当显示工具）。

**(3) 录制/回放要用到的三个键，键值未知**

- 报告表 2/表 3 要"录制开始键、录制结束键、回放键、清空键"，目前只有 5 个方向键的键值。
- → 烧 `remote.hex`（会把**任何**键的 cmd 字节打到串口），把遥控器其余键逐个按一遍记下来。

### 6.3 Timer0 / 中断资源现状（与报告表 3 的差异）

| 资源 | 报告怎么写 | 工程实际怎么用 | 影响 |
|---|---|---|---|
| Timer0 | 10 ms 统一节拍 | **方式 2 自动重装，100 µs tick**（`T0_RELOAD=164`），中断里维护 16 位 tick 计数（`remote.asm` 已验证） | 10 ms 节拍 = 数 100 tick，**现成可用**；不用改 |
| Timer1 | — | **串口 9600 波特率发生器**（所有带打印的程序） | ⚠️ 若要拿 Timer1 做 PWM 或超声波计时，**就没有串口调试了** |
| 外部中断 INT0/INT1 | 红外解码用 INT0 | **完全没用**（红外是轮询） | 需要时可以把红外改成 INT1，但**现方案已验证能跑，不急着改** |
| PWM 通道 | `EN` 端 PWM 调速 | **不存在** | 建议：在 Timer0 的 100 µs 中断里做**软件 PWM**（`P0.4`/`P0.5`），不占 Timer1、不影响红外 |

**红外解码与回放互不破坏的原则**：解码是主循环轮询（非阻塞），回放是 tick 驱动的状态机，
两者共用同一个 100 µs tick 计数即可，**不要把回放写成阻塞 delay**。

### 6.4 存储规划（240 B 缓冲）的确认

- **RAM 够**：STC 官方 STC89C52RC = 8K Flash + **512 B RAM**（256 标准 + 256 片内扩展）。
  现有程序最多只用了 25 个 `DATA` 字节（`remote.asm`），`0x30~0x7F` 与 `0x80~0xFF(IDATA)` 大片空闲。
- 240 B 缓冲的放置建议：**整块放片内扩展 RAM（`MOVX @DPTR`）**，或 `IDATA(128) + DATA` 拼。
  ⚠️ 两点注意：
  1. **不要用 `MOVX @Ri`** —— 它拿 `P2` 当高 8 位地址，而 `P2` 整口是数码管段选，一访问就把显示打花；
  2. 片内扩展 RAM 是否**默认可用**（有些 STC 型号要看 `AUXR` 的 `EXTRAM` 位）**没验证过** ——
     建议先写一个 20 行的验证程序：写 `MOVX 0x0000~0x00FF` 再读回比对，通过再用。
- 结论：**报告"240 B / 80 单元 / 3 B 单元"的方案对 STC89C52RC 是合适的**，不需要改设计。

### 6.5 代码体积约束（来自 `docs\代码体积预算.md`）

- Eval 版 2048 B 上限**只算 code、不算 data**，所以 240 B 缓冲不占额度。
- 正式固件预估 713~938 B（35%~46%），余量 1100 B 以上；但**串口调试打印占 368 B**，
  验收固件应把 `DEBUG_UART` 关掉；且必须**写一块、量一块**（每步跑一次 `build.ps1` 看 `code=`）。

### 阶段 1：地基层（复用 + 扩展，风险最低）

1. **`Motor_Set(action, speed)` 统一接口** —— 在 `remote.asm` 的 `MOTOR_SET_ACT` 上扩一个"速度档"参数
   （PWM 占空比表），保留原动作码语义不变 → **老功能不受影响**。
2. **软件 PWM**（Timer0 的 100 µs 中断里做占空比计数，驱动 `P0.4`/`P0.5`）→ 变速 + 不同幅度转弯。
3. **数码管显示层**（反序段码表 + `Display(value)`）+ **蜂鸣器提示层**（`Beep(pattern)`）。

### 阶段 2：架构层（决定后面所有功能能不能干净地加）

4. **模式状态机骨架**：`MODE_MANUAL / RECORD / PLAYBACK / TRACE / AVOID / LIGHT / COMBO`，
   非阻塞、单循环、**停止键最高优先级**，先只挂"手动模式"，编译验证 `code=` 增量。

### 阶段 3：传感模式（每个模式独立一次编译 + 一次上机）

5. 循迹模式（0.2 的实测结论为准）
6. 避障模式（红外反射 `P3.5/P3.6` + 超声波 `P1.2/P1.3`，绕行策略）
7. 寻光模式（0.1 的实测结论为准）
8. 综合模式（优先级：避障 > 循迹 > 寻光）

### 阶段 4：创新功能（课题本体，最后做但最重要）

9. **录制**：3 B 单元写入 / 同动作时长累加 / 满保护 / 蜂鸣器提示 / 数码管显示条数或状态
10. **回放**：10 ms 节拍调度 / 空记录拒绝 / 任意键中断 / 结束自动回手动
11. 回归自测：报告表 5 的 5 项验收（基础遥控、录制正确性、回放一致性、中断安全性、边界条件）

### 阶段 5：收尾

12. 逐项跑报告第十六节的硬件测试优先级表（①电机 → ⑭缓冲区满保护）
13. 生成《开发完成说明》（已实现功能 / 改动文件 / 新增模块 / 录制回放原理 / Timer0 用法 / RAM 与体积 / 编译结果 / 待人工实测项 / 已知问题）

## 九、审计结论（一句话）

**地基（电机/红外/时基/数码管/蜂鸣器）是实的、已验证的、可直接复用；
要新增的是"变速 + 状态机 + 三个传感模式 + 录制回放"；
但开工前有 3 件事必须先在实物上量出来 —— 寻光脚位、循迹极性、剩余键值 ——
否则循迹/避障/寻光的电平逻辑只能靠猜，而本项目的原则是不猜。**

### 6.2 ❗ 三个真实的技术缺口（会直接卡住功能实现）

**(1) 寻光功能的硬件路径没有闭环（最严重）**

- 追线结果：`P1.1`（DIP40 第 2 脚）的网 **bbox=(2051,1028)-(3284,1378)**，远端正好落在 `(3284,1378)[OUTA]`
  —— 即 **`P1.1` ← `IC3` 的 `OUTA`**，而 `IC3` 这一簇（`IC3`/`LM393`/`W1`/`W2`/`RL1`/`RL2` 坐标 x≈3000~3750）
  正是**光敏电阻那一组**。所以 **`P1.1` 极可能是寻光通道 A**。
- 但 `IC3` 的 **`OUTB`（3380.97,1385.37）落在一根只有 4 段的短网上，去向没追到 MCU**；
  `P1.6` 则通过同名网标号 `P16` 连到传感底板右下角的接插件（`(2938,2007)→(3050,2007)`），**用途未定**。
- **结论：寻光只用得了 1 路（`P1.1`，且未经实测），"左右比较判断光源方向"所需的两路都不确定。**
  → **开工前必须做一次实测**：照 `modtest.asm` 的"扫端口"思路写一个程序，
  用手电筒/遮光分别照左右光敏，看**哪个脚翻转**（重点盯 `P1.1`、`P1.6`、`P1.4`、`P1.5`、`P3.7`）。
  在拿到结果前，寻光模式**不能按"通用 51 小车教程"假定电平**。

**(2) 循迹的黑白极性从未实测**

- `config.h` 只写了 `TRACK_ACTIVE_LOW 1`（节点低 = 触发），来历是"探测过"，但
  **"黑线算触发还是白底算触发"没有实测记录** —— 而循线算法的整个判断方向取决于它。
- → 开工前用白纸/黑胶带在探头下面过一遍，看 `D5`/`D6` 灯和数码管读数（`follow.asm` 就能当显示工具）。

**(3) 录制/回放要用到的三个键，键值未知**

- 报告表 2/表 3 要"录制开始键、录制结束键、回放键、清空键"，目前只有 5 个方向键的键值。
- → 烧 `remote.hex`（会把**任何**键的 cmd 字节打到串口），把遥控器其余键逐个按一遍记下来。

### 6.3 Timer0 / 中断资源现状（与报告表 3 的差异）

| 资源 | 报告怎么写 | 工程实际怎么用 | 影响 |
|---|---|---|---|
| Timer0 | 10 ms 统一节拍 | **方式 2 自动重装，100 µs tick**（`T0_RELOAD=164`），中断里维护 16 位 tick 计数（`remote.asm` 已验证） | 10 ms 节拍 = 数 100 tick，**现成可用**；不用改 |
| Timer1 | — | **串口 9600 波特率发生器**（所有带打印的程序） | ⚠️ 若要拿 Timer1 做 PWM 或超声波计时，**就没有串口调试了** |
| 外部中断 INT0/INT1 | 红外解码用 INT0 | **完全没用**（红外是轮询） | 需要时可以把红外改成 INT1，但**现方案已验证能跑，不急着改** |
| PWM 通道 | `EN` 端 PWM 调速 | **不存在** | 建议：在 Timer0 的 100 µs 中断里做**软件 PWM**（`P0.4`/`P0.5`），不占 Timer1、不影响红外 |

**红外解码与回放互不破坏的原则**：解码是主循环轮询（非阻塞），回放是 tick 驱动的状态机，
两者共用同一个 100 µs tick 计数即可，**不要把回放写成阻塞 delay**。

### 6.4 存储规划（240 B 缓冲）的确认

- **RAM 够**：STC 官方 STC89C52RC = 8K Flash + **512 B RAM**（256 标准 + 256 片内扩展）。
  现有程序最多只用了 25 个 `DATA` 字节（`remote.asm`），`0x30~0x7F` 与 `0x80~0xFF(IDATA)` 大片空闲。
- 240 B 缓冲的放置建议：**整块放片内扩展 RAM（`MOVX @DPTR`）**，或 `IDATA(128) + DATA` 拼。
  ⚠️ 两点注意：
  1. **不要用 `MOVX @Ri`** —— 它拿 `P2` 当高 8 位地址，而 `P2` 整口是数码管段选，一访问就把显示打花；
  2. 片内扩展 RAM 是否**默认可用**（有些 STC 型号要看 `AUXR` 的 `EXTRAM` 位）**没验证过** ——
     建议先写一个 20 行的验证程序：写 `MOVX 0x0000~0x00FF` 再读回比对，通过再用。
- 结论：**报告"240 B / 80 单元 / 3 B 单元"的方案对 STC89C52RC 是合适的**，不需要改设计。

### 6.5 代码体积约束（来自 `docs\代码体积预算.md`）

- Eval 版 2048 B 上限**只算 code、不算 data**，所以 240 B 缓冲不占额度。
- 正式固件预估 713~938 B（35%~46%），余量 1100 B 以上；但**串口调试打印占 368 B**，
  验收固件应把 `DEBUG_UART` 关掉；且必须**写一块、量一块**（每步跑一次 `build.ps1` 看 `code=`）。

### 阶段 1：地基层（复用 + 扩展，风险最低）

1. **`Motor_Set(action, speed)` 统一接口** —— 在 `remote.asm` 的 `MOTOR_SET_ACT` 上扩一个"速度档"参数
   （PWM 占空比表），保留原动作码语义不变 → **老功能不受影响**。
2. **软件 PWM**（Timer0 的 100 µs 中断里做占空比计数，驱动 `P0.4`/`P0.5`）→ 变速 + 不同幅度转弯。

### 阶段 2：架构层（决定后面所有功能能不能干净地加）

4. **模式状态机骨架**：`MODE_MANUAL / RECORD / PLAYBACK / TRACE / AVOID / LIGHT / COMBO`，
   非阻塞、单循环、**停止键最高优先级**，先只挂"手动模式"，编译验证 `code=` 增量。

8. 综合模式（优先级：避障 > 循迹 > 寻光）

### 阶段 4：创新功能（课题本体，最后做但最重要）

## 九、审计结论（一句话）

**地基（电机/红外/时基/数码管/蜂鸣器）是实的、已验证的、可直接复用；
要新增的是"变速 + 状态机 + 三个传感模式 + 录制回放"；
但开工前有 3 件事必须先在实物上量出来 —— 寻光脚位、循迹极性、剩余键值 ——
否则循迹/避障/寻光的电平逻辑只能靠猜，而本项目的原则是不猜。**
