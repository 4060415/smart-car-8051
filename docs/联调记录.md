### ★ R14（v23）：**数字键 1/2/3 直接选模式**，**取消遥控上的"模式轮换"**

用户原话："遥控器上 1 2 3 分别映射三个模式，4 的轮换可以取消"。追问后定为：
**只取消遥控那一路，长按 S3 保留**；**1=手动 / 2=寻光 L / 3=循迹 t**。

**改动**：把 `MODE_SWITCH` 拆成两个入口，**共用同一套副作用**（清动作 / 补默认档 / 刷新 `LASTLN` / 刷显示 / 响一声）：

```
MODE_SWITCH（长按 S3）-> 算出"下一个" -> 落到 MODE_GOTO
KEY2MODE（数字键 1/2/3）-> 直接给出目标 -> 也落到 MODE_GOTO
```

| 项 | 变化 |
|---|---|
| 数字键 **1 / 2 / 3** | ★ 新增：**直接选** 手动 / 寻光 `L` / 循迹 `t`（**手动/寻光/循迹下都生效**，所以在 `L` 里按 1 就直接回手动） |
| 数字键 **5**（`1C`，原"模式键"） | ❌ **不再切模式**（`KEY_MODE` 保留定义但已无人使用）→ 变成"不认识的键"（只打印，电机不动） |
| **长按 S3** | ✅ **保留循环切换**（遥控没电/丢失时的后路 —— 这是用户选的范围） |
| 按**当前模式**对应的键 | 只**响一声**、不做动作（避免重复触发切模式那套副作用） |

**⚠️ 码值是推断的，要核实**：`KEY_M1/M2/M3 = 0C / 18 / 5E` 是**按码值表结构推出来的** ——
依据：第 6 行 `08/1c/5a` 已实测确认是数字键 4/5/6（列 1/2/3）→ 数字键区按行排 → 1/2/3 应是第 5 行 `0c/18/5e`。
> **核实只要 30 秒**：烧 `firmware\diag\irdecode.hex`，点一下**数字键 1** → 数码管闪 `0` `c` 即对。
> **认错的后果很轻**：不认识的键只走"不认识的键"分支（**打印 + 电机不动，不会乱跑**）✅

**代价**：`code` 1890 → **1930 B**（+40 B）。

**R14 的上机判据**：
| # | 操作 | 预期 |
|---|---|---|
| 1 | 点一下**数字键 1/2/3** | 数码管分别在 **档位数字 / `L` / `t`** 之间**直接跳**，每次响一声 |
| 2 | 在 `L` 模式里按 **1** | **直接回手动**（不用再循环） |
| 3 | 按**当前模式**那个键 | 只响一声，**模式不变**、车不受影响 |
| 4 | 点一下**数字键 5** | **不再切模式**（按 1/2/3 才切） |
| 5 | ★ **长按 S3** | **仍然循环切换**（S3 后路保留） |
| 6 | ★ **核实码值** | 若按 1/2/3 没反应 → 用 `irdecode` 读出真实码值，我改三行 |

### ★ R13b（v22）：极性不再"猜"，改成**上电自动校准**

**为什么改**：两种写法**都出现"车不动"** ——
| 版本 | 写法 | 用户实测 |
|---|---|---|
| v20 | `JNB`（低 = 检测到） | 车不动 |
| v21 | `JB`（高 = 检测到） | **挡住不响、不挡响** + 车不动 |

v21 的现象说明 **"无反射 = 高"**，也就是说 v20 的 `JNB` **极性本来是对的** ——
那 v20 那次"车不动"就**不该由红外解释**（推测见下）。**与其继续在两个方向上猜，不如让固件自己测**。

**做法**：**上电时读一次 `P3.7`**，把当时的电平当作"**无反射（前面没东西）**"的参考电平，存进 `IR_INV`；
之后 **"检测到" ⇔ 当前电平与参考相反**。判据统一走新的 `IR_DET` 子程序。

```asm
; 初始化（P3 = 0FFH 之后）
            MOV     IR_INV, #0          ; 默认：上电读到高 -> 检测到 = 低
            JB      IR_AVOID, IRC_DONE
            MOV     IR_INV, #1          ; 上电读到低 -> 检测到 = 高
IRC_DONE:

; 判据
IR_DET:     MOV     C,      IR_AVOID
            MOV     A,      IR_INV
            JZ      IRD_INV0
            RET                         ; IR_INV=1：高 = 检测到
IRD_INV0:   CPL     C                   ; IR_INV=0：低 = 检测到
            RET
```

**这样得到两个性质**：
1. **不管硬件是哪种极性，都自动正确** —— 不用再改代码 ✅
2. ★★ **最坏情况只是"红外这一项失效"，绝不会再把车锁死** ✅
   （上电时若车头正好贴着东西 → 校准把"有反射"当成"无反射" → 红外不触发 → **失效方向是安全的**）

**★ 使用前提（要记住）**：**上电时车头 1~2 cm 内不要有东西**（正常摆放就是如此）。

**⚠️ v20 那次"车不动"的推测**：既然 v20 的极性是对的，那它可能**不是红外造成的**。
最可能的是：**当时超声波是拔着的**（做我建议的"单通道隔离"），而**悬空的 Echo 拾到噪声**
→ 被当成一个窄回波 → 误判"太近" → 刹停锁存。**这正是我当时提醒过的干扰源。**
→ 建议：**插好超声波再测一次**，用来区分这两件事。

**代价**：`code` 1870 → **1890 B**（+20 B）。

### R1（用户需求）：模式循环**回到手动档时不要停车**

原行为：回手动 = 停车 + 显示档位、不自动前进（`MODE_SWITCH` 1306~1310 行）。
用户要求：绕圈回到手动档时**运动不断流**，保持继续走。

**实现**（`car_asm.asm` 1300~1324 行）：回手动时不再无条件停车，改为**按当前档位继续前进**；
档位 0 时照旧停。
★★ **同时把 `CURACT` 一起置上**（前进时 `ACT_FORWARD`、档位 0 时 `ACT_STOP`）——
因为 `AV_GATE` 用 `CURACT != 0` 判断"本来就在动"，漏了这句就会变成"**车在走却完全不避障**"。

**为什么实现成"继续前进"而不是"照搬切换前的动作"**：
1. 手动模式的既有语义本来就是"档位非 0 = 前进"（块① `APPLY_GEAR`），这样最自洽。
2. 若照搬切换前的动作，**循迹时恰好在转向**的话，回手动后会**一直原地转**；
3. 而且转向会被 `IR_HOLDCHK` 的 300 ms 松手超时（**只豁免前进/后退**）立刻停掉，
   反而达不到"不停车"的目的 —— 见 `car_asm.asm` 390~428 行。

**R1 的上机判据（待验）**：循迹中（车在线上走着）长按 S3 绕一圈回到手动档 →
① **车应保持前进、不停**；② 此时手挡车前 <20 cm，**应仍能右转避让**（这条验 `CURACT` 没漏）。

## 0.2 R2（用户需求）：避障**只在手动 / 寻光触发，循迹不参与**

原行为：块⑥ 是**全局闸门** —— 任何模式下都会测距，并把电机动作强制改写成"右转避让"。
用户要求：**循迹模式不要避障**。

**理由**：循迹时"遇障要转"会和"脱线要停"互相打架 —— 正是清单 **S3** 盯的那个冲突。

**实现**（`car_asm.asm` `AV_GATE`）：判完 `AVOIDON` 之后先比 `MODE == MODE_TRACK`，是就清 `AVBLK` 后 `RET`。

**★★ 关键：跳过时必须显式清 `AVBLK`。** 全程序**只有 `AG_FREE` 一处**会清零它（约 1533 行），
直接 `RET` 会让 `AVBLK` 永久卡在 1 → `MOTOR_SET_ACT` 把循迹的**每个动作都改写成右转**
→ **车会一直原地转，循迹彻底废掉**。

**★ 写成"排除循迹"的黑名单，而不是"只准手动/寻光"的白名单**：将来加 ⑦⑧ 回放模式时它天然带避障，
正好对上报告要求"**回放中前方检测到障碍 → 立即中断回放并停车**"。
（注意：回放要求的是"**中断并停车**"，与现在块⑥ 的"**转向避让**"语义不同 → ⑦⑧ 得单独实现。）

**代价**：`code` 1622 → **1631 B**（+9 B）。

**R2 的取舍（报告里要写成"设计选择"，别当成遗漏）**：
⚠️ **循迹模式下遇到障碍车不会躲**，会继续按循迹逻辑走，或按"脱线"处理停车。

## 0.3 R3（用户需求）：避让加一档 —— **太近则刹停，之后由遥控决定**

用户原话："避让模块加入新功能，如果障碍物太近则刹停，**由遥控来决定**"。

**块⑥ 从单档变两档（+锁存）**，实现为 `AVST` 四态（原来 `AVBLK` 只有 0/1）：

| `AVST` | 名字 | 含义 |
|---|---|---|
| 0 | `AV_FREE` | 放行：不介入，并把原动作重新套上 |
| 1 | `AV_TURN` | **近区**（10~21 cm）：动作一律改写成"**原地右转避让**"（不刹车） |
| 2 | `AV_HOLD` | **太近**（<10 cm）：**刹停 + 锁存**，车不动，决定权交给遥控 |
| 3 | `AV_HUMAN` | **遥控已接管**：完全放行；等距离回到 ≥10 cm 后自动回 `AV_FREE` |

**三个参数（用户拍板）**：
1. **"太近"门限 = `US_STOP = 6` tick ≈ 10 cm**（原先只有 `US_NEAR = 12` tick ≈ 21 cm）
   —— 只能取 1.72 cm 的整数倍，且 HC-SR04 最小量程约 2 cm。
2. **刹停后遥控全权接管**：连"前进"（朝障碍方向）也照常执行 —— 这是用户的选择。
3. **锁存**：刹停后车**保持停住直到遥控给指令**；**障碍自己移开也不会让它重新动**。

**实现要点**：
| 位置 | 改动 |
|---|---|
| `AV_GATE` | 三档判定 + `AV_HOLD` 时**提前 `RET`**（不测距、不介入，车保持停，等遥控） |
| `MOTOR_SET_ACT` | 按 `AVST` 四态分派：`AV_TURN`→改写右转，`AV_HOLD`→**强制刹停**，`AV_FREE`/`AV_HUMAN`→按原动作 |
| `MOTOR_SET_ACT` 的 `MSA_HOLD` | ★ **同时把 `CURACT` 清 0** —— 否则寻光/循迹每趟都会把 `CURACT` 设回动作码，车虽然停着但 **D3 会误亮"在动"**（P4 同类） |
| `DO_KEY` 入口 | ★ **任意遥控键一按，`AV_HOLD` → `AV_HUMAN`**（就地接管）。放在最前面，所以方向/停止/加减档/模式键都算"人来接管" |
| `APPLY_GEAR` | ★ `AV_HOLD` 期间**本地加档也不许把车开起来**（只更新档位显示）—— 锁存的语义是"决定权在遥控手里"，只有遥控能解 |
| `AV_GATE` 刹停时 | 响**一声**提示"太近，刹停了"（数码管没有避障指示，靠听） |

**代价**：`code` 1631 → **1699 B**（+68 B）。

**⚠️ 有意的行为（不是 bug，测的时候别误判）**：
1. **车静止时手凑近 <10 cm 也会进入刹停锁存并响一声**（不区分车在不在动）。此后**板载 S3/S4 加档不会驱动车**，必须按遥控才动。
   —— 若觉得"上电时车前有东西就锁存"很烦，可改成"只在车在动时才锁存"（`AV_GATE` 里加一处 `CURACT` 判断即可）。
2. **锁存期间障碍自己移开，车不会自己走** —— 这正是"由遥控来决定"。
3. **寻光模式下锁存也成立**：`LIGHT_STEP` 照常算它的动作，但 `MOTOR_SET_ACT` 在出口把车刹住（显示上的 D3 也是灭的）。

**R3 的上机判据（待验）**：
| # | 操作 | 预期 |
|---|---|---|
| 1 | 手动，遥控前进，手从远处缓慢靠近 | 21 cm 左右开始**右转避让**（不刹车） |
| 2 | 手继续靠近到 <10 cm | **刹停 + 响一声**；车不再转、不再走 |
| 3 | 手拿开（车别动它） | **车仍然停着**（锁存，不会自己恢复前进） |
| 4 | 按遥控「前进」 | **车照常前进**（遥控全权接管）；若手还在 <10 cm 也**不会**再被刹停 |
| 5 | 先把车停住，手凑到 <10 cm、再拿开 | 第 2 步响一声、锁存；短按 S3 加档**车不动**（只换档位显示） |
| 6 | 锁存时长按 S4 关避障 | 锁存被清（`AV_GATE` 走放行分支），车恢复听遥控/按键 |
| 7 | 回归：`t` 循迹模式 | 仍然**完全不参与避障**（R2 未被 R3 破坏） |

## 0.4 R4（用户需求）：**手动（遥控）模式去掉"自动转向避让"**，只留太近刹停 + 手动接管；蜂鸣器给反馈

## 0.5 R5（用户需求 / bug 修复）：**刹停后"遥控能手动前进"原来根本走不通**

用户原话："手动模式下小于 10cm 刹车后，遥控可手动前进" + "**区分一下是按住前进，不锁定**"。

### 发现的 bug（v7 及以前）

`IR_FULL`（完整帧）里有一句**同键去重**：

```asm
CJNE  A, LASTCMD, IR_NEWKEY   ; 键值不同 -> 当新键
LJMP  IR_HOLDCHK              ; ★ 同一个键 -> 直接跳走，DO_KEY 根本不执行
```

**后果**：前进是锁定式 → 按一下 `LASTCMD = 0x46` → 车一直走 → 太近刹停（`LASTCMD` 没被清）
→ **再按「前进」，键值还是 `0x46`，被当成"重复帧"直接跳过** → `DO_KEY` 不执行
→ `AV_HOLD` **永不解除** → **车不动**。
（要绕过去得先按一个别的键 —— 这显然不是用户要的。）

### 修法（v8）：用 `IRSTAT` 把"还按着"和"重新按下"区分开

关键洞察：**重复帧到不了 `IR_FULL`** —— 它走的是上面 `IRSTAT == 3` 那条路。
所以能进 `IR_FULL` 的**必定是"刚按下去"的完整帧**。

```asm
IR_FULL:
            ACALL   STAMP_NOW
            MOV     A,      AVST
            CJNE    A,      #AV_HOLD, IR_DEDUP
            SJMP    IR_NEWKEY         ; ★ 锁存中：完整帧 -> 跳过同键去重，当新键处理
IR_DEDUP:
            MOV     A,      IB2
            CJNE    A,      LASTCMD, IR_NEWKEY
            LJMP    IR_HOLDCHK        ; 正常情况：同键的重复帧不重复动作/打印
IR_NEWKEY:
            MOV     A,      IB2
            MOV     LASTCMD, A
            ACALL   DO_KEY
```

（`MOV LASTCMD, A` 改成 `MOV A, IB2` + `MOV LASTCMD, A`，因为新分支进来时 `A` 不是 `IB2`。）

> ★ **后续简化（v11 / R8）**：上面这个"锁存期间特判"**已被删掉** ——
> 直接把**同键去重整段删除**效果相同、还更干净（而且省 15 B）。见 **0.8 节**。
> R5 要的功能（"松开再按"能解除锁存 / "按住不放"不能）**完全不变**。

### 修好之后的行为（**这就是"区分"的意义**）

| 用户操作 | 遥控器发什么 | 固件行为 |
|---|---|---|
| 刹停后**松开、重新按下**前进 | **完整帧**（`IRSTAT=0`） | ✅ 解除锁存 + 执行 → **车前进** |
| 刹停后**一直按着不放**（从未松手） | **重复帧**（`IRSTAT=3`） | ⛔ **不解除**锁存（车保持停）—— 防"撞停后自动又冲出去" |
| 刹停后按**别的键**（后退/左转/停止…） | 完整帧 | ✅ 同样解除锁存并执行 |

**代价**：`code` 1746 → **1755 B**（+9 B）。

**待定（等用户拍板）**：接管后的「前进」是
- **A** 保持全局的**锁定式**（按一下就一直走，直到「停止」/别的键）—— 与 7.7 定稿一致；还是
- **B** 改成"**按住才走、松手就停**"（不锁定）—— 更安全，但要为"接管后"单独记一个状态。

> ✅ **用户已选 B** → 实现见 **0.6 节（R6，v9）**。

## 0.6 R6（用户需求）：接管后的「前进/后退」改成**"按住才走、松手就停"**

用户在"锁定式 / 按住式"之间选了 **B（不锁定）**。

**落点很省 —— 不需要新增变量**：`AVST == AV_HUMAN` 本身就是
"**锁存已被遥控解除、但还没脱离 ≤10cm 危险区**"的标志（距离回到 ≥ `US_STOP` 才变回 `AV_FREE`）。
拿它当"危险区"判据即可。

```asm
IR_HOLDCHK:
            MOV     A,      CURACT
            JZ      IR_KEYSCAN          ; 本来就在停
            MOV     A,      AVST
            CJNE    A,      #AV_HUMAN, HC_LOCK
            LJMP    HC_TMO              ; ★ 接管中 -> 不豁免，直接判 0.3s 超时
HC_LOCK:
            MOV     A,      CURACT
            CJNE    A,      #ACT_FORWARD, HC_NF
            LJMP    IR_KEYSCAN          ; 正常：前进锁定式
HC_NF:
            CJNE    A,      #ACT_BACK, HC_TMO
            LJMP    IR_KEYSCAN          ; 正常：后退锁定式
```

**效果（语义很顺）**：
- **在障碍物旁（危险区，`AV_HUMAN`）**：前进/后退**按住才走，松手约 0.3 s 就停** —— 不会一松手就冲出去；
- **一旦离开危险区**（距离 ≥ 10 cm → `AV_FREE`）：恢复正常**锁定式**（按一下就一直走）；
- 左转/右转**本来就是**按住才转，不受影响。

**⚠️ 注意**：这段**同样作用于「后退」** —— 危险区里后退也变成按住式。理由一致（贴着障碍物时别一松手就跑）。
若只想改前进，去掉 `HC_LOCK` 那个判断即可。

**代价**：`code` 1755 → **1765 B**（+10 B）。

**R6 的上机判据**：
| # | 操作 | 预期 |
|---|---|---|
| 1 | 刹停后**松开→重新按「前进」并按住** | 车前进 |
| 2 | **松开**前进 | 约 0.3 s 后**停**（★ 与常态"锁定式"不同） |
| 3 | 按住「后退」退到 **≥10 cm 外**再松手 | 此时再按前进 → **恢复锁定式**（按一下就一直走） |
| 4 | **常态**（没触发过刹停）按一下前进 | ✅ 仍是**锁定式** —— 块② 的既有行为没被动 |

## 0.7 R7（用户需求）：**寻光模式"过近"不刹车，而是退回手动模式**

用户原话："寻光模式不要手动模式的过近刹车，过近退回手动模式"。
追问确认：**方案 A（只退回手动，不刹车、不锁存、不响）** + **切换时响一声提示**。

**改动**：只动 `AG_HOLDNOW` —— 原来这里不分支，一律"刹停 + 锁存"。现在按模式分岔：

| 模式 | `<10 cm` 触发时 |
|---|---|
| **手动** | 照旧：`AVST = AV_HOLD` → **刹停 + 锁存 + 间歇响**（R3/R4 不变） |
| **寻光** | ★ **`MODE = MODE_MANUAL`（退回手动）+ `AVST = AV_HUMAN`** → 停车、**不锁存、不间歇响**、响一声提示 |

**★ 为什么用 `AV_HUMAN` 而不是 `AV_HOLD`**：`AV_HUMAN` 在 R5/R6 里已经定义为
"**已交给遥控 / 放行**"状态 —— 它天然满足 R7 要的全部性质：
- 不锁存（`MOTOR_SET_ACT` 放行，`AV_GATE` 不重复触发）；
- 不间歇响（间歇响只发生在 `AV_HOLD` 期间）；

**结果**：寻光过近 → 数码管从 `L` **变回档位数字**（＋响一声）→ 车停下、控制权交还给人。
之后按遥控前进就能走（且因为是 `AV_HUMAN`，按 R6 是"**按住才走**"）。

**代价**：`code` 1765 → **1786 B**（+21 B，含下面那个跳转改写）。

**★ 顺带修了一个编译错误（踩到文档里记过的坑）**：
加完 R7 后 A51 报 `ERROR #A51 LINE 1609: TARGET OUT OF RANGE` ——
**`AV_GATE` 开头那条 `JZ AG_FREE` 要跳到函数最末尾，被新代码推出了 ±127 字节射程**。
按 `正式固件开发记录.md` 第 42 行记的老规矩改成"**反向短跳 + `LJMP`**"：
```asm
            JNZ     AG_ON
            LJMP    AG_FREE
AG_ON:
```

**R7 的上机判据**：
| # | 操作 | 预期 |
|---|---|---|
| 1 | 寻光 `L` 模式下让车走，手靠近到 **10~21 cm** | 仍**原地右转避让**（R4 保留） |
| 2 | 继续靠近到 **<10 cm** | **模式自动退回手动**：数码管从 `L` 变成**档位数字** + **响一声**；车停下 |
| 3 | 此时**按遥控前进** | 车能走（且是"按住才走"，R6） |
| 4 | 对比 **手动模式**下同样操作 | 仍是**刹停 + 锁存 + 间歇响**（R3/R4 没被 R7 影响） |
| 5 | 回归 | 循迹 `t` 仍完全不参与避障（R2） |

**⚠️ 已知交互（待用户决定要不要改）**：
寻光过近退回手动后，`AVST` 停在 `AV_HUMAN`（"放行、等距离回 ≥10 cm"）。
若此时**障碍还在 <10 cm 就再长按 S3 回到寻光**，车会**按寻光逻辑朝障碍走、不再刹停**（因为 `AV_HUMAN` 是放行态）。

**代价**：障碍没挪开时进寻光会被**立刻弹回手动**（连续两次模式切换）。**暂未改，等拍板。**

## 0.8 R8（**用户实测报的 bug**）：遥控**加/减档只能调一次**，必须按一下别的键才能再调

用户原话："遥控加减挡位的时候只能调整一次，需要按一下前进才能继续换挡"。
（同一类症状：**模式键连按也会失效**。）

### 根因：`IR_FULL` 里的"同键去重"吃掉了真按键

```asm
IR_FULL:
            ACALL   STAMP_NOW
            MOV     A,      IB2
            CJNE    A,      LASTCMD, IR_NEWKEY
            LJMP    IR_HOLDCHK          ; ★ 同一个键 -> 跳过 DO_KEY
```

- 按一次数字键 `6` → `LASTCMD = 0x5A`，加一档；
- **再按一次 `6`** → 键值还是 `0x5A` → 被判成"同一个键"→ `DO_KEY` **根本不执行** → **不加档**；
- 按一下「前进」→ `LASTCMD = 0x46`（键值变了）→ 之后按 `6` 又"变成新键" → 才能再调一次。

### ★ 为什么这段去重是错的：**重复帧根本到不了 `IR_FULL`**

`IR_RECV` 靠"**引导码高电平会不会变低**"把两类帧分开（`car_asm.asm` 964~992 行）：

| 遥控器行为 | 判成 | 路径 |
|---|---|---|
| **按住不放** | `IRSTAT = 3`（NEC 重复帧：9ms 低 + 2.25ms 高，之后不再变低） | `JZ IR_FULL` **之前**就 `LJMP IR_HOLDCHK` |
| **真正按下去**（包括再按同一个键） | `IRSTAT = 0`（完整帧） | 进 `IR_FULL` |

所以**能进 `IR_FULL` 的，必定是"完整的、刚按下去的"帧** —— 它不可能由"按住"产生。
**旁证**：7.7 的"左转/右转按住才转"一直工作正常 —— 那正是靠重复帧只刷新时刻、不重发动作实现的，
说明这套区分是可靠的（否则按住就会连发）。

### 修法（v11）：**直接把同键去重删掉**

```asm
IR_FULL:
            ACALL   STAMP_NOW
            MOV     A,      IB2
            MOV     LASTCMD, A          ; 仍记下来（诊断用；已不参与去重）
            ACALL   DO_KEY
```

**副作用检查**（都过）：
- **按住不放** → 仍是 `IRSTAT=3`、到不了这里 → **不会连发**（档位不会一路加到 5 档）✅
- **左转/右转按住才转** → 不受影响 ✅
- **R5 的功能不变**：刹停后"松开再按"（完整帧）能解除锁存；"一直按着"（重复帧）不能 ✅

**顺带清理**：R5 当时加的 `AVST == AV_HOLD` 特判**一并删掉**（不再必要）——
所以这段从"特判 + 去重"简化成了 3 条指令。

**代价**：`code` 1786 → **1771 B**（**反而小了 15 B**）。

**连带修复**：这一改**同时修好了"模式键（数字键 5）连按"** —— 原来连按切两次模式，第二次同样被吃掉。

**R8 的上机判据**：
| # | 操作 | 预期 |
|---|---|---|
| 1 | **连续按数字键 `6`**（一下一下按，不按住） | 档位**一档一档连续加**，每下响一声（原来只能加一次） |
| 2 | **连续按数字键 `4`** | 同样能连续减档 |
| 3 | **按住 `6` 不放** | **只加一档**（不会一路飙到 5 档）—— 这是重复帧被正确拦住的证明 |
| 4 | **连续按模式键 `5`** | 模式能连续切换（原来第二次无效） |
| 5 | 回归 R5：刹停后"松开再按前进" | 仍能解除锁存并前进 |

## 0.9 R9（用户需求）：**弧线转弯**（差速转弯）—— 即文档里的优化项 **O7**

用户原话："你这个只能原地转弯，我想把前进左右两个键分别设为左右弧度转弯"。
追问后定为：**「CH + 左转 / CH + 右转」语义** + **松手回到前进** + **弯度 = 内轮为外轮的一半**。

### ★ 先说清一个硬件事实：NEC 遥控器**一次只发一个键码**

"同时按住 CH 和左转"物理上做不到（遥控器编码器只会送出其中一个键）。
**但需求照样成立** —— 因为 **CH（前进）是锁定式**（按一下就一直走），
所以靠 **`CURACT` 状态推断**就够了：

| 操作 | 行为 |
|---|---|
| 按一下 CH → 车前进；**再按住左转** | **左弧线**（因为此刻在前进） |
| 车**停着**时按住左转 | **原地左转**（原行为**保留**） |
| 弧线中**松开**左转 | **回到前进**（继续直行，不停车） |

→ **不需要新增遥控键**（原先讨论的"另用两个键"方案作废；也已无需实测新键码）。

### 实现（v12）

| 位置 | 改动 |
|---|---|
| 新动作码 | `ACT_ARC_L = 05H` / `ACT_ARC_R = 06H` |
| `MOTOR_SET_ACT` | 命中弧线动作时：`DIRBITS = DIR_FWD`（**两轮都正转**）+ **内轮占空比取自 `HALFTAB`**（= 外轮一半）；外轮仍是当前档位 |
| 新表 `HALFTAB` | 档位 1~5 → `2/4/6/8/10`（对照 `DUTYTAB` 的 `4/8/12/16/20`） |
| `KEY2ACT` | 左/右键：先 `ACALL K_ISFWD`，`C=1` 走弧线，否则**原地转** |
| 新 `K_ISFWD` | 判 `CURACT ∈ {前进, 弧线左, 弧线右}` → `C=1`（用 C 返回，因为 A 要留给动作码） |
| `IR_TIMEOUT` | 松手超时：若原动作是弧线 → **回到 `ACT_FORWARD` 并用当前档位继续走**；其余照旧停车 |

**左右轮映射**：`DUTY_A` = **左轮**（ENA / IN1-IN2）、`DUTY_B` = **右轮**（ENB / IN3-IN4）
—— 由 `DIR_LEFT = IN2+IN3`（原地左转 = 左轮反转 + 右轮正转）推得。⚠️ **这个推导必须实物盖章**（见判据 1）。

**为什么 `K_ISFWD` 把"弧线中"也算作"向前跑"**：按住左转画弧时若**松开再按**，
此刻 `CURACT` 还是 `ACT_ARC_L`；不算进去就会突然掉回"原地转"，手感突变。

**代价**：`code` 1771 → **1866 B**（+95 B）。

### 转弯半径怎么调（★ 2026-09-20 调过两次，**第一次还调反了**）

**半径完全由那张"内轮"表决定**（`car_asm.asm` 的 `ARCTAB`）：

- 内轮**越接近**外轮 → 半径越**大**（弯越缓）；
- 内轮越**小** → 半径越**小**（弯越急）；
- 内轮 = **0** → 这个轮子不走，车**绕着它原地转**（最急的"弧线"）。

## 0.11 R11（**用户实测报的 bug**）：**"前进偶尔会中断"** —— 根因找到了

用户原话："前进偶尔会中断"。追问后确认两条特征：**① 没有响声；② 按住前进不放就能一直走**。

### 这两条特征只可能指向一条路径

前进本来是**豁免 300 ms 超时**的（锁定式），**唯一能让它失效的就是 `AVST == AV_HUMAN`**
（`IR_HOLDCHK` 里那条 R6 分支）。于是：

| 现象 | 解释 |
|---|---|
| **松手 0.3 s 后就停** | `AVST == AV_HUMAN` → 前进丢了锁定豁免 |
| **按住不放就一直走** | 按住时重复帧一直在刷新"还按着"的时刻 → 超时永远不触发 |
| **不响** | `AV_HUMAN` 分支只 `RET`，**不会重复刹停**，所以静默 |

### 为什么 `AV_HUMAN` 一直没清掉

`AV_HUMAN` 要等**距离回到 ≥ `US_STOP`(10cm)** 才自动清除。
而**只要车前方那个读数一直在 10 cm 以下**（台架上很容易是墙 / 盒子 / 显示器），
它就**永不清除** → 前进**从此永久变成"按住才走"**。

> 注：早期应该响过**一声**（首次 `刹停 + 锁存` 的那一下），只是用户没把它和后来的现象联系起来。

### 修法（v16）：让 R6 的"按住才走"**只用一次**

R6 的本意是"**刚被刹停、你要挪开时小心点**"，**不是**"前方有东西就永久改手感"。
所以在**本次动作结束**（松手超时）时把 `AV_HUMAN` 收回 `AV_FREE`：

```asm
IT_APPLY:
            ACALL   MOTOR_SET_ACT
            ACALL   SHOW_STATE
            MOV     LASTCMD,#LASTCMD_NONE
            ; ★ R11：R6 的"接管后按住才走"只用一次
            MOV     A,      AVST
            CJNE    A,      #AV_HUMAN, IT_NORST
            MOV     AVST,   #AV_FREE            ; -> 避障重新武装、前进恢复锁定式
IT_NORST:
```

**修好之后的行为**：

| 情形 | 行为 |
|---|---|
| 前方 ≥ 10 cm | 正常：**前进按一下一直走** |
| 接管那一次（刚被刹停后按前进） | **按住才走、松手停**（R6 保留） |
| 松手/动作结束后 | 回到 `AV_FREE` → **再按前进就是正常锁定式** ✅ |
| 前方**确实**还有 <10 cm 的东西，再按前进 | **响一声 + 刹停锁存** —— 明确、不静默 ✅ |
| 想从"前方太近"里脱身 | ★ **按后退**（R10 后是按住才走）退开 —— 距离增大自然解除 |

**顺带加了"滞回门限"**（`US_CLEAR = 10 tick ≈ 17 cm`）：
刹停锁存的**解除/停响**要退到 17 cm，而不是刚好 10 cm ——
否则读数在 10 cm 上下抖动会让锁存"解除↔又触发"反复跳（表现为反复响 + 手感突变）。

**代价**：`code` 1860（v15）→ **1868 B**（v16）。

**⚠️ 残留（没做，知道就好）**：`US_CLEAR` 只加在"解除"侧。
如果读数**长期卡在 10 cm 附近抖动**，仍可能出现"反复响"（因为**进入**侧还是 10 cm）。
台架测试时的省事办法：**长按 S4 关掉避障**（响一声长=关）。
要根治就得加一个"进入侧滞后"（需多存一个状态字节），**等真出现再说**。

**R10 / R11 的上机判据**：
| # | 操作 | 预期 |
|---|---|---|
| 1 | 按住**后退** → 松开 | 车后退；**松手约 0.3 s 停**（不再一直倒） |
| 2 | 按一下**前进** → 松开 | 车**继续前进**（锁定式不变） |
| 3 | **正常环境**（前方 ≥10 cm）按前进跑一段 | **不会偶尔中断** ✅（这是 R11 要修的） |
| 4 | 手挡到 <10 cm 触发刹停 → 按前进接管 → 松手 | 前进**按住才走**；松手后**再按一次前进 → 恢复锁定式** |
| 5 | 弧线转弯 | 半径 = **v12 与 v14 的中间**（内轮 ≈外轮 40%） |

**★ 失效安全**：`P1` 口悬空时内部弱上拉 → 读到**高** = "没东西" = **不干扰** ✅

| 脚 | `P1.0` | `P1.1` | `P1.4` | `P1.5` | **`P1.6`** | `P1.7` | **`P3.7`** | `P3.5` | `P3.6` |

- 跳 **7** → 改成 `IR_AVOID BIT P3.7`（一行）

### 它**不能替代**超声波（这点报告里要写清）

| | 超声波 | 车头红外（V7/V4） |
|---|---|---|
| 量程 | **5 ~ 21 cm**（已配门限） | **仅 1~2 cm** |
| 作用 | **远距转向避让 / 刹停** | 只兜"**最后 1~2 cm**" |
| 关系 | —— | **冗余/兜底**：超声波在极近处或软目标上可能漏检，红外补上 |

### ★ 最省事的验法：**拔掉超声波做"单通道隔离"**（用户提出，2026-09-20）

**超声波是可拆卸的**（4P 插座）—— 拔掉它，**避障闸门里就只剩红外一个触发源**，
于是**不用先烧 lightscan 就能验红外**：

| 步 | 操作 | 预期 | 不对意味着 |
|---|---|---|---|
| ① | 拔超声波 + 车头**不挡** | 车**照常能走** | 莫名刹停+响 → 红外脚**一直是低**（接错脚） |
| ② | 拔超声波 + 手贴**车头 IR 前 ~1cm** | **刹停 + 响**，手不动 → 每 ≈0.7 s 再响 | **响了 = 红外通道有效** ✅；没反应 → 需 lightscan 定脚位 |
| ③ | 若 ② 是"**贴上不响、拿开才响**" | —— | **极性反了** → 两处 `JNB` 改 `JB` |

**为什么拔掉是安全的**（已核对 `US_READ` 两条路径）：
| Echo（`P1.2`）悬空读到 | 路径 | 结果 |
|---|---|---|
| **高**（P1 内部弱上拉，最可能） | `US_W2` 数到 **12 tick ≈ 1.2 ms** → `JNC US_FAR` | `255` = 够远 ✅ |
| **低** | `US_W1` **2 ms** 超时 | `255` = 够远 ✅ |

→ **两条都不会卡死**，都走失效安全（当"前面没东西"）。

⚠️ **要分清的一个干扰源**：拔掉后 Echo 悬空**可能偶发拾到噪声** → 被当成窄回波 → **偶发**误判"太近"。
判据：**"偶发"而且是"插回去就不犯"** = 悬空 Echo 的锅，**不是红外**。

**R13 的上机判据**：
| # | 操作 | 预期 |
|---|---|---|
| 1 | **先烧 lightscan 定脚位** | 白纸贴车头那对管子 → 数码管跳号 = 那对管子**通到 MCU** |
| 2 | 手动模式前进，把手贴到**车头那对管子前 ~1cm** | **刹停 + 响 + 间歇响**（与超声波 <5cm 同样表现） |
| 3 | 手拿开 | **停响**，但车**仍停着**（锁存，等遥控） |
| 4 | **回归**：正常跑（前方无遮挡） | **不受影响**、不会莫名刹停（悬空/无反射 = 高 = 不干扰） |
| 5 | ★ 若**一上电就一直在响/刹停** | 说明该脚**一直是低** = 接错脚 → 删掉两处 `JNB` 或改正脚位 |

## 3. 发现的问题（按影响排序：跑飞 > 功能错 > 手感差）

### P1（S1）切模式那一瞬间**没有真正刹车**，车是被"模式逻辑"接管的

**现象**：手动前进中长按 S3 切到 `L`，车没有停下；遮住两路光敏后车才停。

**代码根据**（`car_asm.asm`，2026-09-20 核对）：

| 位置 | 事实 |
|---|---|
| `MODE_SWITCH` 第 1302 行 | 进非手动分支只做了 `CURACT = ACT_STOP`，**没有调 `MOTOR_SET_ACT`** → 电机输出保持切模式前的状态 |
| 只有回手动分支（1306~1310） | 才真正调 `MOTOR_SET_ACT`（`R7=0` + `ACT_STOP`）停车 |
| 主循环 303~320 行 | 顺序是 `AV_GATE` → **模式动作（`LIGHT_STEP`/`TRACK_STEP`）** → `IR_RECV`。所以切模式后**下一趟主循环立刻由寻光逻辑重设动作** |
| `LIGHT_STEP` 1339~1351 行 | 两边都见光 → `ACT_FORWARD`；只有一边 → 转向；**两边都没光 → `ACT_STOP`** |

**结论**：`L` 模式下"遮住光敏 = 停"是**照设计走的**（与 `8.1b` 的 F 条"都遮住→停"一致）。
真正和清单预期冲突的是：**进了 `L` 模式车就自己驱动了**——正常室内光下两路都见光 → 车直接按寻光规则直走，
所以看起来像"切模式没刹车/继续窜"。

> ⚠️ **注意**：就算在 `MODE_SWITCH` 里补一句 `MOTOR_SET_ACT(ACT_STOP)`，**观察到的现象也不会变**
> —— 因为下一趟主循环（约 27 ms 内）`LIGHT_STEP` 会立刻重新给出 `ACT_FORWARD`，刹车只存在 27 ms，肉眼不可见。
> 要真正"切模式后先停住、等有光差再动"，得改的是**寻光模式对"两边都见光"的处理**，不是补那句停车。

**这不是块④ 单块的问题**——单测寻光时"两边照亮→直走"就是预期行为。
属于**清单预期（我写 S1 时想要"切模式即停"）与寻光自主性的冲突**，需要拍板：

- 方案 A（改清单，不改代码）：接受"进 `L` 即自主寻光"，把 S1 预期改成"切过去不残留手动方向"。
- 方案 B（改代码）：`L` 模式下**两边都见光不驱动**，要有光差才动 —— 但那等于废掉"两边都照→直走"这条验收项。

**待确认**：需用户复测区分两种读法（见下）。

### P2（预登记，未测）切到循迹 `t` 时车也会自己动最多 0.5 s

**代码根据**：`TRACK_STEP` 在"两探头都白（脱线）"时**先直走找线**，超过 `TRK_TMO`(≈0.5 s) 才停；
而 `MODE_SWITCH` 第 1318~1320 行会 `TICK_GET` 刷新 `LASTLN`，所以那 0.5 s 是**从切模式那一刻重新计时**的。

**后果**：若**不在黑线上**长按 S3 进 `t`，车会自己直走约 0.5 s 再停 —— 和 P1 是同一类现象。
阶段 3 的 S10 要专门盯这个。

### P3（S12）"回手动后车不动"需排除**状态残留/卡死**（待复测）

**背景**：S12 的"车不动"本身是设计行为（回手动不自动前进）。但"不动"也可能是**卡住**——
历史上本项目踩过的坑正是"**被读的变量没在初始化里清零**"（`MODE`、`AVOIDON`、`AVBLK` 都踩过），
若 `AVBLK` 被置位后没复位，`MOTOR_SET_ACT` 会把"动"一律拦掉 → **手动模式按遥控也不走**。

**判别测试**：回到手动档后**按遥控「前进」** → 车必须能走。
- 能走 = S12 ✅ 真通过，`AVBLK`/电机状态没有残留。
- 不走 = ❗ 真 bug（`AVBLK` 或电机输出被 latch），优先级按"功能错"处理。

**状态**：✅ **2026-09-20 复测通过** —— 回到手动档后按遥控「前进」**车能走**，`AVBLK`/电机输出**无 latch**。
故 S12 的"车不动"确认为设计行为（v1 的"回手动不自动前进"），不是卡死。
> ⚠️ 该行为已随后被 **R1** 改掉（见第 0.1 节）：v2 起回手动**不再停车**。P3 的排查结论仍然有效（无 latch）。

### P4（★ **2026-09-20 实物确认 + 已修复（v3）**）手动模式"档位即前进"**绕过了避障闸门**

**实物确认过程**：用户在 v2 上反馈"**在手动模式下避障没了**"。追问答：
① 车是用**短按 S3/S4 调档**（"档位即前进"）驱动起来的；
② `L`/`t` 模式下避障**正常**。
这两条正好就是 P4 静态分析预测的那一组特征（手动模式两条驱动路径里只有 `APPLY_GEAR` 那条绕过闸门，
而 `L`/`t` 每趟都由 `LIGHT_STEP`/`TRACK_STEP` 设 `CURACT`）→ **P4 成立**。

| 代码位置 | 事实 |
|---|---|
| `AV_GATE` 1490~1513 行 | **`CURACT == 0` 就"不主动避让"**（`JZ AG_RET`）—— 靠 `CURACT` 判断"本来在不在动" |
| `APPLY_GEAR` 原 513~539 行 | 直接写 `DUTY_A/DUTY_B/DIRBITS` 让车前进，**从不设 `CURACT`** |
| `ML_APPLY` 原 487~493 行 | 手动模式 + `CURACT == 0` → 走 `APPLY_GEAR`（注释原文"**本地档位就是前进**"） |

**后果**：手动模式用"档位即前进"驱动时 `CURACT` 恒为 0 → `AV_GATE` 判定"本来就没在动"
→ **不测距、不避让、不刹车**。块⑥ 号称"全局闸门、各模式/遥控都抢不过它"，**这条路径把它绕过去了**。
（`AVBLK` 还会被置 1 却没人消费，等下一次遥控方向键时**突然变成右转**。）

**前提核实**：写电机的只有 **`APPLY_GEAR` 和 `MOTOR_SET_ACT` 两处**（grep `MOV DIRBITS|MOV DUTY_A|MOV DUTY_B` 确认），
所以补 `APPLY_GEAR` 一处即可闭环，不存在第三条绕过路径。

**已实施的修法（v3）**：
1. `APPLY_GEAR` 前进分支加 `MOV CURACT, #ACT_FORWARD`；`AG_STOP` 分支加 `MOV CURACT, #ACT_STOP`
   → 恢复"**`CURACT != 0` ⟺ 车在动**"这条不变式。
2. `ML_APPLY` 加一句"**档位 0 一律走 `APPLY_GEAR` 停车出口**"（`JZ ML_GEAR0`）
   → 否则减档到 0 时走 `ML_ACT`，`CURACT` 会留在 `ACT_FORWARD`，**D3 会误亮"在动"而车其实是停的**
   （R1 带来的那个显示瑕疵，一并修掉）。
3. 顺带订正 `car_asm.asm` 1434 行的**过期注释**（原文"强制停车（只刹车、不抢方向）"，
   块⑥ 早已改成"**原地右转避让**"，该注释一度误导排查）。仅注释，不影响 code。

**代价**：`code` 1612 → **1622 B**（+10 B）。

**修复后待上机验证（P4 判据）**：
- 手动模式**短按 S3 加档**让车前进 → 手挡车前 <21 cm → **应原地右转避让**（原来不躲）。
- 档位**减到 0** → 车停且 **D3 灭**、显示 `0`，此时手挡车前**不应自己转起来**。
- 回归：`L`/`t` 模式避障照旧正常；遥控「前进」驱动时避障照旧正常。

### P5（★ **2026-09-20 实物确认 + 已修复（v5）**）循迹左右转向**是反的** —— 且 8.1b 那条"已验证"是错记

### 4.3 设计取舍（报告里按"设计选择"写，别当遗漏）

1. **手动模式 10~21 cm 不自动转向**（R4）—— 只有 <10 cm 才刹停。用户要求"只保留太近刹车"。
2. **循迹模式完全不参与避障**（R2）—— 避免"遇障要转"和"脱线要停"打架。
3. **寻光过近退回手动、不锁存**（R7）—— 与手动的"刹停 + 锁存"有意区分：自主模式该**交还控制权**。
4. **前进/后退锁定式**（块② 定稿）—— 副作用：**遥控没电/超范围时车不会自己停**（风险 4，已知）。
