## 1. 判断标准

这套图**不是**程序的逆向产物，而是设计阶段的工作底稿。所以正确的一致性标准不是
"逐节点等于代码"，而是：

| 允许保留 | 必须删掉 |
|---|---|
| 设计粒度粗于实现（没写门限值、没写变量、把同一步画成两格） | **开发中期才加进去的功能**（图上画了、可设计时并没有打算做） |
| 设计时的抽象概念与代码命名不完全对应 | **会让读者误判"程序不做某件事"的缺口** |
| 时序细节比实现粗（例如"立刻结束"实际差一趟循环） | 同一份文档里两张图**自相矛盾** |

判定"哪些是开发中期才加的"，依据是**设计冻结时的基线功能集**
（`docs\示教创新功能设计冻结.md` §2 明确列出当时已有的入口：
"`S3`（短按加档 / 长按切模式）、`S4`（短按减档 / **长按开关避障**）、
遥控（方向 5 键 + **数字键 1/2/3 直选模式** + 4/6 加减档）"），
以及 `docs\正式固件开发记录.md` §9.8 的 **C1~C16** 与 `docs\联调记录.md` 的 **R9~R14** 改动清单。

⇒ **`S4` 长按开关避障、遥控数字键 1/2/3 直选模式、录制/回放/清空 = 设计基线，保留**；
`R9` 弧线转弯、`R13` 车头红外冗余通道、`C8` 倒车限时、`C9` 超声近距提示音、
`C12` 倒车不响、`C14` 录制中超声不参与、`C15` 录制中前进按住才走、`C16` 弧线改急
—— **全部是设计之后才加的，删除**。

## 2. 本轮实际改动（已执行）

改动固化在 **`tools\_flow_drop_late_features.py`**（纯 ASCII、可重放；每一条都写了"删的是什么、
依据是哪条改动编号"）。改完只动了 **图 2** 和 **图 5** 两张，其余 6 张一字未动。

### 图 2 主循环 —— 删掉 5 项后期功能

| 删除内容 | 依据 |
|---|---|
| 弧线转弯（"松手后：前进继续走，**弧线回直行**，其他停" → "松手后：前进继续走，其他停车"） | `R9`（联调中用户提出） |
| 倒车限时（C8） | `C8` |
| "倒车时超声波不参与" | `C8` |
| 录制中前进"按住才走" | `C15` |
| 板载 `S4` 长按 = 避障开关（设计基线里这是 **S4 的既有功能**，属于"现有入口"而非设计要新加的东西；图上不再单列这一支，只留 `S3` 长按切模式） | 冻结文档 §2 入口清单 |
| 遥控接收结果由"四种情况"简化为三种（去掉"信号不完整 → 记异常"这类后期细化） | 设计粒度 |

### 图 5 避障判断 —— 删掉 2 项后期功能

| 删除内容 | 依据 |
|---|---|
| **整个"车头红外"备用通道**（检测框、判断框、"手动停车 / 寻光退回手动"处理框） | `R13`：车头红外是**后期加的冗余通道**，不在设计基线里 |
| **"倒车时超声波不参与"分支** | `C8` |

保留下来的仍是设计基线的那一套：总开关 → 循迹不参与 → 锁存等遥控 → 测距 → 太近刹停 / 较近右转 / 够远放行。

**改后图 5 的完整口径**（这张图现在的权威描述）：

```
避障判断开始
  → 避障功能打开了吗？   否 → 直接放行，恢复原来的动作，返回
  → 现在是循迹模式吗？   是 → 循迹时不做主动绕障，照常循迹，返回
  → 现在停着等遥控吗？   是 → 车还停着，每隔一会儿响一声提醒；障碍移开后停止响，
                              但仍要等遥控操作；按遥控键后才解除，返回
  → 测一次前方的距离
  → 距离太近了吗？       是 → 车停下并锁存，等遥控接管，返回
                         否 → 已经不远了：解除停车状态，避障重新生效
  → 前方比较近吗？       否 → 距离够远：放行，恢复原来的动作，返回
                         是 → 小车本来就在动吗？ 否 → 本来没动就不管，返回
                                                 是 → 向右转，绕开障碍，返回
```

### 同时修掉的两个"硬伤"（与"保留错误"不冲突）

1. **图 5 两处"是/否"出口原来标反了**：`d1「避障功能打开了吗？」` 的"是"指向"直接放行"、
   `d2「现在是循迹模式吗？」` 的"是"指向"循迹不做绕障"。删掉后期功能后，出口标签与分支语义已经理顺。
2. **图 2 右栏两条分支线原来重叠成一竖**（`x=256` 上跑了两条不同支路），已把"寻光/循迹也收遥控"
   那一支移到 `x=337`、各支路互不重叠。

## 3. 有意保留的偏差（**不要"修"**）

这些是设计先于编码的正常痕迹，保留才像设计底稿。**引用/答辩时以程序为准，不要拿图当规范。**

| 图 | 保留的偏差 | 为什么留 |
|---|---|---|
| 图 1 | "清零这次运行要用到的数据"一句话带过十来个变量；未提超声波状态机复位与触发脚拉低 | 设计粒度，写细了反而像抄代码 |
| 图 2 | 回放分支仍写"不做避障判断，也不扫描按键" | 设计阶段的原始决定（冻结文档 §2.2 就是这么定的）；虽然最终程序在回放里另加了"安全检查"，但那是**回放自己的安全逻辑**，不是走避障闸门，图的口径自洽 |
| 图 2 | "避障判断：测一次前方情况，决定转向避让还是停车" | 比代码粗，但方向对 |
| 图 3 | **没有**画中断里的超声波回波采样状态机 | 该非阻塞状态机是 `C6/C7` 才定的实现手段，设计阶段没有它 |
| 图 3 | "②电机调速 / ③决定通不通电"分成两格（实际是同一分频体里的连续两步） | 设计粒度 |
| 图 5 | 判断顺序与代码仍有差（代码把"车头红外"和"倒车"插在中间；图上没有这两条） | 那两条本来就是删掉的后期功能，图自然没有 |
| 图 5 | "障碍移开后停止响"（代码是"一次遭遇只响 3 声"） | `C13` 后期调音 |
| 图 5 | "距离太近了吗？"只画了两路出口，实际调试时三分支里的"较近→右转"在"前方比较近吗"这一步接上了 | 设计粒度 |
| 图 5 | 三层嵌套菱形是"展开的 if 链"，与代码的复合条件不完全同构 | 设计粒度 |
| 图 6 | "记录条数满了 → 自动结束"其实是在下一趟循环的采样开头收尾 | 结果一致，时序差一趟 |
| 图 6 | 未提"单条时长上限 28 s 拆条"的具体数值 | 设计冻结里写的是 30 s，实现取了 28 s，图不写数值最稳 |
| 图 7 | 未写"再按一次回放键也可退出"（代码支持；设计冻结只要求"停止键/方向键") | `R9` 之后的交互延伸，非设计承诺 |
| 图 7 | 未提"退出时恢复进入前的档位"以外的细节 | 设计粒度 |
