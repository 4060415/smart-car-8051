## C3. 补测创新功能遗留项（**报告点名的优先**）

**前置**：冷启动；车轮**架空**（先架空验动作顺序，再落地验落点）。
★ **录制示教时前方保持畅通**，或**先长按 S4 关掉避障** ——
因为避障在录制时仍会绕障，而**记录里存的是"操作意图"**，两者不一致会让回放看起来"不对"。

| 序 | 项 | 怎么操作 | 判据 |
|---|---|---|---|
| 1 | ★ **T2 相同动作合并** | 按 `7` 录 → 按 `CH` 前进，**中途松开再按**（保持前进不断）→ 再按 `7` 结束 → 按 `8` 回放 | **车不停顿地走完全程**。若合并失败会看到 2~3 段"微停" |
| 2 | ★ **T3 档位不同不合并** | 按 `7` 录 → `CH` 前进 1 s → 按 `6` 加档 → 继续前进 1 s → 按 `7` 结束 → `8` 回放 | **能明显看出速度变化**（第一段慢、第二段快） |
| 3 | **T7b 车头红外兜底** | 回放中把白纸贴到车头对管前 **1~2 cm** | 立即停车 + 响两声；**不绕行** |
| 4 | **T13 长按方向键后松开** | 录制中**按住** `\|◀◀` 约 3 s 再松开 | 松开后约 0.3 s 内记录转 STOP（弧线松手则回前进） |
| 5 | **T9 录满 80 条** | 快速录"前进 0.3 s → 停止 0.3 s"反复，逼近 80 条 | 到 80 条：**自动停录 + 停车**，数码管 `F` + 长响；**已有数据保留**（仍能按 `8` 放这 80 条） |
| 6 | **T12 掉电语义** | 录一段 → **断电** → 上电 | 记录**丢失**（XRAM 掉电清空）—— 与报告口径一致，**别写成"掉电保存"** |

> ⚠️ **1 和 2 是报告表 5 直接点名的验收项**（"连续前进被合并，无冗余条目"），答辩很可能被问，**务必测掉**。

## C4. ★★ 循迹方向 P5 复核（**历史遗留，我建议排最高优先级**）

**为什么单独列一环**：`P5` 是**唯一"改了代码但从来没过实物"**的既有功能
（2026-09-20 曾把它错记成"已按实测翻正"，后来发现反了，改回来之后**用户一直暂缓验证**）。
**成品验收时循迹是要演示的** —— 如果它方向是反的，现场就会"朝远离线的方向转"。

| 怎么做（静态法，不用场地） | 判据 |
|---|---|
| 烧好 → 冷启动 → 长按 S3 进 `t` → **把车放在黑线上，手动把车头往左偏** | 左探头压线 → 车应**向左**修正（把车拉回线上） |
| 同理往右偏 | 右探头压线 → 应**向右**修正 |
| 两个探头都在白纸上（脱线） | 先直走找线；超过约 0.5 s 自动停 |

**依据（几何规则，与会话无关）**：只有**左**探头压线（`10`）= 线在车**左下** = 车偏在线的**右边** → 要**左转**；
只有**右**探头压线（`01`）→ 要**右转**。**与"手感"无关，可以照着推。**

> ⚠️ **报告措辞**：在实物复核之前，只能写"**已按几何规则修正，待上机复核**"，**不能写"已实测验证"**。

## C5. 取报告要的实测数据（表 5）

| 要填的 | 怎么量 | 预期 |
|---|---|---|
| **回放一致性** | 同一段记录**连续回放 3 次**，每次用**手机秒表**量总时长 | 3 次**总时长散布极小**（时长由中断 10 ms 节拍保证，相对误差仅 **−0.17%**） |
| **落点散布 ≤ ___ cm** | 地面上用胶带标**起点**；每次回放前把车摆回标记点，跑完量**终点与上次的偏差** | 现场量、**按实测填**。⚠️ **无编码器 ⇒ 开环，落点散布不会很小，这是方案固有特性，别编数据** |
| **中断安全性 ≤ 20 ms** | 回放中按「停止」/ 方向键 | 立即停（"检测到→停车"实际 ≤ 1 ms；人工键响应 ≤ 主循环周期+解码） |
| **档位 1 能否起步**（风险 6） | 从 0 档逐档加，记录**最低能起步的档位** | 报告里**按实测写**，别声称"1 档就能走"（有刷电机有启动死区） |
| （可选）录制数据核对 | 若想要**精确**的时长误差：我另编一版**串口 dump 80 条记录**的调试固件（不动验收版） | 可得到"记录时长 vs 实测时长"的硬数据 |

> **想要可选那条就跟我说** —— 大概 15 分钟，能给你答辩用的量化证据（"每条时长误差 <1%"这种硬数字）。
