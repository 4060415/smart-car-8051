## 一、代码层：循迹模式下能让车停下来的路径只有 4 条

固件：`firmware/c51/main.c`。★ **下表 H1、H3 两条已在 §五 修掉**（保留供对照）；
排查当时的 `git diff` 显示循迹逻辑此前**未被本地改动**，未提交的改动只有 `duty_tab` 提速
20/40/60/80/100% → **40/55/70/85/100%** 与 `motor_set`/`apply_gear` 的 `-Debug` 打印包装。

| # | 路径 | 代码位置 | 停下时数码管 | 能否自己恢复 |
|---|---|---|---|---|
| **H1** | 循迹脱线超时：两个探头都看不到黑线 ≥ 0.5 s → `ACT_STOP` | `track_step()` L1171-1173（`TRK_TMO_TICKS=4864`） | `t` | ★ **能**：探头再看到线就自己接着走 |
| **H2** | 档位被减到 0：`motor_set(act, gear)` 里 `gear==0` ⇒ 硬停车 | `apply_gear_core()` L947；减档入口 `auto_step()` L2460（遥控误码 `0x08`）、主循环 L2822（板载 S4 短按） | `t` | **不能**，要按 S3 加档 |
| **H3** | ★ **车头红外触发 → `avst` 锁存成 `AV_HOLD` → 之后每条电机指令都被改写成停车** | `av_gate()` L1467 → `ir_brake()` L1330 → 驱动出口 `motor_set_core()` **L827-834** | `t`（`ir_brake` 里特意用 `show_mode`，L1333） | ★★ **不能，循迹模式下无任何自解路径**（见下） |
| **H4** | 非固件：供电带载压降 / 电机驱动过热 / 电机堵转 | —— | `t`（MCU 还活着，按键有反应） | 冷却 / 换电池后能 |

（车头红外之外，超声波在循迹模式下**完全不参与**：`av_gate()` L1476-1479 每趟都把
`avst` 清成 `AV_FREE`。所以循迹模式下出现 `AV_HOLD` 只可能来自**车头红外对管 P3.7**。）

### ★ H3 为什么"锁上就再也解不开"

```
av_gate():
  L1422  if (avoid_off() && avst == AV_HOLD) avst = AV_FREE;   ← 需要"超声波避障关着"
  L1428  if (avst == AV_HOLD) {
  L1430      if (ir_det()) return;                 ← 还贴着 -> 直接返回
  L1436      if (avoid_off() || mode == MODE_TRACK) return;   ← ★ 循迹在这里就返回了，avst 保持 AV_HOLD
             ...（只有手动/寻光的解锁逻辑在后面）
         }
  L1467  if (ir_det()) { ir_brake(); return; }     ← 车头红外：三种模式都刹 + 锁存
  L1476  if (mode == MODE_TRACK) { avst = AV_FREE; return; }   ← ★ 这行"想解锁"，但被上面的早退挡住，AV_HOLD 时永远到不了
```

后果：**车头红外只要有一瞬间（哪怕一个主循环）误触发，`avst` 就永久停在 `AV_HOLD`**，
`motor_set_core()` 从此把每次 `motor_set` 都改成停车 —— 车永久停下、
`track_step()` 照跑、数码管照刷 `t`、**不会自己恢复**。
循迹模式下唯一能解开它的只有：**遥控数字键 5 / 长按 S4**（`avoid_toggle()` L1565 `avst = AV_FREE`），
或切到手动模式后按一次遥控（`ir_do()` L1842 → `AV_HUMAN`）。

> 这条路径与现场三条已知完全吻合：显示仍是 `t` ✔、位置不固定（取决于哪一瞬间误触发）✔、
> 停住不再动（不自己恢复）✔。**H3 是当前第一嫌疑。**

## 四、若 H3 成立：再分一层（车头红外为什么误触发）

1. **复现实验（架空）**：手动模式、轮子离地、档位 3~5 连跑，盯 `! IR=`。
   出现 `IR=1` ⇒ 触发与**电机干扰/振动**相关；一直 `IR=0` ⇒ 只在带载/贴地时触发（光学/反光）。
2. **光学因素**：`ir_det()` 的极性基准是**上电瞬间**读的 P3.7（L1277-1280 注释）。
   ⇒ 上电时车头 1~2 cm 内不能放东西；赛道黑线/白底反光变化、对面强光/日光都可能把 P3.7 翻过去。
   现场检查：停车后把车头对着空气 / 对着白纸 / 对着黑线，看 `! IR=` 是否跟着变。
3. **电气因素**：`P3.7` 与循迹探头 `P3.5/P3.6` 相邻，走线与电机线束并行时最容易被毛刺打到。
   查车头红外与探头的走线、模块供电去耦（就近 0.1 µF）。

## 七、事后复盘：最初失败最可能的原因（**推断，非实测**）

### 能确定的

- 你的现象（**显示一直是 `t`、车在"看着像正常循迹"的状态下停住、位置不固定、里程差不多**）
  只能落在 §一 的 **H1 / H2 / H3**（H4 是供电/驱动，通常伴随掉速或按键无反应）。
- 我改了 **H1 + H3**；**H2（档位被误减到 0）没改** —— 如果现象再出现，先查它（§二 第 3 步）。

### 结构性推断：**H1 的"几何版本"嫌疑最大**

`track_step()` 旧代码里有一条**隐含假设**：

| 探头状态 | 旧代码判成 | 这个判断成立的前提 |
|---|---|---|
| 两个都压线（`11`） | 骑在线上 → **直走** | ★ 探头**间距 < 线宽**，居中时两个探头**都在黑线上** |
| 两个都没压线（`00`） | **脱线** → 直走 0.5 s → **停车** | 同上（居中时不会出现 `00`） |

一旦装法是"**两个探头分列黑线两侧**"（探头间距 > 线宽，线从两探头中间穿过），
**居中跑得最正的状态恰好就是 `00`** ⇒ 车会被判成"脱线"，**在直线段每 0.5 s 就被停一次**；
而在弯道上单侧压线（`01`/`10`）时修正逻辑**方向是对的**，所以看起来"能正常循迹、会跟着弯走"。
⇒ 现象逐条吻合：显示仍是 `t`、位置取决于哪一段"两探头同时落在白底"、里程大体相当。

- 你们文档里**早就写过这个陷阱**（`docs\正式固件开发记录.md` L372-374 原文）：
  *"⚠️ 原文写的是'探头骑在线的两侧'，那是错的：`TRACK_STEP` 把'两个都白'当脱线，
  若真分列两侧，车一上电就会判脱线、0.5 s 后停车。"*
  —— 当时的处理是**要求装成"探头间距 < 线宽"**，而没有改代码。
- ★ **参考工程 `巡线ok` 对这两种装法都能跑**：它把 `00`（`L&&R`）和 `11`（`else`）
  **都判成 `M_Forward()`**。这正是"它可行、我们停"的唯一实质差别 —— 所以我按它改。
- 倾向 H1 而不是 H3 的理由：H1 是**确定性**的（装法如此就每次都在直线停），
  和你说的"每次都会停"更配；H3 要在跑动中 P3.7 出现**瞬时**误触发
  （车静止时实测 `IR=0` 能连稳 42 s，见 `docs\上机验证记录.md`），更"偶然"。

### 10 秒自证（不用工具）：看探头信号灯 `D5`/`D6`

按 `firmware\car\config.h` §6.1：`D5`/`D6` 是**探头信号灯**，接在探头节点上，
**节点为低时点亮**，而本板实测"**有反射（白底）= 低**"。所以：
**灯亮 = 该探头下面是白底；灯灭 = 压到黑线。**

| 把车摆正、两个探头跨在黑线上时的现象 | 结论 |
|---|---|
| **两个灯都亮**（都读到白底 = 居中状态是 `00`） | ★★ **H1 定案**：旧代码把"跑得最正"的状态判成脱线，0.5 s 后停车 |
| **一个亮一个灭** | 探头间距 ≈ 线宽（边缘状态）⇒ 居中时经常出 `00`，**H1 也成立** |
| **两个灯都灭**（居中 = `11`） | 装法符合文档要求 ⇒ H1 只在真丢线时发生，元凶更可能是 **H3** / H2 / H4 |

> ★ 不管属于哪一种，**改动都已覆盖**：新代码里 `00` 与 `11` **都直走**，
> 所以两种装法都不会再"自己停"；而 H3 的锁存也加了自动解锁。
