# 创新功能方向评估（待拍板）

> **这份文件回答一个问题**：这门课的"创新功能"到底做什么最划算。
> 输入包（`docs\创新功能讨论输入包.md`）是给外部顾问看的背景；**这份是我给出的结论与论证**。
> 日期基准：2026-09-20。基础功能 ①~⑥ 已全部上机通过，⑦⑧ 未动一行代码。

## 0. 结论（先看这个）

**主线不变：做「红外遥控动作录制与回放」，但不要照报告原样做一遍，而是升格成
「语义化示教 → 受约束复现」**，用 3 个具体增强点把"照抄官方选项"变成"有论证的创新"。
**同时把已经上机跑通的「超声波定距跟驰」并进正式固件，当第二个创新项**（官方第 4 项"自行构思"）。

理由一句话：**这是唯一一条"报告几乎不用重写 + 全部硬件已验证 + 答辩当场演示得出来"的路。**

## 1. 先看清评分口径 → 什么才叫"划算"

| 项 | 权重 | 创新功能影响它吗 |
|---|---:|---|
| 平时出勤 | 20% | 否 |
| 硬件验收 | 10% | 否 |
| 软件验收（单项） | 30% | 否（这是 ①~⑥，已经稳了） |
| **成品验收（综合、创新）** | **20%** | ★ **主要就是这一项** |
| **试验报告** | 20% | ★ 报告里"创新性分析"那一章 |

两条硬信息：

1. **PPT 原话是"必须完成基本功能和至少 1 种创新功能；多选不限，酌情加分"**
   → **"多选"能加分**。所以最优解不是"憋一个大招"，而是**一个扎实的主线 + 一个便宜的加分项**。
2. **"参加答辩并演示功能"**
   → **当场 5 分钟演示得出来 > 技术多先进**。任何"演示链路长、现场容易翻车"的方向都要扣分。

> 推论：**风险要压到最低，演示要最短路径，创新要靠"论证"而不是"器件"**。

### 2.1 为什么否决 D（两车超车）

需要**两台车 + 车际通信**。手上只有一台，且车与车之间没有任何现成通信链路
（红外是单向遥控、超声是测距）。**硬件层面就不成立**，不是难度问题。

### 2.2 为什么否决 F（沿墙走 / 建图 / 自主探索）

**硬约束**：这块板子上**唯一的连续量是超声波距离**，其余全是二值量（红外反射、光敏、按键）。
**没有编码器、没有陀螺仪、没有摄像头、没有语音。**

- 沿墙走：只有"有/无反射"两档，**给不出角度和距离** → 只能做成"蹭一下修一下"的抖振，做不稳。
- 地图/栅格/自主探索：**没有里程计也没有航向** → 车不知道自己在哪、转了多少度 →
  **纯属不可能**。（这不是"难"，是缺传感器。）

> ⚠️ 这条要写进报告当"设计边界论证"——**能说清"为什么不做"也是加分项**。

### 2.3 关于 C（蓝牙）：先花两分钟翻盒子

已经查到的事实（比输入包里的说法更明确）：

- **教师 PPT 里"扩展范例"专门有一页「功能说明——蓝牙遥控」**（slide 43），
  和「红外避障」「超声波避障」「灭火机器人」并列 —— 说明**这个套件设计上支持蓝牙模块**。
- 已交的《硬件分析报告》里写着："**可选扩展模块**：灭火驱动（L9110＋USB 风扇＋火焰传感器）、
  超声波避障模块、**蓝牙模块**、舵机接口。"

→ 所以**"套件资料里有蓝牙"是确定的**；**"你盒子里那个模块在不在、插哪个口"仍未确认**。

**处置建议**：翻一下盒子，看有没有一个带 4 针排线的小板（通常丝印 `HC-05`/`HC-06`/`JDY-31`），
以及板上有没有对应插座。**有的话不要改主线**——主线已经按录制回放写进报告了，
蓝牙更适合作为**附加演示**（或干脆写进"后续改进"）。**没有就死心，别在这上面耗时间。**

## 3. ★ 推荐路线

```
创新功能 = 主线「语义化示教 → 受约束复现」
         + 加分项「超声波定距跟驰」（已验证，近乎免费）

主线 = A（报告规格的录制/回放）
     + B 里的三个增强：① 可变倍速回放  ② 多段路线库 + 循环  ③ 安全改写（避障优先于示教）
```

### 3.1 为什么"不要照报告原样做"

报告已经把方案写完了，**照做 = 交一份和报告一模一样的实现**，答辩时老师只会问
"这不就是官方第 3 项吗"。增强包的作用是**把报告 3.1 节自己声称的创新点"变成看得见的东西"**：

> 报告 3.1 原话：*"关键不在于保存遥控器发出的原始红外脉冲，而在于把遥控操作转换为
> 机器人能够理解的语义化动作……既降低了存储需求，也使后续更换遥控器编码或增加蓝牙控制时
> 仍可复用同一动作回放模块。"*

这句话现在是**纯论证**。而**"同一段记录用 2 倍速再放一遍"**这一个演示，
就把它变成了**实验事实**——因为存的是"语义动作 + 时长"，**时长可以被缩放**；
如果存的是红外波形，**根本做不到这件事**。这是全场最有说服力的一击。

### 3.2 ★ 最强的免费论据：报告自己承诺了，而我们已经把地基铺好了

课题报告**第 7 节「结论与后续改进」原文**：

> *"后续可增加 24C02 EEPROM 以保存动作序列，加入编码器或循迹传感器以减小因电池电压、
> 地面摩擦和轮胎打滑带来的累计误差，并**可在回放中叠加避障与超时保护机制**。"*

也就是说 **"回放叠加避障保护"是报告自己写下的承诺**。而代码里**已经为它预留好了**：

```asm
; firmware\car\car_asm.asm L107
NMODES      EQU     3       ; 目前实现到 3；后面加综合/录制/回放时改这里 + MODETAB

; L1805  AV_GATE 里（避障闸门）
; ★★ R2：**循迹模式不参与避障**
MOV     A,      MODE
CJNE    A,      #MODE_TRACK, AG_CHK     ; ← 只排除"循迹"
```

> ★ **避障闸门当初是特意写成"排除循迹"而不是"只准手动/寻光"的**，
> 为的就是"将来加回放模式时它**天然带避障**"。**新加的 `MODE_PLAY` 不需要动 `AV_GATE` 一行。**

> ### ⚠️⚠️ **2026-09-20 更正（设计冻结阶段核对代码后）**
>
> 上面这段的**结论是对的**（`AV_GATE` 确实不用改），**但理由是错的**，必须更正：
>
> 当时只想到"回放**有没有**避障"，**没想到避障的语义是什么**。实际代码 `MOTOR_SET_ACT`（L703–712）：
> ```asm
>             DEC     A
>             JZ      MSA_TURN                ; 1 = AV_TURN  近区
> MSA_TURN:   MOV     R6,     #ACT_RIGHT      ; ★ 把动作改写成"原地右转"（不是停车！）
> ```
> ⇒ 避障闸门在 5~21 cm 的动作是「**改写成原地右转绕过去**」。
> 而创新功能要求的是「**遇障立即停车 + 终止复现，不擅自改变路径**」——**两者语义相反**。
> 若让 `MODE_PLAY` 走 `AV_GATE`，会得到**正好相反**的行为（车自己绕开继续跑），
> 这就**毁掉了"复现示教路径"这个定位**（详见 `docs\示教创新功能设计冻结.md` §1.1 冲突 C1）。
>
> ⇒ **正确做法**：回放**根本不进 `AV_GATE`**（在 `MAIN_LOOP` 最前面就跳进独立的 `PLAY_STEP`），
> 自己用 `PLAY_SAFETY` 实现"停车终止"。**`AV_GATE` 依然一行都不用改** ✅
> —— 但这是**"绕开"而不是"继承"**，与上面写的"天然带避障"是两回事。
>
> ★ 答辩口径随之修正：不要讲"回放天然继承避障"，要讲
> **"回放有自己独立的安全策略：遇障终止而非绕行——这正是'复现'与'重新规划'的定义性区别"**。
> 这个说法比原来的更强，也更站得住。

### 3.3 三个创新论据（答辩口径，分层递进）

| 层 | 论据 | 现场怎么证明 |
|---|---|---|
| **编码层** | 不存红外波形，存**语义动作码 + 时长**（3 B/单元）→ 存储省、协议无关，**且时长可缩放** | **同一段记录用 0.5× / 1× / 2× 各放一遍** |
| **执行层** | 复现**不是盲目重放**：示教数据统一走 `Motor_Set` 单一出口，**过一遍避障闸门才生效** → 示教让位于安全 | 回放中伸手挡车前 → 车**立刻停/绕**，不硬顶 |
| **管理层** | 从"一条记录"变成"**路线资产**"：多段路线库 + 选段回放 + 循环回放 +（可选）串口导出 | 录 2 段，按段号选着放 |

## 5. ★★ 开工前必须先定的三个设计决定

这三条**会改代码结构**，所以现在定比写完再改便宜得多。

### 决定 1：**回放计时必须放进 Timer0 中断，不能靠主循环数节拍**

⚠️ **这是本项目最容易做错、而且一做错表 5 的 ±5% 指标就必然不达标的一点。**

- 现状：主循环每趟都调 `IR_RECV`，而它**没有红外信号时最多阻塞 25.6 ms**（等下降沿超时）
  → **主循环周期 ≈ 27 ms**（`基础功能联调与优化清单.md` 风险 1 已记录）。
- 后果：如果回放用主循环数 10 ms 节拍，**误差就是 ±27 ms** →
  一个 100 ms 的动作实际可能跑 127 ms，**误差 27%，远超报告的 ±5%**。
- **正解**：`TICK_L/TICK_H`（100 µs 时基）**本来就在 Timer0 中断里维护**，
  在中断里加一个 10 ms 分频计数器（≈10 B），主循环只读标志位。
  → **时长误差由中断保证**（晶振级精度，±5% 轻松达标）。
- **还要顺手做的事**：回放期间**不能每趟都等 25.6 ms 的红外**，否则**动作切换时刻**
  会有最多 27 ms 的抖动（对短线动作就是大误差）。
  → 回放模式改成**每 N 趟收一次红外 + 缩短收帧限时**（这正好就是优化项 **O1**，本来就要做）。

> 一句话：**时长精度靠中断，切换精度靠缩短主循环阻塞，两件事都要做。**

### 决定 2：**"录制"不该是状态机的一个状态，而应是叠加在手动模式上的一层**

报告表 2 把「手动控制 / 动作录制 / 动作回放 / 安全停止」列成**并列的四个状态**。
但按报告 3.3 的流程，**录制时遥控键仍然要驱动电机**（不然人怎么"开"给车看？）
→ 所以"录制"的实质是 **手动模式 + 一个记录标志 `RECON`**，不是并列状态。

**建议**：
- `RECON`（录制中）= **正交标志位**，叠加在**手动模式**上；
- `MODE_PLAY`（回放中）= **真正的第四个模式**，加进 `MODE_*` 与 `MODETAB`
  （`NMODES 3 → 4`），这样它**自动继承避障闸门**（见 3.2），也能像数字键 1/2/3 一样直选。

> ★ 报告里这一处**要在实现说明里点出来**："状态机按'控制权归属'重新划分：
> 录制是手动模式的叠加，回放是独立模式"。**这是对报告的修正，也是设计深度的体现。**

### 决定 3：**遥控三个功能键的码值——必须先上机核实**

你给的是 **`42` / `52` / `4a`**（= 码值表第 7 行，按行排正好是**数字键 7/8/9**）。

- ✅ 这条**与码值表结构自洽**（第 6 行 `08/1c/5a` 已实测 = 数字键 4/5/6，第 5 行 = 1/2/3）。
- ⚠️ 但**本项目有前科**：`docs\遥控器码值表.md` 的"行↔按键"推断**错过一次**
  （曾推断 `08/1c/5a` 是数字键 7/8/9，实测是 4/5/6）。
- **核实只要 30 秒**：烧 `firmware\diag\irdecode.hex` → 冷启动 → 点一下数字键 `7` →
  数码管闪 `4` `2` 即对。（认错的后果很轻：不认识的键只走"不认识的键"分支，电机不动。）

**待你确认的分配**（我按"7 录 / 8 放 / 9 清"暂定，可换）：

## 6. 诚实的风险清单

| # | 风险 | 说明 | 处置 |
|---|---|---|---|
| **1** | ★ **无编码器 → 开环复现必然有落点误差** | 报告的 表 5 要求"3 次落点散布 ≤ ___ cm，**现场实测填入**"。电池电压、地面摩擦、轮胎打滑都会让车跑偏，**这是方案固有缺陷，不是 bug** | 慢速回放、短序列、胶带标起点、每次回放前把车摆到标记点；**报告按实测数字填，绝不编** |
| **2** | 遥控三键码值未核实 | 见决定 3 | 30 秒的事，先做 |
| **3** | 主循环阻塞 27 ms | 见决定 1 | 回放计时进中断 + 收帧限时缩短（O1） |
| **4** | 汇编短跳超射程 | 项目踩过两次（`TARGET OUT OF RANGE`） | 按老规矩改"反向短跳 + `LJMP`"；每改一次必须编译看 0 错 0 警告 |
| **5** | 多段路线要动 240 B 分区的口径 | 报告写的是"240 B = **80 条**"。分成 N 段后**总条数仍是 80**，只是分区 → 与报告**不冲突**，但报告中要加一句说明 | 分区方案（如 4 段 × 20 条）**可调**；或先只做单段，多段作选做 |
| **6** | 时间 | 主线 ⑦⑧ + 增强包 估 **2~3 个晚上**；上机验证另算 | 增强包**分级**：①②③ 按性价比砍（见第 7 节） |
| **7** | 掉电就白录 | 240 B 在 RAM，断电清空；**24C02 是否存在未确认**（疑似 `P1.4`/`P1.5`，未实测） | 短替代：**记录经串口导出到 PC / 再导入**（复用现成 `DEBUG_UART` 通道，车停着时才导，不影响红外实时性）→ 报告里"预留 EEPROM 掉电保存"那句话就有了**实实在在的替代实现** |

## 7. 增强包的分级（可以按时间砍）

| 级 | 增强 | 收益 | 代价 | 建议 |
|---|---|---|---|---|

### 3.1 为什么"不要照报告原样做"

报告已经把方案写完了，**照做 = 交一份和报告一模一样的实现**，答辩时老师只会问
"这不就是官方第 3 项吗"。增强包的作用是**把报告 3.1 节自己声称的创新点"变成看得见的东西"**：

> 报告 3.1 原话：*"关键不在于保存遥控器发出的原始红外脉冲，而在于把遥控操作转换为
> 机器人能够理解的语义化动作……既降低了存储需求，也使后续更换遥控器编码或增加蓝牙控制时
> 仍可复用同一动作回放模块。"*

这句话现在是**纯论证**。而**"同一段记录用 2 倍速再放一遍"**这一个演示，
就把它变成了**实验事实**——因为存的是"语义动作 + 时长"，**时长可以被缩放**；
如果存的是红外波形，**根本做不到这件事**。这是全场最有说服力的一击。

### 3.2 ★ 最强的免费论据：报告自己承诺了，而我们已经把地基铺好了

课题报告**第 7 节「结论与后续改进」原文**：

> *"后续可增加 24C02 EEPROM 以保存动作序列，加入编码器或循迹传感器以减小因电池电压、
> 地面摩擦和轮胎打滑带来的累计误差，并**可在回放中叠加避障与超时保护机制**。"*

也就是说 **"回放叠加避障保护"是报告自己写下的承诺**。而代码里**已经为它预留好了**：

```asm
; firmware\car\car_asm.asm L107
NMODES      EQU     3       ; 目前实现到 3；后面加综合/录制/回放时改这里 + MODETAB

; L1805  AV_GATE 里（避障闸门）
; ★★ R2：**循迹模式不参与避障**
MOV     A,      MODE
CJNE    A,      #MODE_TRACK, AG_CHK     ; ← 只排除"循迹"
```

> ★ **避障闸门当初是特意写成"排除循迹"而不是"只准手动/寻光"的**，
> 为的就是"将来加回放模式时它**天然带避障**"。**新加的 `MODE_PLAY` 不需要动 `AV_GATE` 一行。**

> ### ⚠️⚠️ **2026-09-20 更正（设计冻结阶段核对代码后）**
>
> 上面这段的**结论是对的**（`AV_GATE` 确实不用改），**但理由是错的**，必须更正：
>
> 当时只想到"回放**有没有**避障"，**没想到避障的语义是什么**。实际代码 `MOTOR_SET_ACT`（L703–712）：
> ```asm
>             DEC     A
>             JZ      MSA_TURN                ; 1 = AV_TURN  近区
> MSA_TURN:   MOV     R6,     #ACT_RIGHT      ; ★ 把动作改写成"原地右转"（不是停车！）
> ```
> ⇒ 避障闸门在 5~21 cm 的动作是「**改写成原地右转绕过去**」。
> 而创新功能要求的是「**遇障立即停车 + 终止复现，不擅自改变路径**」——**两者语义相反**。
> 若让 `MODE_PLAY` 走 `AV_GATE`，会得到**正好相反**的行为（车自己绕开继续跑），
> 这就**毁掉了"复现示教路径"这个定位**（详见 `docs\示教创新功能设计冻结.md` §1.1 冲突 C1）。
>
> ⇒ **正确做法**：回放**根本不进 `AV_GATE`**（在 `MAIN_LOOP` 最前面就跳进独立的 `PLAY_STEP`），
> 自己用 `PLAY_SAFETY` 实现"停车终止"。**`AV_GATE` 依然一行都不用改** ✅
> —— 但这是**"绕开"而不是"继承"**，与上面写的"天然带避障"是两回事。
>
> ★ 答辩口径随之修正：不要讲"回放天然继承避障"，要讲
> **"回放有自己独立的安全策略：遇障终止而非绕行——这正是'复现'与'重新规划'的定义性区别"**。
> 这个说法比原来的更强，也更站得住。

|---|---|---|

## 5. ★★ 开工前必须先定的三个设计决定

这三条**会改代码结构**，所以现在定比写完再改便宜得多。

### 决定 1：**回放计时必须放进 Timer0 中断，不能靠主循环数节拍**

⚠️ **这是本项目最容易做错、而且一做错表 5 的 ±5% 指标就必然不达标的一点。**

- 现状：主循环每趟都调 `IR_RECV`，而它**没有红外信号时最多阻塞 25.6 ms**（等下降沿超时）
  → **主循环周期 ≈ 27 ms**（`基础功能联调与优化清单.md` 风险 1 已记录）。
- 后果：如果回放用主循环数 10 ms 节拍，**误差就是 ±27 ms** →
  一个 100 ms 的动作实际可能跑 127 ms，**误差 27%，远超报告的 ±5%**。
- **正解**：`TICK_L/TICK_H`（100 µs 时基）**本来就在 Timer0 中断里维护**，
  在中断里加一个 10 ms 分频计数器（≈10 B），主循环只读标志位。
  → **时长误差由中断保证**（晶振级精度，±5% 轻松达标）。
- **还要顺手做的事**：回放期间**不能每趟都等 25.6 ms 的红外**，否则**动作切换时刻**
  会有最多 27 ms 的抖动（对短线动作就是大误差）。
  → 回放模式改成**每 N 趟收一次红外 + 缩短收帧限时**（这正好就是优化项 **O1**，本来就要做）。

> 一句话：**时长精度靠中断，切换精度靠缩短主循环阻塞，两件事都要做。**

### 决定 2：**"录制"不该是状态机的一个状态，而应是叠加在手动模式上的一层**

报告表 2 把「手动控制 / 动作录制 / 动作回放 / 安全停止」列成**并列的四个状态**。
但按报告 3.3 的流程，**录制时遥控键仍然要驱动电机**（不然人怎么"开"给车看？）
→ 所以"录制"的实质是 **手动模式 + 一个记录标志 `RECON`**，不是并列状态。

**建议**：
- `RECON`（录制中）= **正交标志位**，叠加在**手动模式**上；
- `MODE_PLAY`（回放中）= **真正的第四个模式**，加进 `MODE_*` 与 `MODETAB`
  （`NMODES 3 → 4`），这样它**自动继承避障闸门**（见 3.2），也能像数字键 1/2/3 一样直选。

> ★ 报告里这一处**要在实现说明里点出来**："状态机按'控制权归属'重新划分：
> 录制是手动模式的叠加，回放是独立模式"。**这是对报告的修正，也是设计深度的体现。**

## 6. 诚实的风险清单

| # | 风险 | 说明 | 处置 |
|---|---|---|---|
| **1** | ★ **无编码器 → 开环复现必然有落点误差** | 报告的 表 5 要求"3 次落点散布 ≤ ___ cm，**现场实测填入**"。电池电压、地面摩擦、轮胎打滑都会让车跑偏，**这是方案固有缺陷，不是 bug** | 慢速回放、短序列、胶带标起点、每次回放前把车摆到标记点；**报告按实测数字填，绝不编** |

| **3** | 主循环阻塞 27 ms | 见决定 1 | 回放计时进中断 + 收帧限时缩短（O1） |
| **4** | 汇编短跳超射程 | 项目踩过两次（`TARGET OUT OF RANGE`） | 按老规矩改"反向短跳 + `LJMP`"；每改一次必须编译看 0 错 0 警告 |

| **6** | 时间 | 主线 ⑦⑧ + 增强包 估 **2~3 个晚上**；上机验证另算 | 增强包**分级**：①②③ 按性价比砍（见第 7 节） |
| **7** | 掉电就白录 | 240 B 在 RAM，断电清空；**24C02 是否存在未确认**（疑似 `P1.4`/`P1.5`，未实测） | 短替代：**记录经串口导出到 PC / 再导入**（复用现成 `DEBUG_UART` 通道，车停着时才导，不影响红外实时性）→ 报告里"预留 EEPROM 掉电保存"那句话就有了**实实在在的替代实现** |
